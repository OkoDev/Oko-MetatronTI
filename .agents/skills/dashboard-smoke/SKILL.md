# Dashboard Smoke — Oko MTF

Проверка «жив ли бот и панели» за один проход. Даёт числа, а не впечатления.

## Когда применять

- Правил `web/`, `web/static/`, любой эндпоинт дашборда.
- Пользователь говорит «панель пустая», «данные не грузятся», «дашборд завис».
- Перед коммитом, который трогает веб-слой.
- При старте сессии, если `logs/` или `STATUS.md` намекают на падения.

## Эталонные значения

Замерено 2026-10-31 на живой системе. При расхождении — перемерить и обновить таблицу, а не подгонять вывод.

| Проверка | Эталон | Тревога |
|---|---|---|
| `GET :8000/` | HTTP 200, ~160 КБ | не 200 / <50 КБ |
| `GET :8000/api/settings` | HTTP 200, <1 с | >3 с |
| `GET :8000/api/stats` — HIT | <0.1 с | >0.5 с |
| `GET :8000/api/stats` — MISS | 2.4 с (изолированно) | >5 с на живом процессе |
| `GET :3000/` | HTTP 200, ~50 КБ | не 200 |
| JSON `/api/stats` | валидный, есть `summary`, `open_count`, `risk_exposure_pct` | тело — не JSON |

Константы из кода, а не из головы: `_STATS_CACHE["ttl"] = 30.0` (`web/dashboard_server.py`).

## Порядок проверки

### 1. Порты

```bash
netstat -ano | grep LISTENING | grep -E ":8000|:3000"
```

Оба должны слушать. `:8000` — aiohttp-дашборд бота, `:3000` — Next-панель `oko-dashboard`.

### 2. Эндпоинты с таймингом и заголовками

```bash
curl -s -o /dev/null -D - -w "  time=%{time_total}s\n" \
  http://127.0.0.1:8000/api/stats --max-time 30 | grep -Ei "^HTTP|X-Cache|time="
```

Обязательно смотреть `X-Cache`:

- `HIT` — ответ из кэша, должен быть <0.1 с.
- `MISS` — холодный пересчёт, до 20 с на живом боте.
- `HIT-LOCK` — запрос ждал чужой пересчёт; время = чужой пересчёт, не ваш.
- `STALE` — пересчёт упал, отдан прошлый payload. Это **деградация**, а не успех.

### 3. Валидность JSON и обязательные ключи

```bash
curl -s http://127.0.0.1:8000/api/stats --max-time 60 \
| python -c "import json,sys; d=json.load(sys.stdin); print(sorted(k for k in ('summary','open_count','risk_exposure_pct','open_trades') if k in d))"
```

Ожидается 4 ключа из 4. Пустой список — контракт сломан.

### 4. Живость бота по БД

```bash
python -c "import sqlite3; c=sqlite3.connect('file:C:/oko_data/subscriptions.db?mode=ro',uri=True); print(c.execute('select count(*) from simulated_trades').fetchone()[0]); print(c.execute('select max(created_at) from simulated_trades').fetchone()[0])"
```

Рост счётчика и свежий `max(created_at)` подтверждают, что бот пишет. Дашборд этого не покажет.

### 5. Визуальный / DOM-контроль (опционально)

Только если нужен фронт: ошибки JS, битая вёрстка, не отрисовались графики.

Через Playwright MCP (`mcp__playwright__*`):

1. `browser_navigate` → `http://localhost:3000` (и/или `:8000`).
2. `browser_console_messages` — ошибки консоли = регресс фронта.
3. `browser_snapshot` — текстовый DOM, основной инструмент.
4. `browser_take_screenshot` — только когда нужно показать пользователю.

Скриншот — последний аргумент, не первый. `browser_snapshot` дешевле и не зависит от того, принимает ли модель изображения.

## Известные ловушки

- **Пустая таблица ≠ нет данных.** При медленном `MISS` фронт уходит в `MOCK` по таймауту. Сначала `X-Cache` и время, потом выводы.
- **`MISS` бывает 1–20 с.** Разброс — следствие конкуренции за пул потоков, не медленного SQL.
- **Параллельный клиент ждёт пересчёт** из-за `_STATS_LOCK`. Видно по `HIT-LOCK`.
- **TTL 30 с при поллинге 30 с** — промах регулярно попадает на критический путь.
- **БД 3 ГБ**, пересчёт открывает 8 отдельных соединений (`PerformanceEngine._conn()` на каждый метод).

## Границы

- `core/trading/`, `core/signals/`, `core/smc/`, `bot/` — **не править**, зона Claude. Находка → запись в `DISCUSSION.md` с меткой `→ TRADER:`.
- `web/dashboard_server.py` — править можно, но после правки прогнать разделы 1–4 заново.
- Если эндпоинт медленный, а причина в `engine.full_stats()` — это чужая зона, только диагностика.

## Формат отчёта

Таблица «проверка / факт / эталон / вердикт», затем одной строкой — что сломано и где. Всегда указывать, когда мерил: цифры устаревают.

```
| :8000/ | 200, 163 КБ | 200, ~160 КБ | OK |
| /api/stats (HIT) | 0.02 s | <0.1 s | OK |
| /api/stats (MISS) | 5.2 s | 2.4 s | деградация, разбор ниже |
```
