## ❌ ПРОБЛЕМЫ ТЕКУЩЕЙ СТРУКТУРЫ

### 1. **Монолитный файл бота**
- `bot_with_subscriptions.py` - **1278 строк!**
- Содержит все: команды, FSM состояния, обработчики, логику
- Невозможно тестировать отдельные компоненты
- Сложно поддерживать и расширять

### 2. **Отсутствие четкой структуры**
- Нет директорий для handlers, commands, utils
- Все в одном файле `bot_with_subscriptions.py`
- Смешанные уровни абстракции

### 3. **Разбросанные модули**
- `core/` содержит слишком много модулей
- Нет группировки по функциональности
- Дублирование конфигурации (`config.py` и `config_loader.py`)

### 4. **Отсутствие тестов**
- Тесты разбросаны по корню проекта
- Нет директории `tests/`
- Нет структуры для unit/integration тестов

### 5. **Отсутствие документации**
- Документация разбросана по корню
- Нет директории `docs/`
- Нет четкой структуры API

### 6. **Смешанные зависимости**
- Нет четкого разделения на layers
- Тесная связанность между модулями
- Сложно добавить новые функции

## 🎯 ЦЕЛИ РЕФАКТОРИНГА

1. **Разделение на слои**
   - Domain (бизнес-логика)
   - Application (использование логики)
   - Presentation (UI/API)
   - Infrastructure (внешние сервисы)

2. **Модульность**
   - Каждый модуль отвечает за одну функцию
   - Явные зависимости
   - Легко тестировать и расширять

3. **Четкая структура**
   - Логичные директории
   - Группировка по функциональности
   - Легко найти нужный код

4. **Тестируемость**
   - Директория для тестов
   - Unit тесты для каждого модуля
   - Integration тесты для сложной логики

5. **Масштабируемость**
   - Легко добавлять новые функции
   - Минимальная связанность
   - Явные интерфейсы
