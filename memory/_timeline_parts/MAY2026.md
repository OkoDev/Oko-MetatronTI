# Месяц: MAY2026

## 🎯 Главные темы и фазы
- **Диагностика и оптимизация стратегии `pivot_reversal`**: Выявлена критическая проблема с таймингом входа, приводящая к открытию сделок в неоптимальной `wt_zone='N'` вместо целевой `wt_zone='OS'`.
- **Развитие LLM-интеграции (L1 Pre-trade Screen)**: Переход от пост-фактум анализа убыточных сделок к проактивному пре-трейд скринингу сигналов с использованием Groq 70B для повышения качества торговых входов.

## 🏆 Принятые архитектурные решения (ARCH)
- `[2026-05-02] ARCH-X — Внедрение L1 Pre-trade Screen для фильтрации сигналов.`
    - **Суть:** Перед регистрацией каждого торгового сигнала в БД, контекст сигнала будет отправляться в Groq 70B для получения структурированного вердикта (`decision`, `score`, `reasons`) о целесообразности входа.
    - **Почему важно:** Это первое применение LLM для активной фильтрации сделок *до* их открытия, что позволяет предотвращать потенциально убыточные входы и значительно улучшать качество торговых решений, в отличие от предыдущего использования LLM только для анализа уже закрытых убыточных сделок (DEV-15, DEV-151).
    - **Детали:** Вызов LLM будет интегрирован в `core/trading_intelligence.py` → `analyze_symbol()`. Если `score` от LLM будет ниже 30, сделка будет пропущена (`SKIP`). Предусмотрен асинхронный вызов с таймаутом 3 секунды и fallback на `PASS` в случае недоступности или таймаута Groq.

Вместо этого, сделки всегда открываются в `wt_zone='N'` (нейтральная).

Это указывает на неоптимальные точки входа, противоречащие изначальной задумке стратегии как отскока от уровня при перепроданности.

## ⚠️ Главные баги/инциденты
- **[2026-05-02] Неоптимальные точки входа в стратегии `pivot_reversal` из-за проблемы с `wt_zone`.**
    - **Что ломалось:** Стратегия `pivot_reversal` не открывает сделки в целевой зоне `wt_zone='OS'`, вместо этого всегда входя в `wt_zone='N'`.
    - **Root cause:** Предполагается проблема с таймингом сигнала (ARCH-95 H1): к моменту генерации сигнала по закрытой свече, `wt_zone` уже смещается из 'OS' в 'N'.
    - **Как чинили:** Находится на стадии диагностики. Предложены дальнейшие шаги: ARCH должен определить, является ли это багом логики, DEV должен проверить частоту сочетания `OS` + `cross_up`.
    - **Потери:** Для 315 сделок `pivot_reversal` в `wt_zone='N'` за период пост-v4 (с 29.04.2026 22:00) зафиксирован `avgR = -0.339`.
