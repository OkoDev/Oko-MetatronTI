# Order-Book Data — наработка (бэклог для получения данных)

> Создано 03.06.2026. Разведка по запросу: данные стакана крупных игроков для позиционной торговли и магнитов цены. НЕ интегрировано в бота — наработка/инструменты для будущей фичи (потенциально Сфера ликвидности Куба).

## 🎯 Зачем
Понимание позиционной торговли и магнитов цены: где киты расставили лимитные «сети» (стены), какие уровни работают притяжением/отбоем. Оперативность НЕ нужна (это не скальпинг) — просмотр раз в день / в 14:00. Стены меняются редко.

## 📡 Endpoints (публичные, БЕЗ API-ключа)

**Binance — лучший источник** (глубже, реальная ликвидность, видны институционалы на круглых числах):
- SPOT depth (до **5000** уровней): `https://api.binance.com/api/v3/depth?symbol=BTCUSDT&limit=5000`
- FUTURES perp depth (до 1000): `https://fapi.binance.com/fapi/v1/depth?symbol=BTCUSDT&limit=1000`
- klines (для пивотов): `https://api.binance.com/api/v3/klines?symbol=BTCUSDT&interval=1d&limit=5` (intervals: 1d/1w/1M)
- Формат символа Binance: `BTCUSDT` (без разделителей).

**BingX** (вторичный — торгуется ~0.45% НИЖЕ реального рынка, маркет-мейкится):
- depth (до 1000): `https://open-api.bingx.com/openApi/swap/v2/quote/depth?symbol=BTC-USDT&limit=1000`
- klines: `https://open-api.bingx.com/openApi/swap/v3/quote/klines?symbol=BTC-USDT&interval=1d&limit=5`
- Формат: `BTC-USDT`. Depth → `data.bids/asks` = `[[price, qty], ...]`, qty в базовой монете, объём USDT = price*qty.

**Вывод:** для чтения smart money — **Binance spot (limit 5000)**. BingX — только для исполнения сделок бота.

## 🛠️ Готовые инструменты (в `e:/tmp/`, не в репо)
| Скрипт | Назначение |
|---|---|
| `binance_full_analysis.py SYMBOL` | стакан spot+fut + пивоты D/W/M + конфлюенция стен с пивотами |
| `binance_depth_deep.py SYMBOL` | кумулятивная ликвидность по зонам (±0.5..100%), кластеры, стены по сторонам |
| `binance_level_history.py SYMBOL LEVEL ±% TF` | проверка уровня на истории (касания/отбои, поддержка vs сопротивление) |
| `bingx_depth_test.py`, `bingx_pivot_confluence.py`, `bingx_level_history.py` | BingX-аналоги |

Пивоты считаются ТОЧНО по формуле бота: `core/indicators/indicators.calculate_pivot_points` (Traditional PP, S1-S5/R1-R5).

## 📊 Что даёт анализ (метрики)
1. **Стены** — топ-N крупнейших лимиток (price×qty в USDT) = уровни китов.
2. **Кумулятивная ликвидность по зонам** — BID/ASK дисбаланс на ±0.5/1/2/5/10% от mid. Близкий дисбаланс ≠ глобальный.
3. **Кластеры** — группировка близких уровней в зоны ликвидности.
4. **Конфлюенция с пивотами** — стена + пивот = усиленный уровень.
5. **История уровня** — сколько раз цена касалась/отбивалась (поддержка vs сопротивление) за N дней.
6. Институционалы ставят лесенку лимиток на **круглых числах** (50/55/60... 66000).

## ⚠️ Важные ограничения
- REST = **снимок**, не поток. Крупная заявка может быть **спуфингом** (исчезнет при касании). Отличить реальную стену → серия снимков во времени (стена, что стоит днями — реальна).
- Для realtime есть WebSocket depth-поток (отложено — оперативность не нужна).
- Прогноз/разметка волн без визуального графика старших ТФ — субъективны.

## 🧊 Идея для интеграции (если возьмём в Куб)
- **Сфера ликвидности / OrderBookSphere**: дневной снимок стакана Binance → стены/кластеры → в Shared Context Bus как магниты цены и подтверждение пивотных уровней.
- Сохранение снимков с датой (`depth_BTC_2026-06-03.json`) → сравнение день-ко-дню → отсев спуфинга, отслеживание накопления/распределения китов.
- Связь со сферами: PivotSphere (конфлюенция), SMC Sub-куб (ликвидность), TPSelector (магниты-цели).
