## 🥇 **1. Gamma Scalping (Торговля волатильностью через маркет-мейкеров)**

**Уровень приоритета:** 🟢 **ВЫ МОЖЕТЕ ВЗЯТЬ СЕЙЧАС** (3-4 дня)

### Суть
Маркет-мейкеры при spike волатильности или экспирации вынуждены хеджировать дельта → покупают/продают без фундаментальной причины → аномальный объём → откат → наш профит.

### Edge-механизм
- Детект: `volume_ratio >1.5x медиана` + `НЕ корреляция с новостями`
- Маркет-мейкеры срочно хеджируют → цена движется
- После завершения хеджирования → откат к справедливости
- Мы ловим отток (TP1 на откате)

### Честный WR
**55-60%** (низкий, но высокое R:R на спайках)

### Где искать
- Опционные экспирации (каждую пятницу)
- Spike ATR >2σ от медианы
- Периоды с объёмом >150% от MA100

### Как интегрировать в Куб
- **Сфера 6 (Intelligence):** новый детектор `detect_gamma_spike()`
- **Компоненты готовы:** `compute_volume_ratio()` ✅, `AnomalyModel` ✅ (Isolation Forest)
- **Вход:** когда `volume_anomaly_strength ≥50` И `trend=neutral` (не в тренде)
- **Выход:** TP1 по откату (не дальше), SL за импульс

### Сложность & время
- 🟢 **EASY:** скопировать логику из Памп-Бота
- ⏱️ **3-4 дня** одного разработчика
- Рекомендация: **СЕЙЧАС**, до более сложных

### Код-точка входа
```python
# core/intelligence/gamma_detector.py (новый файл)
def detect_gamma_spike(ohlcv, volume_ma):
    vol_ratio = compute_volume_ratio(ohlcv['volume'], volume_ma)
    anomaly_score = AnomalyModel.score(ohlcv)
    if vol_ratio > 1.5 and anomaly_score > 50:
        return {"type": "gamma_spike", "strength": anomaly_score}
```

## 🥈 **2. Liquidation Cascades (Охота за ликвидациями)**

**Уровень приоритета:** 🥈 **2 неделя** (неделя разработки)

### Суть
Когда цена достигает уровней с концентрацией стоп-лоссов → ликвидируются позиции других трейдеров → создаётся каскадный импульс → мы ловим профит на импульсе + на слипеджах.

### Edge-механизм
1. Получаем карту Open Interest (OI) с BingX
2. Находим уровни с 70%+ ликвидаций (горячие точки)
3. Выставляем лимиты **ЗА** стоп-лоссами (ловим каскад)
4. Профит = движение из-за ликвидаций (не из-за торговцев)

### Честный WR
**65-75%** (высокий, требует точности Level 2 данных)

### Где искать
- **Coinglass / Hyblock / CryptoQuant** → карты ликвидаций
- Сопоставлять с Order Book BingX (Level 2)
- Волатильные пары: BTC, ETH, leveraged-alts (10x, 25x)
- ТФ: 5m-15m (ликвидация мгновенная)

### Как интегрировать в Куб
- **Новая мини-сфера:** `LiquidationMonitor`
- **API:** BingX Open Interest API (уже есть?) + Coinglass API (платный, $99/мес)
- **Логика:** `if price_approaches(oi_level, tolerance=0.5%) → prepare_limit_order(beneath_sl)`
- **Выход:** SL за движением, TP1 после каскада

### Сложность & время
- 🟡 **MEDIUM:** требует API интеграции + сопоставления уровней
- ⏱️ **1-2 недели** (если API доступны)
- **Блокер:** нужна подписка на Coinglass или Hyblock (платно)

### Рекомендация
Сначала попробовать на **исторических данных** (есть ли ликвидации в логах?), потом live.

## 🥉 **3. Statistical Arbitrage Pairs (Корреляционный арбитраж)**

**Уровень приоритета:** 🥈 **2 неделя** (параллельно Liquidation)

### Суть
BTC растёт +2%, ETH стоит → ETH **должна** "догнать" из-за высокой корреляции → открываем **хеджированную позицию**: LONG ETH + SHORT BTC. Оба закрываются одновременно, профит = разница в возврате к среднему.

### Edge-механизм
1. Рассчитываем коэффициент корреляции Пирсона (скользящее окно 100 свечей, ТФ 5m)
2. Если корреляция >0.9 И расхождение цен >X% → расхождение аномально
3. Открываем хеджированные позиции (нейтральны к направлению)
4. Профит = статистический откат (15-60 мин)

### Честный WR
**70-80%** (хороший, зависит от волатильности)

### Где искать
- **Пары:** BTC↔ETH (корр 0.95), BTC↔SOL (корр 0.88), BTC↔XRP (корр 0.85)
- **ТФ:** 5m-15m (откат происходит быстро)
- **Вход:** когда корреляция очень высокая, расхождение большое
- **Выход:** когда цены вернулись к среднему

### Как интегрировать в Куб
- **Новая Сфера:** `PairsArbitrageur`
- **Сфера 3 (Indicators):** добавить `calculate_correlation(prices_a, prices_b, window=100)`
- **TradeSimulator:** поддержка открытия двух позиций одновременно (уже есть?)
- **RiskIntelligence:** размер позиций должны быть **взаимно хеджированы** (qty_long_eth = qty_short_btc × price_ratio)

### Сложность & время
- 🟡 **MEDIUM:** корреляция рассчитывается просто, но синхрон двух позиций требует аккуратности
- ⏱️ **1 неделя** (если уже есть двухпозиционная логика)

### Рекомендация
Начать с BTC↔ETH, потом расширить на другие пары.

## 💎 **4. Delta Footprint (Дельта-профайлинг / Анализ потоков)**

**Уровень приоритета:** 🥉 **3 неделя**

### Суть
**Не цена падает = профит**, а **агрессивные рыночные ордеры слабеют** = медведи выдыхаются = разворот (absorption). Ловим разворот перед ценовым движением.

### Edge-механизм
1. Отслеживаем дельту (Market Buy - Market Sell) в реальном времени
2. Если цена падает, но дельта становится положительной (покупателей больше) → absorption
3. Это означает, что покупатели впитывают продажи → медведи сдаются
4. Вход перед разворотом (ловим движение вверх)

### Честный WR
**55-60%** (требует хороших точек входа, иначе ложные сигналы)

### Где искать
- **Level 2 Order Book** (нужна глубина, не только спред)
- **Мониторим:** агрессивные ордеры (маркет ордеры vs лимиты)
- **ТФ:** 5m-15m (на 1h слишком долго, на 1m слишком шумно)
- **Пары:** волатильные (DOGE, SHIB, leveraged), где много розницы

### Как интегрировать в Куб
- **Сфера 2 (DataCollector):** добавить дельта-расчёт в OHLCV stream
  - `delta = market_buy_volume - market_sell_volume` (за каждую свечу)
- **Сфера 5 (Intelligence):** детектор absorption
  - `if price_down AND delta_positive → signal_reversal()`
- **Выход:** TP1 на откате, SL за импульс падения

### Сложность & время
- 🟡 **MEDIUM:** рассчёты дельты просты, но Level 2 API требуется
- ⏱️ **1-2 недели** (если Level 2 API есть)
- **Блокер:** нужен доступ к Level 2 Order Book (может быть дорого или недоступно на BingX)

### Рекомендация
Сначала проверить, есть ли Level 2 API на BingX, иначе стратегия не реализуема.

## 🚀 **5. Epsilon Arbitrage (Латентный межбиржевой арбитраж)**

**Уровень приоритета:** 🏁 **4 месяц** (если есть VPS у серверов)

### Суть
BingX отстаёт от Binance на **0.1-0.3% в цене** (из-за меньшей ликвидности). Мониторим обе биржи через WebSocket, ловим разницу через высокочастотный арбитраж.

### Edge-механизм
1. Подписываемся на WebSocket цен BTC/ETH на Binance И BingX параллельно
2. Если BingX дешевле >0.1% → **ловим покупку на BingX + продажу на Binance**
3. Синхронизируем исполнение (или используем кроссбиржевый хеджинг)
4. Профит = разница в ценах (обычно 0.1-0.3% в час на спайках волатильности)

### Честный WR
**85-95%** (очень высокий, почти безрисковый при низком пинге)

### Где искать
- **Только Top пары:** BTC/USDT, ETH/USDT (достаточно ликвидности)
- **Требует:** пинг <50ms к обеим биржам (критично для HFT)
- **Периоды:** spike волатильности (когда спред расширяется)

### Как интегрировать в Куб
- **Новая Сфера:** `InterExchangeArbitrageur` (обособленная от основного Куба, может работать параллельно)
- **Требуется:** две WebSocket подписки (Binance + BingX)
- **Логика:** автоматический хеджинг позиций между биржами
- **Выход:** закрытие, когда спред вернулся к норме

### Сложность & время
- 🔴 **HARD:** требует низкоуровневой работы с WebSocket, синхрон двух бирж, обработка проскальзывания и комиссий
- ⏱️ **2-3 недели** (если уже есть инфраструктура для двух бирж)
- **Блокер:** нужен VPS рядом с серверами бирж (иначе пинг >100ms, стратегия не работает)

### Рекомендация
**ОТЛОЖИТЬ** до стабилизации основных стратегий. Это HFT, высокие требования к инфре.
