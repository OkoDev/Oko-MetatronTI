## 📊 Системные наблюдения (важно для DEV/ARCH)

### 1. Критическая проблема: нет mode-direction lock 🔴
**Факт:** CAKE LONG при TREND_DOWN (str=98), KITE LONG при TREND_DOWN (str=95), SAHARA SHORT при TREND_UP (str=94) — 3 из 16 позиций это контр-тренд входы с очень высоким score.

**Почему происходит:** confluence и pivot_reversal дают высокий score от локальных технических сигналов, не учитывая глобальный тренд. Система не блокирует, а только штрафует.

**Что нужно:** TREND_DOWN → только SHORT. TREND_UP → только LONG. Режим RANGE — оба направления.

### 2. R:R нереалистичные 🟡
**Факт:** STBL R:R=21.2x, PAXG R:R=24.6x, ICNT R:R=20.9x, CRCLX R:R=32.1x — система ставит TP на далёкий пивот.

**Проблема:** с таким R:R система будет почти всегда закрываться по SL, потому что TP недостижим. Это маскирует реальный edge. Тест: если все закрываются по SL, WR падает к нулю, что и видим.

**Рекомендация:** max R:R = 5-6x на 15m. Выше — сомнительно. TR-003 TP1/TP2 решит это.

### 3. Корреляция активов 🟡
PAXG + XAUT = одновременно два золотых токена. Нужен correlation filter.

### 4. Массовый SL 18:00-19:00 UTC — что произошло?
8 сделок закрылись по SL за 25 минут (18:01–18:37 UTC). Это событие в базовом активе (BTC?). DEV должен добавить в features_json маркер "market event" когда >5 SL за 30 минут.
