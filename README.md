# Oko-MetatronTI — исследовательская система для рынка криптофьючерсов

Система следит за ~570 бессрочными контрактами BingX, размечает структуру рынка на нескольких
таймфреймах и проверяет каждую торговую идею замером: на истории, затем на демо-счёте.
Это не «бот с сигналами» и не обещание доходности. Главное, что здесь сделано, — способ
отличать работающую идею от случайной удачи.

> Состояние описано на **13.10.2026**. Рабочая ветка — `arch-128-oko-sm`; `main` от неё отстаёт.

## Честный статус

| Что | Состояние |
|---|---|
| Режим торговли | Только демо-счёт BingX (VST). Реальные деньги не подключены |
| Преимущество после издержек | У источников сигналов, работающих в бою, не доказано. Замер 06.10.2026: при издержках 0,35% на сделку его не сохраняет ни один из 19 |
| Кандидаты | Редкие волновые сетапы, единицы сделок в месяц. На исполнении не подтверждены |
| Внешний аудит (10.2026) | Оценка 5 из 10: исследовательское ядро зрелое, готовности к эксплуатации и продаже нет. Найдено 14 дефектов, три исправлены 13.10, остальные в работе |
| Продукт | В разработке. Публичного сервиса нет |

Отрицательные результаты здесь записываются так же подробно, как положительные: они и есть
основная часть накопленного знания.

## Что внутри

- **Бот-анализатор** (`oko_mtf.py`). Круг скана по всем парам: свечи, структура (сломы, зоны,
  уровни), WaveTrend, пивоты, волны. Сигналы проходят проверки перед входом и регистрируются
  как сделки симуляции или демо-счёта.
- **Шина состояния** («Куб Метатрона»). Одна доска с текущим состоянием каждой пары, которую
  читают остальные части. Вынесена в отдельный процесс-хаб, переживает перезапуск бота.
  Каталог полей — [docs/BUS_CATALOG.md](docs/BUS_CATALOG.md).
- **Слой исполнения.** Заявки, стопы и закрытия на демо-счёте идут отдельно от симуляции:
  у каждой сделки записано, где она исполнялась.
- **Исследовательский контур.** Единая точка входа для замеров, карточка вердикта с
  обязательными срезами, нулевая модель, проверка на перебор гипотез.
- **Спутники.** Отдельные процессы: поток свечей, открытый интерес, ликвидации, лента сделок,
  новости, теневые журналы стратегий, вахты.
- **Интерфейсы.** Telegram, терминал с графиками, два дашборда. Все рассчитаны на одного
  владельца, а не на внешних пользователей.

## Как устроено

```
oko_mtf.py        точка входа бота (aiogram)
config.yaml       вся конфигурация
core/             логика: данные, структура, волны, сигналы, проверки входа, исполнение, шина
bot/              Telegram-слой и рабочие циклы (скан, волны, сопровождение сделок)
web/              дашборд бота, терминал, слой чтения
scripts/          спутники, вахты, исследовательские замеры, хаб шины
tests/unit/       юнит-тесты
docs/             архитектура, реестры, решения (ADR), аудиты
obsidian/         граф знаний: задачи, обсуждения, сырые данные замеров
```

Локальные службы: дашборд бота `:8000`, слой чтения `:8001`, дашборд Next.js `:3000`,
терминал `:8010`, хаб шины `:8020`. В бою всё работает под pm2 на Windows: 39 записей,
из них 21 постоянный процесс и 18 задач по расписанию.

Хранение: SQLite (сделки и журналы, отдельные базы у спутников) и parquet (история свечей).

## Запуск

```bash
pip install -r requirements.txt     # Python 3.12
python oko_mtf.py
```

Нужен файл `.env` в корне. Примера в репозитории нет; код читает переменные
`TELEGRAM_TOKEN`, `ADMIN_ID`, `BINGX_API_KEY`, `BINGX_SECRET_KEY`, `BINGX_VST_API_KEY`,
`BINGX_VST_SECRET_KEY`, по желанию `CMC_API_KEY` и `PROXY_LIST`.

Один бот без спутников запустится, но часть данных (открытый интерес, ликвидации, вахты)
приходит только от отдельных процессов. Их состав — в [docs/SYSTEM_MAP.md](docs/SYSTEM_MAP.md)
(карта от 13.07.2026, местами отстаёт от кода).

## Проверка

```bash
python tools/install_hooks.py       # поставить хуки git, один раз
python scripts/test_gate.py         # ворота: падают только на НОВЫХ падениях тестов
```

Сейчас проходят 1415 юнит-тестов, 23 падения известны и записаны в `tests/known_failures.txt`.
Ворота запускаются сами перед каждым `git push`.

## Как здесь выносят вердикт идее

Правила появились после собственных ошибок, каждая стоила недель:

1. **Считать в процентах после издержек**, а не в единицах риска.
2. **От реальной цены входа**, а не от цены сигнала.
3. **Не по общей строке.** Обязательные срезы: сторона, год, режим рынка, размер стопа,
   ликвидность, результат без лучших дней, охват монет.
4. **Против контроля** — случайного входа с той же геометрией и той же волатильностью.
5. **Без заглядывания в будущее.** Старший таймфрейм — только с закрытой свечи; причинность
   детектора проверяется прогоном, а не рассуждением.
6. **Найденное перебором** проверяется тем же перебором на перемешанных исходах.
7. **Вывод называет слой**, который проверен, и отдельно — что не проверено.

Инструменты: `scripts/research_harness.py` (единая точка входа, вся матрица признаков),
`scripts/research_verify.py` (карточка вердикта). Реестр готового — [docs/REGISTRY.md](docs/REGISTRY.md)
и [TOOLS.md](TOOLS.md).
