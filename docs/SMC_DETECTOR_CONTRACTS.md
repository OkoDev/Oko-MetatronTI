## 1. Главное правило, из-за которого документ существует

> ### Все поля «времени» в этом модуле — это `df.index[i]`, а НЕ номер бара.
>
> Их конкретный тип определяется **индексом переданного DataFrame**, а не детектором:
>
> | что передали | что вернётся в «ts»-полях |
> |---|---|
> | `load(sym, tf)` — **DatetimeIndex** | `pd.Timestamp` (tz-aware UTC) |
> | `df.reset_index(drop=True)` — **RangeIndex** | `int` (позиция бара) |
>
> Тот же самый код на двух разных входах возвращает **разные типы**. Проверено прогоном
> обоих вариантов: `detect_fvg[0][0]` → `Timestamp('2026-08-13 23:00:00+0000')` при
> DatetimeIndex и `36` (int) при RangeIndex.
>
> 🔴 `scripts/research_harness.py:102` прямо советует `.reset_index(drop=True)` для
> SMC-детекторов — половина исследовательских скриптов работает во «втором режиме».
> Поэтому **нельзя писать `df.index.get_loc(f[0])` вслепую**: на RangeIndex сработает,
> на DatetimeIndex сработает, а на смешанном пайплайне даст молчаливо неверный бар.

**Поля, которые ВСЕГДА `int` (номер бара, iloc) — независимо от индекса df:**
`Swing.idx`, `StructureBreak.idx`, `StructureBreak.from_idx`, `OrderBlock.left_idx`,
`OrderBlock.break_idx`, `OrderBlock.mitigated_idx`, `SponsoredCandle.idx`.

**Поля, которые следуют за индексом df (Timestamp или int):**
`Swing.ts`, `StructureBreak.ts`, `SponsoredCandle.ts`, весь возврат `detect_fvg`
(поз. 0, 4, 5), `detect_fvg_overlap` (`since`, `held_ts`, вложенные кортежи),
`classify_structure` (поз. 0), `detect_equal_levels` (поз. 0 и 2), `zigzag_atr` (поз. 0),
`detect_elliott_*` (`waves[k][0]`).

## 3. `detect_swings` (стр. 71)

```python
detect_swings(df: pd.DataFrame, major_len: int = 50, minor_len: int = 5) -> List[Swing]
```

**Возврат:** `List[Swing]` — frozen dataclass, **отсортирован по `idx` по возрастанию**,
major и minor **перемешаны в одном списке**.

| поле | тип | смысл |
|---|---|---|
| `idx` | `int` | **iloc бара экстремума**. Проверено: `df.index[s.idx] == s.ts` (100%) |
| `ts` | `df.index[idx]` | Timestamp при DatetimeIndex, **int при RangeIndex** |
| `price` | `float` | `high[idx]` для `kind='H'`, `low[idx]` для `'L'` (проверено 149/149) |
| `kind` | `'H'` / `'L'` | вершина / дно |
| `level` | `'major'` / `'minor'` | масштаб: `major_len=50` / `minor_len=5` |

**Полей «когда стало известно» и «когда умерло» НЕТ.** Свинг не митигируется в этой
структуре вообще.

🔴 **Лаг = `length` баров** (замер: major ровно 50 из 50 случаев, minor ровно 5 из 36).
Свинг помечается на баре экстремума, но выпадает из `_swings_luxalgo` только через
`length` баров. Признак «свинг был N баров назад» при `N < 50` для major — look-ahead.

⚠️ Один бар может дать **и major, и minor свинг** (9 совпадающих пар `(idx, kind)` на
1000 баров) → фильтруйте по `level`, иначе двойной счёт.

## 4. `detect_structure_breaks` (стр. 103)

```python
detect_structure_breaks(df, length: int = 50, vol_len: int = 20,
                        vol_mult: float = 1.2) -> List[StructureBreak]
```

**Возврат:** `List[StructureBreak]`, монотонно по `idx`.

| поле | тип | смысл |
|---|---|---|
| `ts` | `df.index[idx]` | бар пробоя (**Timestamp / int** — см. §1) |
| `idx` | `int` | **iloc бара пробоя** |
| `price` | `float` | **пробитый уровень (цена свинга)**, а не цена на баре пробоя |
| `kind` | `'BOS'` / `'CHoCH'` | продолжение / смена характера |
| `direction` | `'bull'` / `'bear'` | сторона пробоя |
| `has_volume` | `bool` | `volume[idx] > SMA(volume, vol_len)[idx] * vol_mult`. Замер: True в 28 из 39 сломов |
| `from_idx` | `int` | **iloc бара свинга-уровня** (откуда тянуть линию). По умолчанию `-1`, но фактически всегда заполнен: 0 из 39 равны `-1` |

**Порядок полей в dataclass — `ts` ПЕРВЫМ, `idx` вторым.** Это единственная структура
в модуле, где время стоит раньше индекса; позиционная распаковка `StructureBreak(*args)`
ловушечна.

Дистанция `idx - from_idx` ≥ `length` всегда (минимум замера — 51 при `length=50`):
уровень активируется только через `length` баров после свинга.

✅ **Лаг = 0** (замер: 15 из 15 при `length=5`, 1 из 1 при `length=50`). Слом виден на
закрытии своего бара — единственный полностью реал-таймовый структурный детектор.

**Поля «умер» НЕТ.** Слом — точечное событие, не зона.

## 5. `detect_order_blocks` (стр. 166)

```python
detect_order_blocks(df, breaks: List[StructureBreak], atr_len: int = 200) -> List[OrderBlock]
```

**Возврат:** `List[OrderBlock]`. **Все поля времени — `int` (iloc). Timestamp-полей нет
вообще.** Единственная структура модуля, где время не «протекает» из индекса df.

| поле | тип | смысл |
|---|---|---|
| `left_idx` | `int` | **iloc OB-свечи**. `top == high[left_idx]`, `bottom == low[left_idx]` (проверено) |
| `top` | `float` | верх бокса = `high[left_idx]` |
| `bottom` | `float` | низ бокса = `low[left_idx]`, всегда `≤ top` |
| `kind` | `'bull'` / `'bear'` | **наследуется от `direction` слома**, не от свечи |
| `break_idx` | `int` | **iloc слома → это и есть «когда стало известно»** |
| `mitigated_idx` | `int` | **iloc бара смерти** (close за боксом), `-1` = ещё активен |
| `is_breaker` | `bool` | `== (mitigated_idx != -1)` — проверено, всегда тождественно |

**Момент известности = `break_idx`, НЕ `left_idx`.** Замер: OB с `left_idx=381`
и `break_idx=402` впервые появляется на префиксе, заканчивающемся баром 402-403.
Лаг от `left_idx` до появления = **19-44 бара** (замер по 4 OB: 19, 22, 23, 44).
Скрипт `smc_confirmation_lags.py` печатает для этого детектора 0 — потому что там
событием объявлен `break_idx`. Обе цифры верны, вопрос в определении события.

🔴 **`mitigated_idx` и `is_breaker` МУТИРУЮТ задним числом.** Замер на префиксах
600/900/1200/1500 баров: 2 из 6 OB меняли значение, например
`left_idx=381 bear: (600, -1, False) → (900, -1, False) → (1200, -1, False) → (1500, 1253, True)`.
Смотреть на `is_breaker` из прогона по всему ряду и ставить флаг на бар `break_idx` —
классический survivorship look-ahead. Для причинного признака нужно `mitigated_idx <= бар_замера`.

Что делает код (докстринг звучит иначе): среди баров `[from_idx .. break_idx]`
берётся **экстремальная** свеча (минимальный `low` для bull, максимальный `high` для
bear) из тех, у кого `high-low < 2×ATR(200)`; при равенстве — **первая**. Не «последняя
спокойная». Митигация ищется с бара `break_idx + 1`, не с `left_idx + 1`.

Замер: число OB **равно** числу сломов (3/3, 5/5, 7/7). Пропуск возможен, если
`break_idx - from_idx < 1` или ни одна свеча не прошла ATR-фильтр.

## 6. `active_breakers` (стр. 226)

```python
active_breakers(obs: List[OrderBlock], at_bar: int) -> List[OrderBlock]
```

**Возврат:** те же самые объекты `OrderBlock` (не копии), у которых
`mitigated_idx != -1 and mitigated_idx <= at_bar`, **отсортированы по `mitigated_idx`**
(порядок отличается от входного `left_idx`-порядка — проверено на реальном ряду).

* `at_bar` — **int, iloc**. Передача Timestamp даст неверный результат без ошибки.
* Замер: `at_bar=999` → 2 breaker'а, `at_bar=500` → 0. Каузальность обеспечивается
  только этим аргументом.
* **Срока жизни у breaker'а нет** — однажды пробитый OB остаётся в выдаче до конца ряда.
* Торговая сторона **обратна** `ob.kind` — берите её через `breaker_side(ob)` (стр. 239),
  не через `ob.kind`.

## 7. `active_order_blocks` (стр. 244)

```python
active_order_blocks(obs: List[OrderBlock], n_bars: int, per_side: int = 5) -> List[OrderBlock]
```

**Возврат:** только `mitigated_idx == -1`, последние `per_side` bull + `per_side` bear,
отсортированы по `left_idx`.

🔴 **`n_bars` — МЁРТВЫЙ ПАРАМЕТР.** В теле функции не используется. Замер:
`n_bars=0` → 2 объекта, `n_bars=10**9` → 2 объекта. Докстринг обещает
«пробитый OB удаляется (`mitigated_idx != -1` **и `< n_bars`**)» — второго условия в
коде нет.

🔴 **Функция НЕ каузальна.** «Активен» здесь значит «не был пробит **за всю историю
переданного df**», а не «не был пробит к бару X». На баре 500 она вернёт OB, который
будет пробит на баре 700, — потому что в снимке по всему ряду у него `mitigated_idx == -1`
только когда пробоя не случилось вообще. Для среза на конкретном баре нужна ручная
фильтрация `o.mitigated_idx == -1 or o.mitigated_idx > bar`, плюс `o.break_idx <= bar`.

## 9. `detect_equal_levels` (стр. 416)

```python
detect_equal_levels(df, eq_len: int = 3, threshold: float = 0.1,
                    atr_len: int = 200) -> List[tuple]
```

**Возврат:** `List[tuple]` длины **5** — пара уровней:

| поз. | тип | смысл |
|---|---|---|
| `[0]` | `df.index[i1]` | **ts ПЕРВОГО пивота** |
| `[1]` | `float` | цена первого пивота |
| `[2]` | `df.index[i2]` | **ts ВТОРОГО пивота** (всегда позже `[0]`) |
| `[3]` | `float` | цена второго пивота |
| `[4]` | `str` | `'EQH'` (равные вершины) / `'EQL'` (равные донья) |

Индексов баров в возврате нет — обе позиции времени. Сравниваются только **соседние**
пивоты одного типа: тройной EQH придёт двумя перекрывающимися парами, а не одной записью.

Порог: `|p2 - p1| < threshold × ATR(atr_len)[i2]`. Замер чувствительности:
`threshold=0.1` → 13 пар, `threshold=0.5` → 50 пар на 1000 баров.

🔴 **Лаг = `eq_len` = 3 бара** от второго пивота (замер: 3 из 3, оба символа).
`_pivots` требует `eq_len` баров справа. Уровень EQ известен на баре `i2 + 3`.

**Поля «умер» / «снят» НЕТ.** Свип уровня надо считать самому.

## 10. `detect_sponsored_candle` (стр. 461)

detect_sponsored_candle(df, lookback=10, atr_len=14, min_body_atr=0.5,

| поле | тип | смысл |
|---|---|---|
| `ts` | `df.index[idx]` | Timestamp / int |

| `top` | `float` | bull: `max(open,close)`; bear: `high` |
| `bottom` | `float` | bull: `low`; bear: `min(open,close)` |
| `direction` | `'bull'` / `'bear'` | сторона разворота (bull = снял МИНИМУМ и закрылся вверх) |
| `mt` | `float` | Mean Threshold = `round((top+bottom)/2, 8)` — проверено тождественно |
| `open_level` | `float` | `open[idx]` |
| `swept` | `float` | пробитый экстремум за `lookback` баров ДО (не включая сам бар) |
| `broke_structure` | `bool` | 🔴 см. ниже |
| `has_imbalance` | `bool` | 🔴 см. ниже |
| `confirmed` | `bool` | `== broke_structure and has_imbalance` — проверено тождественно |

✅ **Сама свеча: лаг 0** (замер 12 из 12) — критерии «снял ликвидность + закрылся против
фитиля» считаются по закрытому бару.

🔴 **Флаги `broke_structure` / `has_imbalance` / `confirmed` — ЛАГ ДО `confirm_bars` = 5
баров.** Замер: 3, 5, 3, 2, 3, 5, 0, 4, 0, 0, 5, 2 → медиана 3, максимум 5.
Они смотрят в окно `[idx+1 .. idx+confirm_bars]` ВПЕРЁД. Строка `SponsoredCandle`
содержит бар `idx` и одновременно знание из будущего на 5 баров: **ставить флаг
`sc_confirmed` на бар `idx` = look-ahead 1.25 ч на 15m.** Ставить на `idx + confirm_bars`.

🔴 Докстринг говорит «критерий 2: импульс после = **BOS**», внутренняя переменная
названа `bos`, а комментарий в коде и текст докстринга ниже говорят **CHoCH**.
Фактически считается «экстремум в окне вперёд превысил экстремум окна `lookback` назад» —
ни BOS, ни CHoCH из `detect_structure_breaks` тут не участвует.

Частота: 14 SC на 1000 баров, из них `confirmed` — **1** (диапазон по 5 символам: 0-5).
`confirmed` — редкое событие, выборка набирается медленно.

| `[3]` | `str` | `'bull'` / `'bear'` |
| `[4]` | `df.index[i]` | **ts БАРА ОБНАРУЖЕНИЯ** (третья свеча). ✅ Единственная причинная точка |
| `[5]` | `df.index[j]` или `None` | **ts митигации** (close за противоположной границей), `None` = ещё активен |

Разница `[4] - [0]` = **ровно 2 бара всегда** (проверено на всех 133 записях;
зафиксировано тестом `tests/unit/test_fvg_causality_contract.py`).

🔴 **Именно на этом споткнулись:** `swing_bridge.etl_fvg` брал `f[0]` вместо `f[4]` →
флаг ставился на 2 бара раньше знания → WR 96.3% против честных 43.8%, PF 52.55 против 0.72.

✅ **Лаг на поз. `[4]` = 0** (замер 33 из 33 + 12 из 12 в боевом скрипте). Но **лаг на
поз. `[0]` = 2 бара**, а на поз. `[5]` лаг неограничен — митигация приходит из будущего.

🔴 **Авто-порог пересчитывается по ВСЕМУ переданному ряду** и потому делает выдачу
нестабильной: `threshold=None` → средний |gap%| по всем барам × 2. Замер на BIRB:
на 400 барах — 55 FVG, на 600 барах — 76, но **6 из тех 55 ИСЧЕЗЛИ** (порог подрос).
Плюс у 7 общих изменилось поле `[5]`. То есть: набор FVG на префиксе ≠ префикс набора
FVG на полном ряду. **Для причинных замеров передавайте явный `threshold`** (например
`0.1`), иначе rolling-прогон и разовый прогон дают разные множества.
Замеренное авто-значение на BIRB/1000 баров: `0.12768%`; `threshold=0.0` → 223 FVG
вместо 133.

Условие фильтра — строгое `dper > threshold` (в коде `if dper <= threshold: continue`).
Мелкая асимметрия: у bull `dper` нормируется на `high[i-2]`, у bear — на `high[i]`.

Частота: **133 на 1000 баров** (bull 79 / bear 54), к концу ряда активных (`[5] is None`) — 18.

## 12. `detect_fvg_overlap` (стр. 587)

```python
detect_fvg_overlap(df, threshold=None, hold_bars: int = 5) -> List[dict]
```

**Возврат:** `List[dict]` с 8 ключами:

| ключ | тип | смысл |
|---|---|---|
| `lo` | `float` | нижняя граница ЗОНЫ ПЕРЕСЕЧЕНИЯ (`max` нижних границ), `lo ≤ hi` |
| `hi` | `float` | верхняя граница пересечения (`min` верхних) |
| `direction` | `'up'` / `'down'` | `'up'` = bull перекрыл bear (возможен разворот вверх) |
| `since` | `df.index[i0]` | **ts бара обнаружения ПОЗДНЕГО FVG** (`bull[4]` или `bear[4]`) |
| `held` | `bool` | зона удержалась на окне `hold_bars` |
| `held_ts` | `df.index[...]` | **ts бара, на котором `held` становится известен** = `since + hold_bars` (проверено: ровно 5 при `hold_bars=5`) |
| `bull` | `tuple` len=6 | **сырой кортёж `detect_fvg`** — та же раскладка, что в §11 |
| `bear` | `tuple` len=6 | то же |

🔴 **`held` — знание из будущего относительно `since`.** Флаг ставится на `held_ts`,
не на `since`. Докстринг это оговаривает, и это уже стоило нам WR 89-92% / PF 49-71 на
`bull_fvg_overlap_held_15m` (фикс 13.08.2026, комментарий в коде стр. 618-628).

🔴 **Возврат — ДЕКАРТОВО ПРОИЗВЕДЕНИЕ, не список зон.** Замер: 280 строк при
**103 уникальных `(since, direction)`**; на одну зону приходится до **11 строк**
(один bull-FVG пересекается с 11 разными bear-FVG). Подсчёт «сколько было перекрытий»
по `len()` завышает частоту в ~2.7 раза. Дедуплицируйте по `since`.

🔴 **Падает на UPPERCASE-колонках:** `KeyError: 'close'` (обращается к `df["close"]`
и `df.index` напрямую, без нормализации регистра).

🔴 **Дублирующийся индекс df ломает результат МОЛЧА.** Внутри строится
`pos = {ts: i for i, ts in enumerate(df.index)}` — при повторяющихся ts словарь схлопывается
в **последнюю** позицию, и `held` считается от другого бара. Исключения не будет.

Стоимость приемлема: 2000 баров → 260 FVG → 958 строк за 0.07 с.

## 13. `detect_elliott_impulse` (стр. 667)

```python
detect_elliott_impulse(zz: List[tuple]) -> List[dict]
```

**Принимает НЕ DataFrame, а результат `zigzag_atr`.**

**Возврат:** `List[dict]` с 7 ключами, хронологически (самый свежий — последний):

| ключ | тип | смысл |
|---|---|---|
| `waves` | `List[tuple]` длиной **6** | точки 0..5, каждая `(ts, price)`. `ts` унаследован от `zz` → Timestamp / int |
| `direction` | `'up'` / `'down'` | направление импульса |
| `lens` | `tuple` из 3 `float` | длины волн `(w1, w3, w5)` в **абсолютной цене**, не в % |
| `w2_retr` | `float` | откат волны 2 к волне 1 |
| `w4_retr` | `float` | откат волны 4 к волне 3 |
| `w3_ext` | `float` | расширение волны 3 к волне 1 |
| `textbook` | `bool` | `0.5 ≤ w2_retr ≤ 0.886` и `0.236 ≤ w4_retr ≤ 0.618` и `w3_ext ≥ 1.3` |

🔴 **`waves[5]` МУТИРУЕТ ЗАДНИМ ЧИСЛОМ.** Механизм — блок EXTENSION (стр. 700-719):
точка 5 тянется до последнего экстремума, пока цена не развернулась за волну 4. Значит на
более длинном ряду тот же импульс имеет **другой конец**. Замер (BIRB, префиксы 300→600
с шагом 5): один импульс дал **4 разные версии** точки 5:

```
P=405: waves[5] = 2026-08-21 21:45 / 0.05922   l5=0.00201
P=415: waves[5] = 2026-08-22 00:15 / 0.06089   l5=0.00368
P=425: waves[5] = 2026-08-22 02:15 / 0.06168   l5=0.00447
P=430: waves[5] = 2026-08-22 03:45 / 0.06182   l5=0.00461
```

Следствия: (1) `lens[2]` и любая метрика от точки 5 нестабильны; (2) поиск импульса по
ключу «waves[0] + direction» находит его **раньше**, чем наступает бар финальной точки 5
(в префиксном тесте это дало отрицательный лаг −1 и −19). Для причинных замеров
привязывайтесь к `waves[4]`, а точку 5 считайте «текущей оценкой», не фактом.

Замер: 3 импульса на 1000 баров при `dev=3`. `textbook` в этой выборке не менялся
при удлинении ряда, но это следствие малой выборки, а не гарантия.

Возврат `[]` при `zz` короче 6 точек (проверено: `[]` и срез из 3 точек → `[]`).

## 🔴 ЛОВУШКИ

1. **«ts» — это `df.index[i]`, а не время.** Тип определяется индексом входного df:
   DatetimeIndex → `pd.Timestamp`, RangeIndex → `int`. `research_harness` советует
   `.reset_index(drop=True)`, поэтому в проекте живут ОБА режима одновременно.
   Код вида `df.index.get_loc(f[0])` корректен только пока вы знаете, какой df передали.

2. **`detect_fvg`: `f[0]` — левый край бокса (`i-2`), `f[4]` — бар обнаружения (`i`).**
   Флаг ставится на `f[4]`. Ошибка стоила WR 96.3% против честных 43.8%.
   Разница ровно 2 бара, поэтому в бэктесте она не выглядит абсурдной и проходит глазами.

3. **`detect_fvg` без `threshold` нестабилен.** Авто-порог считается по всему переданному
   ряду: удлинение 400 → 600 баров **удалило 6 из 55** ранее найденных FVG и изменило
   поле митигации у 7. Для rolling/причинных замеров передавайте явный порог.

4. **`StructureBreak` — единственная структура, где `ts` идёт ПЕРВЫМ полем, а `idx` вторым.**
   У `Swing` и `SponsoredCandle` — наоборот. Позиционная распаковка ошибётся молча,
   потому что оба поля «правдоподобны».

5. **`OrderBlock` не содержит времени вообще — только `int`-индексы.** Смешение с
   остальными детекторами в одном словаре событий даёт `TypeError` при сортировке
   (`int` vs `Timestamp`) — либо, что хуже, «работает» на RangeIndex-df и падает на боевом.

6. **`OrderBlock.left_idx` ≠ момент известности.** OB становится известен на `break_idx`,
   на 19-44 бара позже своей свечи. Признак «OB был N баров назад» надо считать от
   `break_idx`.

7. **`mitigated_idx` / `is_breaker` мутируют задним числом** (2 из 6 OB в замере).
   Снимок по всему ряду знает будущее. Причинный фильтр: `mitigated_idx <= бар_замера`.

8. **`active_order_blocks(obs, n_bars)` — `n_bars` ничего не делает** (мёртвый параметр,
   проверено: 0 и 10⁹ дают одно и то же), и **сама функция не каузальна**: «активен»
   там значит «не пробит за всю историю df», а не «не пробит к бару X».

9. **`SponsoredCandle.confirmed` знает будущее на `confirm_bars` = до 5 баров** (замер:
   максимум 5), хотя лежит в строке с баром `idx`. Ставить на `idx` = look-ahead 1.25 ч
   на 15m.

10. **`detect_fvg_overlap` возвращает пары, а не зоны:** 280 строк на 103 уникальные
    зоны, до 11 строк на одну. `len()` завышает частоту в ~2.7 раза.

11. **`detect_fvg_overlap.held` известен только на `held_ts`**, не на `since`. Поле
    `held_ts` для этого и добавлено — им и пользуйтесь.

12. **`waves[5]` у Эллиотта плавает** — 4 версии одной точки при удлинении ряда.
    Всё, что считается от точки 5 (`lens[2]`, цели, «импульс закончился»), нестабильно.
    Опора — `waves[4]`.

13. **`zz[-1]` не подтверждён** — последняя точка ZigZag продлевается (12 случаев из 375).
    Подтверждённый префикс при этом стабилен: 0 расхождений на 399 сравнениях.

14. **Лаги подтверждения не равны нулю у большинства детекторов** и не видны в возврате:
    свинги/`classify_structure` — **50 баров** при `length=50`, `zigzag_atr` и
    Эллиотт — **5**, `detect_equal_levels` — **3**, SC-флаги — **до 5**.
    Ноль только у `detect_structure_breaks`, `detect_fvg` (поз. 4) и самой свечи SC.
    Пересчитать: `python scripts/smc_confirmation_lags.py --symbols 3 --events 10`.

15. **`classify_structure` и `detect_fvg_overlap` падают на UPPERCASE-колонках** —
    в отличие от остальных одиннадцати, которые нормализуют регистр сами.

16. **`detect_fvg_overlap` на df с дублями в индексе даёт неверный `held` молча** —
    внутренний `{ts: i}` схлопывается в последнее вхождение.

17. **`detect_swings` возвращает major и minor В ОДНОМ списке**, отсортированном по `idx`;
    на 1000 барах 9 баров несут обе метки. Фильтруйте по `.level`.

18. **Первый свинг каждого типа в `classify_structure` всегда `HH`/`LL`** — это заглушка
    отсутствия предыдущего экстремума, а не наблюдение о структуре.
