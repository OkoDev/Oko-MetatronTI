> Читают ВСЕ агенты. Claude: через `.claude/CLAUDE.md`. DeepSeek: через `AGENTS.md`.

## Концепция: мета-куб (фрактал Куба)

```
        Точность (Opus/Claude)
              /│\
   Объём ────┼──●──┼──── Консенсус
 (DeepSeek   │ ARCH │    (Рой 6 LLM
  1M ctx)    │центр │     + meta-синтез)
              \│/
         СТРОЯТ → торговый Куб (13 сфер)
```

Команда агентов = под-куб вычислительного слоя НАД торговым Кубом. Три грани + ты (ARCH) = центр / Shared Context Bus команды, принимаешь решения.

| Грань | Агент | Сила | Слабость |
|---|---|---|---|
| **Точность** | Claude (Opus) | критичный код, архитектура, глубина | контекст ограничен, дороже |
| **Объём** | DeepSeek (1M ctx, DeepCode) | массовый контекст, дёшево, рутина | цена ошибки в коде, lost-in-middle |
| **Консенсус** | Рой (`team_ask`, 6 LLM + meta) | диверсификация мнений, валидация | урезанный контекст, медленно |

## Матрица маршрутизации

| Задача | Исполнитель | Триггер (как Claude определяет) |
|---|---|---|
| Критичный код: `core/trading/` (register_trade, gates, sl_tp), `core/signals/`, `core/smc/`, `bot/` | **Claude** | правка живого кода; цена ошибки = «бот стоит» |
| Архитектура, дизайн сфер, Куб, shadow-механики | **Claude** | требует глубины + полный контекст проекта |
| Объёмный анализ: сотни сделок, весь DISCUSSION-архив, бэктест-дампы, **vault-recall** | **DS** | >100k токенов контекста / сырые дампы (1M вмещает) |
| Рутина: `scripts/` аналитика, тесты, `docs/`, research, рефакторинг низкого риска | **DS** | низкий риск, изолированная зона |
| Спорное решение, архитектурная развилка, валидация гипотезы | **Рой** | нужны разные мнения + синтез |
| Быстрая справка одним LLM | **`llm_ask`** auto-route | мелкий вопрос, скорость |

## Уровни автономии Claude (вызовы рой/deepseek-API) — принято 02.06

**Режим: АВТО + УВЕДОМЛЕНИЕ.**
- ✅ **Авто (сообщаю «запускаю рой по X», не жду разрешения):** рой/deepseek для исследования, валидации гипотез, объёмного анализа — когда ускоряет и данные не критичны.
- ⚠️ **С подтверждением:** дорогие массовые прогоны (десятки вызовов), отправка чувствительного (ключи, личное), действия меняющие торговлю/боевую БД.
- 🔑 Каждый вызов = отправка контекста проекта на сторонние API (необратимо, может кэшироваться). Это цена автономии — потому массовое/чувствительное под флажком.

> ⚠️ DS-агент (окно DeepCode) Claude НЕ запускает программно — это отдельное VSCode-расширение. Claude лишь **готовит** задачу для DS (запись в DISCUSSION/TASKS под ролью DS), запускает её пользователь в окне DeepCode.

## Правила взаимного делегирования

**Claude (я):** перед крупной задачей оцениваю объём/тип → **предлагаю маршрут** пользователю («это объёмный анализ — в DS?» / «спорно — рой?»). Объёмное/толерантное к ошибке не тяну сам — делегирую.

**DeepSeek (DS):** знает про Claude (ядро) и рой (консенсус).
- Упёрся в критичный код (`core/trading/`, gates, signals) → **эскалирует к Claude**, не правит сам.
- Нужен консенсус/спорно → **предлагает рой**.
- Свою работу фиксирует в DISCUSSION под ролью **DS**.

**Эскалация:** любой агент на спорном → рой; DS на критичном → Claude; решение по архитектуре → Claude + ARCH.

## 🔴 Рой = гипотезы, НЕ истина — верификация обязательна

Рой ошибается двумя путями (оба зафиксированы 01-02.06):

| Тип ошибки | Пример | Перепроверка Claude |
|---|---|---|
| **Контекст-слепота** | DEV-238: рой советовал EventBus-адаптер на неверной модели кода (не видел внутренностей шины) | **grep/Read** — соответствие реальному коду |
| **Данные-слепота** | DEV-240: гипотеза «scan>250s = skip entries» опровергнута shadow n=630 (LATE +0.477R ЛУЧШЕ FAST) | **данные** — shadow/backtest, если гипотеза эмпирическая |

**Правило:** Claude НИКОГДА не внедряет вердикт роя без перепроверки. grep (код) + данные (эмпирика). Это [[feedback_discuss_before_act]] + grep-before-claim.

**DS в рое = контекст-якорь:** с 1M DS видит реальный код/vault → его голос корректирует **контекст-слепоту** остальных моделей (урезанный контекст), meta-синтез взвешивает обоснованный голос выше. НО **данные-слепоту DS НЕ лечит** — эмпирическую гипотезу всё равно валидируем данными.
