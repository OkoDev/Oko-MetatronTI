# 🧩 Модульная архитектура продукта — решение 17.10.2026

> Егор: «скелет модульный, на который потом натянем любой дизайн — поменять тему, шрифты, иконки быстро.
> Не переделывать 10 раз. Модули должны переезжать по одному щелчку, компоновка может быть любой».
> Это тот же принцип, что у ядра Куба ([ARCH-125](../METATRON-KERNEL.md)): скелет без доменной логики, к которому
> подключаются сферы. Здесь — скелет без визуального дизайна, к которому подключаются модули.

## Иерархия имён (подтверждена 17.10)
| Имя | Что это |
|---|---|
| **METATRON** | компания и ядро — Куб Метатрона (Metatron Kernel). Ядро переносимо: потенциально отдельный продукт |
| **ОКО** | торговый движок, первый клиент ядра: бот, детекторы, скринер, OKO-SM |

## Три слоя
**1. Токены (тема)** — один файл: цвета, шрифты, радиусы, отступы, тени, иконки, эффекты, знак. Модули рисуются
**только** токенами — ни одного захардкоженного цвета. Сменить тему = заменить файл.
- Шрифты — **единые** для всех тем; выбор после маркетинговых/дизайн-исследований (не блокер).
- Цвета — **база + альтернативная тема**: база — бирюза ([brand.md](brand.md)), альтернатива — золото (мокап, /moment).
- Знак и вордмарк — один модуль «Бренд» на все поверхности (сейчас на /moment кружок в рейле и текст METATRON
  в шапке — несостыковка, лечится здесь).

**2. Модули** — самостоятельный блок с контрактом «данные → вид». Не знает, где стоит; берёт данные из своего
API; рисуется токенами. Один модуль — много мест.

**3. Раскладки (вкладки)** — конфиг «какие модули и где». **Фиксированные** из конфига (перетаскивание
пользователем — позже; архитектура допускает). Переезд модуля = строка в раскладке, не код.

## Раскладки (по мокапу «ОКО — терминал», вкладки переименованы 17.10)
| Вкладка | Модули |
|---|---|
| **Повестка** | Вердикт дня · Приборы · Пульс · Кандидаты (+ строка Карты) |
| **Терминал** (в мокапе «Стол») | слева Кандидаты / В игре · центр График · справа Ордер + Риск + Карта · снизу Позиции |
| **Фильтр** | Конструктор фильтра · Скринер / результаты |
| **Монитор** | Сетка графиков → в раскрытом окне График + Ордер + Риск · Позиции |
| **Волны** | Журнал волн · График |
| **Бот** | Живая проверка стратегий · Риск-каркас · Здоровье · Лента |

Карта и Кокпит из :8010 отдельными вкладками не остаются — их модули расходятся по раскладкам.
Монитор ускоряет решение («много монет в поле зрения»), Терминал — решить и исполнить по одной монете;
торговля (Ордер + Риск) доступна в обоих — это один и тот же модуль.

## Тарифы гейтят модули, а не страницы
Observer видит, например, Кандидатов без Ордера; Operator — всё; Quant — + живую проверку и API
(ступени — [pricing.md](pricing.md), stack.md). Модуль под замком показывает «по подписке», как рейл /moment.

## Открыто
- **Ордер для пользователей** — закладка на будущее (решение 17.10). Безопасность ключей бирж не решена:
  (а) только владелец · (б) ключ у пользователя в браузере · (в) план без исполнения. Плюс юридическое (ARCH-141).
- **Позиции** — модуль в Терминале и Мониторе (решено); источник данных уточнить.
- **Доминация** — в Повестку или в Бот.
- **Шрифты** — после исследований.
- **Тексты** — из [glossary.json](glossary.json), не из мокапа (мокап на жаргоне до канона).
- **Коллизия «импульс»** — отрезок движения и волновой импульс (glossary.md).

## Порядок работ
1. Токены (база + альтернатива, знак) → 2. Опись модулей с контрактами данных (эта таблица → схемы JSON) →
3. Раскладки как конфиг → 4. Визуальный дизайн модулей → 5. Сборка в Next.js, вкладка за вкладкой (stack.md).
