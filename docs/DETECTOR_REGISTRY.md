## 0. Различение, ради которого документ существует

Все наши замеры отвечают на вопрос «приносит ли инструмент **ДЕНЬГИ**».
Ни один не отвечал на вопрос «находит ли он **ТО САМОЕ ЯВЛЕНИЕ**».

| детектор | деньги | что это значит |
|---|---|---|
| верен | нет | явление реально, но не торгуемо — **честный отрицательный результат** |
| **сломан** | нет | **похоронили рабочую идею, не заметив** |

Второй случай у нас уже был: замена детектора импульса на конечный автомат дала
2.82 → 0.75, потому что автомат «размечает зигзаг, а не импульс». Поймали случайно.

**Стенд:** `scripts/detector_bench.py` — детекторы объявлены реестром, проверки
применяются ко всем автоматически. Новый детектор добавляется ОДНОЙ записью.

```bash
python scripts/detector_bench.py                                  # таблица
python scripts/detector_bench.py --symbol BTC/USDT --tf 1h        # другой инструмент
python scripts/detector_bench.py --export                         # события → JSON для графиков
```

### Четыре проверки, ни одна не смотрит на прибыль

| проверка | что доказывает |
|---|---|
| **ИНВАРИАНТ** | каждое срабатывание удовлетворяет определению явления арифметически |
| **ПРИЧИННОСТЬ** | детектор на `df[:n]` совпадает с детектором на полном `df` — не переписывает прошлое |
| **ЧАСТОТА** | флаг не выродился в константу (истинный в 90% баров — не детектор) |
| **СИНТЕТИКА** | ряд с ЗАЛОЖЕННЫМ явлением → находит; ровный ряд → молчит |

### 🔴 ГЛАВНОЕ ПРАВИЛО СТЕНДА

**«0 нарушений» при НУЛЕ проверенных — это не успех, а несработавший тест.**
Столбец «инв.пров» показывает, сколько событий реально проверено. Стенд печатает
«н/д», а не ✅, когда проверить не удалось.

Правило выучено дорого: за первый же прогон стенд обманул сам себя **дважды** —
дал ложную тревогу («BOS переписывает историю») и ложную галочку («FVG инвариант
чист» при нуле выполненных проверок). Оба поймались по физически невозможным
числам, а не глазами. **Инструмент для проверки инструментов сам нуждается в проверке.**

### 🔴 Честная оговорка: часть «замечаний» — дефекты ПРОВЕРОК, а не детекторов

| замечание | что на самом деле |
|---|---|
| `detect_equal_levels` — 134/134 «нарушений» | мой инвариант берёт два последних числовых поля как ЦЕНЫ, а там индексы → «расхождение 99.98%». **Инвариант надо переписать**, детектор не обвинён |
| `detect_order_blocks` — частота «0.0» | мой экстрактор позиций не нашёл `idx` у `OrderBlock` → частота не посчитана, а показана нулём |
| `detect_fvg_overlap` — 10224 события | позиции не извлекаются, поэтому 85% — оценка по числу событий на 12 000 баров, а не измеренная частота. **Требует проверки** |
| `smc_extensions` ×3 — «ложные на ровном ряду» | ровный ряд имеет постоянные high/low, что законно даёт «равные уровни». Нужен более строгий синтетический ряд |

Это не отговорки: **невыполненная проверка обязана выглядеть как «н/д», а не как ✅ или 🔴.**

## 2. 🔴🔴 ПАРАМЕТРИЧЕСКИЕ РАССОГЛАСОВАНИЯ

Детектор может быть верен, но вызван с параметром, который его ослепляет.
Это отдельный класс дефекта, и он не виден ни по деньгам, ни по инварианту.

### C-01 — `detect_structure_breaks(length=?)` · НАЙДЕНО 11.06 · **НЕ ЗАКРЫТО**

| | |
|---|---|
| эталон | **length=5** (OKO-SM, визуально подтверждён; `chart_builder`, `ote_signal_generator`) |
| в матрице и в бою | **length=50** — `config.yaml:1527` `arch104.choch_length: 50`, читается `swing_bridge._get_choch_length()` и кормит `etl_bos_choch`, `etl_order_blocks`, `etl_ote_premium` |
| комментарий в коде | «Менять на 5 после ре-майнинга 69 паттернов + A/B бэктеста» — не сделано |

**Замер 28.08 (5 монет × 3 ТФ, 8000 баров):**

| ТФ | сломов на 1000 баров: эталон → боевое | во сколько меньше | медиана ЛАГА, баров |
|---|---|---|---|
| 15m | 49.4 → **6.6** | **7.5×** | 23 → **323** |
| 1h | 48.8 → **6.4** | **7.6×** | 20 → **98** |
| 4h | 49.0 → **6.5** | **7.5×** | 18 → **14** |

🔑 На 15m признак BOS/CHoCH в матрице описывает слом **323 бара назад** (≈3.4 суток)
вместо 23 баров. Это не «свежая структура», а археология.

⚠️ Поправка к записи от 11.06: там сказано «length=50 → 5m/15m = **0 CHoCH**, полная
слепота». Сейчас не ноль — 6.6 на 1000 баров. Слепота не полная, но искажение
семикратное. Числа надо перемерять, а не переносить.

**Отравлены** (через `swing_bridge`): Order Blocks · BOS · CHoCH · OTE-premium/discount.
**Чисты:** FVG, FVG-overlap, Elliott (своя логика).

## 4. Как добавить детектор на стенд

Одна запись в `DETECTORS` (`scripts/detector_bench.py`):

```python
dict(name="detect_foo", group="SMC", need="smc",
     call=lambda d: module.detect_foo(d),
     pos=_pos_attr_idx,            # как достать индекс бара события
     inv=inv_foo,                  # инвариант: вернуть (сколько_проверено, [нарушения])
     synth=[("явление", synth_foo, 1, None), ("ровный", synth_flat, 0, 0)])
```

🔴 Инвариант ОБЯЗАН возвращать число реально проверенных. Если проверить нечего —
верните 0, и стенд напишет «не отработал» вместо ложной галочки.
