## 🎯 Цель

Дашборд = **«Око» бота, проявленное наружу.** Сейчас заперт локально (`127.0.0.1`). Цель — дать
видеть свой Куб **с мобилки, откуда угодно**, безопасно, как приложение (PWA).

**Куб-связь:** дашборд = persistence/observation-проекция Куба наружу. Это **тессеракт-доступ**
(к системе вне привязки к месту). Архитектурно опирается на 2 закона, выведенных 09.06:
- **Инкапсуляция:** фронт не знает про бота, бот не знает про фронт → общаются через ОДИН API-контракт.
  Меняешь дизайн фронта — бэк не трогаешь. (как Condor ⊥ мозг, [[principle_reuse_not_duplication]])
- **Переиспользование:** один API, клиенты = ПАРАМЕТР (локальный браузер ∥ мобила ∥ PWA ∥ Telegram-webapp).

## 🔴 ГЛАВНОЕ РЕШЕНИЕ (Phase 0 — развилка стека фронта)

`v0.app` генерит **React/Next.js**. Текущий v2 = **Vue 3**. Нельзя copy-paste код v0 в Vue. Выбор:

| | **A. Остаться на Vue 3** | **B. Перейти на React/Next.js (v0)** ⭐ |
|---|---|---|
| Задел | продолжить DEV-144 (но это лишь Stage-1 зачаток) | выбросить Vue-зачаток (не жалко, v0.1.0/4 компонента) |
| v0.app | только для ВДОХНОВЕНИЯ (перерисовывать паттерны руками в Vue) | **copy-paste код напрямую** — v0 нативно Next.js |
| Деплой мобайл | Vite build → свой хостинг | **Vercel из коробки** (Next.js родной) — PWA/мобайл/SSR даром |
| «как приложение онлайн» | надо настраивать вручную | **ровно то, что описал юзер** — Vercel+Next = mobile-app feel |
| Минус | v0-код не переиспользуешь | новый стек (но React ≈ Vue по сложности) |

**Рекомендация Даат: вариант B.** Vue-задел мизерный (Stage-1), а v0+Next.js+Vercel — это БУКВАЛЬНО
«приложение с мобилки онлайн» из коробки. Инструмент (v0) и цель (мобильный серверный доступ) сходятся
на Next.js. Не цепляться за выброшенный Stage-1 = [[principle_reuse_not_duplication]] наоборот (не держать
дубль-стек). **← решение юзера, не делать молча.**

*Прочие решения Phase 0:* (1) бэк — оставить aiohttp или мигрировать на FastAPI (auto-docs, pydantic)?
рекомендация: **оставить aiohttp** (работает, ~45 роутов, миграция = риск; вынести в модули хватит).
(2) деплой-модель (см. Phase 5).

## 🧭 Целевая архитектура

```
Бот (Python) → SQLite → API-слой [auth+versioned] → (Cloudflare Tunnel/HTTPS) → Фронт Next.js (Vercel, PWA)
   ▲ пишет           ▲ ЕДИНЫЙ контракт /api/v1/*          ▲ безопасный канал        ▲ мобила/десктоп
```

Бэк и фронт — **две инкапсулированные сферы**, связь = HTTP-контракт + auth-токен. Меняешь любую — вторая не знает.

### 🔴 ИНВАРИАНТ: дашборд НЕ потребитель биржи

Дашборд читает **только из БД и общего кэша** `data_collector` — **НИКОГДА не делает собственные
запросы к бирже.** Биржу дёргает ТОЛЬКО торговый цикл (один владелец rate-limit). Причина: 10.06 дашборд
был заблокирован, т.к. его live-роуты ходили на биржу напрямую и отъедали лимит у торговли (на фоне
531-пары). **Правильно:** торговый цикл пишет live-позиции/ордера/историю в БД (или shared-кэш) →
дашборд читает оттуда. Это та же инкапсуляция: дашборд знает только API/БД, не биржу.
**Phase 1 задача:** перевести live-роуты на чтение из БД/кэша → снять блокировку. Связь с ProxyPool
(если позже нужен отдельный биржевой канал для дашборда — через общий пул, не дубль-клиент).

## 🔐 Безопасность (его деньги!)

- **Никогда** не выставлять наружу без Phase 2 (auth). `/close` без auth = чужой закрывает твои сделки.
- **Cloudflare Tunnel** предпочтительнее открытого порта: бэк невидим из интернета, доступ только через
  туннель + auth. Не открывать порты на роутере/WireGuard.
- Секреты (API-ключи биржи) — НИКОГДА на фронт. Фронт видит только данные через API, не `.env`.
- Read-only режим для мобилы по умолчанию; мутации (close/settings) — за доп. подтверждением + admin-токеном.

позволяет (admin) закрыть сделку, ставится как PWA. Бэк за туннелем, секреты не утекают. god-object разнесён.
