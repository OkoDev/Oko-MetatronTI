**При верификации эффекта фикса/конфига — фильтровать метрики по МОМЕНТУ АКТИВАЦИИ (рестарт/коммит), НЕ по «за последние Nч».**

**Why:** 14.06 проверял min_rr ote=3.0 (39d31bc) по окну «10ч». Окно захватило до-фиксовые сделки (фикс активен с ~01:39 UTC, рестарт 04:39 локаль). Увидел «67 нарушителей RR<3» → построил ДВЕ неверные гипотезы подряд (config не резолвит dict → рассогласование gate↔запись по SL) → потратил кучу проверок (config/source/chain/cap/SL). Реальность: split по моменту фикса дал **ДО фикса 427 нарушителей, ПОСЛЕ фикса 0** — фикс работал идеально. Грязное окно = артефакт, проблемы не было. Это нарушение моего же [[feedback_data_era_first]] (data-era split).

**How to apply:** перед выводом «фикс не работает / X плохой» —
1. Узнать момент активации: `git show -s --format=%ci <commit>` + `stat bot_instance.lock` (рестарт).
2. Метрики фильтровать `created_at >= '<момент>'` (UTC!), а не `datetime('now','-Nh')`.
3. Сравнить ДО vs ПОСЛЕ — если «нарушители» только ДО → фикс работает, окно грязное.
4. ТОЛЬКО потом, если после-фикса >0 → копать код.

Связь: [[feedback_data_era_first]] (общее правило data-era), паттерн «разгон гипотез» (как с EXEC-SIM-SPLIT — поспешил проектировать). Сначала чистое окно → потом гипотеза о коде.
