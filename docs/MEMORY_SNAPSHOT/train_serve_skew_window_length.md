**Моя ошибка 05.10, найдена агентом-инвентаризатором в тот же день.**

`scripts/smc_backfill_snaps.py` пересчитывал историю на окнах
`1d=60 · 4h=200 · 1h=200 · 15m=200`, а бой строит тот же снимок на
`15m=100 · 1h=100 · 4h=60 · 1d=60` (`core/trading_intelligence.py:2151-2153` и `:2208`).
Совпадал только 1d. Модель училась на одних распределениях, в бою получала другие —
под теми же именами полей.

**Замерено на одних и тех же символах, два набора окон:**

| поле | бой (4h=60) | обучение (4h=200) |
|---|---|---|
| `ote_zone` | **5%** | **15%** (×3) |
| `ob_bull` | 55% | 70% |
| `brk_internal = True` | **100%** | **68%** |
| `eql_dist_atr` пропущен | 100% | 92% |

**Физическая причина у структуры.** `core/structure/pivots.py:31` ищет опорные точки
только среди баров `[0 … len−window]`. При `window=50`:
- 4h/1d в бою = 60 баров → пивоты только среди баров **0–9**;
- 15m/1h = 100 баров → только в первой половине окна.

Отсюда `brk_internal` ≈ константа `True` (замер 98–100%), `brk_strength` теряет
слагаемое «+10 за старший слой» и сжимается до шести значений. **Старший слой
структуры в бою практически недоступен** — а модель на 200 барах училась его различать.

🔴 **`SNAP_SCHEMA_VERSION` ЭТОТ КЛАСС НЕ ЛОВИТ.** Версия сторожит состав и смысл полей
(ARCH-137.6), но длина ряда в неё не входит: оба снимка формально v3. Версионирование
дало ложное чувство защищённости — я проверил версию и решил, что данные однородны.

**Правило:** длина окна — **часть определения признака**, наравне с порогом детектора.
Любой пересчёт истории обязан брать окна из боевого кода, а не «побольше, чтобы хватило».
Это частный случай [[law_reproduce_live_config_first]]: сначала воспроизвести бой.
Проверка — одна: `grep -n "limit=" core/trading_intelligence.py` в месте сборки снимка.

**Чем это било по выводам:** на этих данных сделаны замер AUC (0.529 против контроля
0.506) и замер конфлюэнции ([[confluence_raises_variance_not_edge]]). Оба требуют
перепроверки на боевых окнах. Старая выборка сохранена как
`oko_feed/smc_backfill_wide200.db` — для прямого сравнения «широкие против боевых»,
это сам по себе полезный замер чувствительности к окну
(ср. [[window_sensitivity_only_smc_breaks]]: SMC — худшая семья по этому параметру,
расхождение 37.3%, у `*_active_*` до 99%).

**Починено заодно (тот же обход кода):**
- `_label_from_proba` имел мёртвую развилку: `if ob_4h or ob_1h: return X` и сразу
  `return X` — обе ветки одинаковы, проверка OB не влияла ни на что.
- `_load_saved` не читал `ctrl_auc`, хотя backfill его писал → модель поднималась даже
  с нулевой Δ над контролем. Теперь порог 0.02 проверяется при подъёме.
- Своё обучение (`fit`) писало модель БЕЗ контроля и перезаписало бы файл более слабым
  протоколом (CV по соседним во времени сделкам завышает: 0.566 против 0.505 по неделям).
  Теперь `fit` тоже считает перестановку и не сохраняет модель с Δ < 0.02.
