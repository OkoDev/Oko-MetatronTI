**Слой 13 — волновой фильтр фазы поверх R2/S2-отбоя (сессия 01.07.2026). Урок про look-ahead + осторожный итог.**

## Что было
Гипотеза: вход R2-отбой (short) только если у R2 завершился 5-волновой bull-импульс (исчерпан) →
цена не вернётся свитить стоп. Детектор `detect_elliott_impulse(zigzag_atr(df,11,dev=5))`, стоп за
вершину волны 5, цель R1. **Full-df результат: mean +5.75, WR 96%, n=48, ВСЕ годы+ (граль-вид).**

## 🔴 Look-ahead вскрыт walk-forward
Пересчёт волны ТОЛЬКО на `df.iloc[:i+1]` (без будущего) для каждого сигнала:
```
full_df:       n=48  mean +5.75  WR 96%
walk-forward:  n=16  mean +6.91  WR 100%   → выжило 16/48
```
**32/48 (67%) сигналов ИСПАРИЛИСЬ** — были хиндсайтом. Источник look-ahead в детекторе:
1. **Extension волны 5** (`while k<len(typed)`) тянет вершину ВПЕРЁД по будущим барам.
2. **zigzag confirm-lag**: пивот подтверждается через `length=depth/2` баров ПОСЛЕ точки.
На баре входа i фильтр «знал», что импульс завершён, хотя в реале подтвердилось бы позже.
Та же ловушка: [[bug_select_significant_impulse_full_dataset_lookahead]] · [[wave_filter_mfe_insight]].

## Итог (ни принять, ни отвергнуть)
Выжившие 16 честных сигналов сильно плюсовые (+6.9%, WR100%), НО:
- **n=16 за 5 лет на 461 символе = статистически незначимо** (WR100% легко удача).
- **~3 сделки/год = непрактично редко** даже если edge реален.
- Волновой детектор look-ahead делает поле ОПАСНЫМ (легко самообман — 32 фантома тому пример).

**Why:** доказывает необходимость walk-forward для ЛЮБОГО волнового/zigzag/pivot-детектора (полный df
= хиндсайт). **How to apply:** если возвращаться к волне — ТОЛЬКО с честным walk-forward детектором
(строить на префиксе) + набрать n через мульти-dev/мульти-ТФ/больше истории. Иначе +5.7% = фантом.
Скрипты `scripts/atr_change_layer13_wave.py` + walk-forward inline. Мерить в % net [[principle_measure_pct_not_r_LAW]].
