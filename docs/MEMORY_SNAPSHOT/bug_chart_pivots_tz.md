**13.07: Егор прислал BTC-скрин нашего SMC-чарта — «проверь все пивоты!». Все 8 плашек мимо:
D 0.35-1.21%, W 1.72-3.51% (W:PP 62162 vs честный 63248).**

## Диагноз (класс ARB-бага НАОБОРОТ)
- `pivot_cache` бота ЗДОРОВ: Δ0.00-0.01%, period_start свежий, страж pivot-sanity работает.
- Врал РЕНДЕРЕР: `scripts/wave_chart_lab.py::_calc_pivot_levels` считал пивоты сам от 1h-ресемпла
  с ДВУМЯ дефектами:
  1. `tz_offset_hours=3` — МСК-сутки/недели. Комментарий «как в TradingView у пользователя» —
     ЗАБЛУЖДЕНИЕ: TW считает пивоты от БИРЖЕВЫХ UTC-периодов независимо от таймзоны отображения.
  2. `resample("W-MON")` с дефолтами pandas = недели, ЗАКАНЧИВАЮЩИЕСЯ понедельником (окно вт→пн);
     биржевая неделя пн→пн требует `label="left", closed="left"`.
- Чартовые числа не совпадали НИ с одним честным окном — смесь обоих дефектов.

## Фикс (коммит в wave_chart_lab.py)
`_pivots_from_cache(symbol)` — чтение pivot_cache (1D/1W) с гардом свежести
(period_start = текущий период UTC) — ПЕРВИЧНЫЙ источник для build_signal_chart;
`_calc_pivot_levels` остаётся fallback'ом (символ вне кэша) с tz=0 + label/closed left.
Потребители: oi-fast (чарты радар-алертов, перезапущен) + oko-bot (паспорт монеты, рестарт Егора).

**Why:** один и тот же расчёт в двух местах разошёлся — чарт «улучшили» под МСК и забыли.
Все уровни (pivot/OTE/магниты) на визуале обязаны идти из ТОГО ЖЕ источника, что у торговой
логики, иначе Егор принимает решения по чужим уровням. **How:** новый уровень на чарте →
сначала grep единого калькулятора; сверка чарт↔TW↔кэш при любом «что-то не так с уровнями»
(Егор ловит глазом — третий раз подряд). [[principle_reuse_not_duplication]] · pivot-sanity.
