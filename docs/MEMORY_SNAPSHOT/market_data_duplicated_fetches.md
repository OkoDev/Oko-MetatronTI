Егор 28.09: «зачем нам дублированные загрузки?!» + «у нас в проекте есть правила переиспользования!»

**Инвентаризация 28.09 (`docs/MARKET_DATA_INVENTORY.md`):** по трафику дубли ~5% (спутники ~1–1.5 тыс. запросов
свечей/ч против ~20–25 тыс. у бота); главная нагрузка — скан бота: 1h/4h/1d по REST каждый цикл (3m/5m/15m уже из
MarketWS-v2, 618 пар), до 12 с на пару. Главный вред — 3 источника и 6 реализаций загрузки; три теневых журнала
(ote-cell, method-shadow, oi-fast) судят сигналы по ценам BINANCE, а торгуем на BingX. Глубина разная (4h: 180 у
бота, 1000 у oko-sm-watch, 15m: 1500 у method-shadow) → каждый качает всю историю каждые 15 мин ради 0–1 нового бара.

**28.09 решения Егора и ход:** BingX по умолчанию, Binance — исследования, паркеты, ТФ от 3m. Сделано: хранилище
`core/infra/market_store.py` ({root}/{exchange}/{tf}/{BASE}/{YYYY-MM}.parquet, только закрытые), сервис pm2
`market-store` (581 монета, 3 запр/с, 16 потоков — прямой BingX отвечает 1–20 с и рвёт соединения; 4h готов за
11 мин, всё ~3 ч), канал = bingx_klines v3 (сверен с ccxt: 0 расхождений; ccxt отдаёт и незакрытый бар).
Первый клиент — oko-sm-watch (50/50 совпало до бара). Дальше: хук WS для 3m/5m, волны, тени, терминал, бот.

**🔴 29.09 поправка к «1h/4h/1d каждый цикл» — НЕВЕРНО:** у старших ТФ TTL ≈ длина свечи, hit 88–98%
(`[OHLCV-CACHE]`). Но это всё равно 50–60% REST скана и ~90% после рестарта, а закрытый бар доходил с опозданием до TTL.
**Бот — клиент №2:** `core/infra/htf_from_store.py` (закрытые из хранилища + текущий бар из 15m WS-кэша; нехватка → REST),
в `ApiEngine.fetch_ohlcv`, config `market_store.bot_htf` off|shadow|on. Оффлайн 40 монет: 119 сверок, 0 расхождений;
в бою shadow 77/0 (после починки дыр WS-кэша [[ws_cache_holes_after_restart]]) → **`on` с 29.09 05:00**.
Ловушки этого шага: 🔴 голое `on` в YAML = `true` (режим молча не включился — теперь кавычки + код понимает bool);
запросы глубже канона (график 1h×530, radar 4h×400) и молодые монеты падали в REST → глубина чтения по запросу +
«хранилище исчерпано» = вся история монеты (сверено SI/UBIK; 577/578 монет с согласованной историей по ТФ).
**Шаг 2 (29.09 15:17):** 3m/5m живьём — закрытые бары WS бота → очередь `core/infra/market_spool` (CSV по минутам) →

**Шаг 3 (29.09 16:03):** 15m тоже через очередь (REST-проход снят). `market-store`: приём очереди и лечение — ОТДЕЛЬНЫЕ

`core/infra/pydantic_config.OkoConfig` (extra=forbid) роняет валидацию — добавлено поле `market_store`.

**Why:** копия источника = дрейф: одна монета может иметь разные бары в боте, терминале и теневых журналах; лишняя
нагрузка на API (анти-бан сага); обход бага ccxt стал ВТОРЫМ каналом вместо починки первого.
**How to apply:** новый процесс НЕ качает рынок сам — берёт из единой сферы данных (BACKLOG N15). Это первый
практический шаг выхода из монолита: Сфера 1 = единый источник для всех процессов, различия (биржа/ТФ/глубина) —
параметры. Связано: [[bus_is_blackboard_not_mesh]], [[data_feeds_staleness_26sep]].
