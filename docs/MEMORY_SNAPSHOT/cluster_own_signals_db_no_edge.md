Замер по решению Егора после опроса по ARCH-101 (30.09): `scripts/cluster_db_measure.py`, отчёт —
`obsidian/Research/2026-09-30-Cluster-Own-Signals-DB.md`. Кластер K = разные монеты у того же источника и стороны
(бар 15m по регистрации / окно ±15 мин); исход — чистый %; перестановка внутри месяца, дня, «день×сторона».

**Итог:** 14 источников — все базы в минусе, кроме ote_nested (+0.06, хрупкий). Кластер K≥2 в плюс не выводит нигде.
pivot_reversal: −0.49 → −0.32 (p дня 0.0007, обе стороны, 5/6 месяцев, SIM и VST, 57% монет), медианы равны.
wt_signal — только март (артефакт времени); arch104, oko_ote — только июнь. Радар: кластер хуже (не значимо, n=80).

**Ловушки БД (важно для любых замеров по simulated_trades):**
- `costs_pct` = 0 у ВСЕХ сделок до июля 2026 → издержки пересчитывать единой формулой (`trade_writer`: 2×taker + часы/8×funding);
- колонка `timeframe` = '15m' у 58 759 из 58 822 — это не ТФ источника; реальный — по источнику (features `entry_tf` = ТФ входа);
- `source_router` пуст до июня (и 2 430 в июле) → брать `signal_type`;
- живые биржевые механики в БД почти не представлены (choch_wavec 12, impulse_fib 8, waves_long 14 закрытых) —
  их кластер мерить только бэктестом через харнесс.

**Why:** опрос роя и субагентов (ARCH-101) сошёлся: потребитель в шине — только после офлайн-замера с эджем.
Замер эджа не нашёл → общий «кластер-гейт» в шину не нужен; знак кластера разный по механикам
(подтверждает [[cluster_of_fills_not_setups]], [[cluster_gate_market_wide_flush]]).
**How to apply:** не предлагать кластер-потребителя в бот по данным БД. Следующий шаг, если вернуться: одиночка vs
кластер по бару сигнала на бэктесте живых разворотных механик; ширина рынка как контекст; K с учётом `signal_drops`.
