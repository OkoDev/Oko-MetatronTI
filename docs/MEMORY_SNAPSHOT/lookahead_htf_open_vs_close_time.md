# 🔴🔴🔴 LOOK-AHEAD ВИД 6: ОТКРЫТИЕ ПРОТИВ ЗАКРЫТИЯ БАРА (09.09.2026)

Целая линия находок за день оказалась артефактом одной строки.

```python
# БЫЛО — заглядывание вперёд на весь ТФ слоя
j = np.searchsorted(d.index.values, bidx, "left") - 1

# ПРАВИЛЬНО — по времени ЗАКРЫТИЯ
close_time = d.index.values + np.timedelta64(tf, "m")
j = np.searchsorted(close_time, bidx, "right") - 1
```

При `resample(label="left")` индекс бара = **время его ОТКРЫТИЯ**. Бар слоя с ТФ=200m,
открывшийся в 10:00, закрывается в 13:20. Первая строка на моменте 10:03 вернёт именно
его — со структурой, посчитанной по данным до 13:20.

## 🔑 Почему это особенно коварно

**Утечка пропорциональна ТФ слоя.** На слое 3m — 3 минуты, на слое 200m — 200 минут при
горизонте замера 240. Значит она **фабрикует ровно тот результат, который хочется
увидеть**: «сила растёт с масштабом окна», гладкую степенную зависимость (R²=0.93),
t=35-40 и прохождение всех контролей — контроль по волатильности утечку не ловит,
потому что она сидит в самом признаке, а не в выборке.

## Что было снято этой ошибкой (всё считалось на заражённом кубе)

- «разворот структуры на большом окне: +0.61 / +1.46 / +3.23% за 4ч, t=35-40»
- «каскад согласия вверх по лестнице: +0.44 → +2.60%, IS→OOS 6 из 6, охват 49/49»
- «согласие младших слоёв вредит, градиент убывающий»
- «MFE/MAE 4.67 на слое 5», «лимитный вход хуже рыночного»
- «сила ∝ окно^0.69, вес слоя пересчитать в 5 раз»

Честный замер (событие берётся на баре СВОЕГО ТФ, форвард оттуда же, 24 монеты,
13 окон, контроль по ATR): CHoCH и BOS дают −0.07…+0.05% на всех окнах, охват монет
10-26 из 48. **Сигнала нет.**

## Что устояло (считалось без форварда)

[[hypercube_scale_step_is_12x_not_4x]] — масштабная инвариантность совпадения слоёв ·
диагностика кривизны детекторов (`liq_near`/`ob_near` схлопываются в ноль,
`liq_void` разбухает ×70) · [[wt_divergence_detector_only_sees_neighbor]] ·
стабильная доля BOS/CHoCH (46%) на всех масштабах.

## 🔴 ВТОРОЙ СЛУЧАЙ ТОГО ЖЕ КЛАССА (та же сессия, через несколько часов)

Отбор сделок по **глубине экстремума** — на скольких слоях лестницы подтверждён тот же
swing. Дало идеальный монотонный градиент: −0.32% → +4.10%, WR 32% → 86.6%,
охват 39/39 монет, IS→OOS проходил на обеих сторонах симметрично.

Утечка: swing слоя `tf` подтверждается через `LEN×tf` минут ПОСЛЕ экстремума. Вход на
3m — через 30 мин; подтверждение на 240m — через **40 часов**, при удержании сделки 15 ч.
То есть отбор шёл по признаку, который проявится уже после закрытия позиции.

Каузальный перемер (глубина только по слоям, подтверждённым ДО входа):

```
каузально доступны: глубина 1 → 97.5% сделок · 2 → 2.5% · 3+ → НЕ СУЩЕСТВУЕТ
                    глубина 1: −0.290% (0/39 монет) · глубина 2: −0.440% (1/39)
```

Весь эффект был утечкой **на 100%**, не частично.

🔑 Общий механизм обоих случаев: **признак становится известен позже входа, и запаздывание
растёт с масштабом слоя** — поэтому утечка выглядит как гладкий монотонный градиент по
масштабу и проходит все обычные контроли.

## Правило впредь

🔴 При ЛЮБОЙ склейке разных ТФ проверять: индекс — открытие или закрытие?
Тест дешёвый: сдвинуть HTF на +1 бар и перемерить. Если результат заметно упал —
была утечка. Ставить его в харнесс до, а не после красивых чисел.

🔴 **Гладкий монотонный рост метрики вместе с ТФ/окном — сам по себе повод искать
утечку, пропорциональную масштабу.** Красота зависимости здесь не довод «за», а улика.
Случилось ДВАЖДЫ за одну сессию.

🔴 **Для КАЖДОГО признака отбора спрашивать: в какую минуту он становится известен?**
Не «causal ли расчёт», а именно момент доступности. Признак, чьё подтверждение приходит
через `LEN×ТФ` минут, нельзя использовать для входа раньше этого срока — и проверять это
надо ДО замера, а не после красивых чисел.
