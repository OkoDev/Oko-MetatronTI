**Егор, 28.09.2026: «конфиг должен быть источником истинности! к этому уже приходили! механизмы
построения включения и выключения стратегий не должны в себе нести разрешений на торговлю/тень
и пр. всё только через конфиг, иначе каша».**

**Why:** за 26–28.09 один и тот же класс сломал пять механизмов, и каждый раз причина была в том,
что решение «торгует / не торгует» лежало НЕ в конфиге либо сразу в нескольких местах:

| что сломалось | где на самом деле принималось решение |
|---|---|
| гейт `wave_leg` радара молчал 2.5 мес | колонка не выбиралась в SQL лупа — конфиг был ни при чём |
| `atr_s2` не торговал НИ РАЗУ | `exchange_enabled: true`, но ветка висит на `tf == "4h"`, а сканер даёт 15m |
| `ds_advisor` не торгует с 13.08 | разрешение в политике, отказ — в пороге `min_sl_dist` реестра |
| `ote_nested` числился торгующим | выключен ключом `ote.vst_trading.enabled`, в политике остался `true` |
| `impulse_fib` окно фила | окно поиска в коде (`WAIT_BARS`), TTL живой заявки — в реестре |

Масштаб: **56** ключей `enabled`/`shadow` в config.yaml и **8** мест в коде, читающих
`exchange_enabled`. Плюс пороги реестра (`min_sl_dist`, `min_rr`, `entry_ttl_bars`), которые
де-факто могут выключить источник целиком, ничего не написав в лог.

**Контракт, к которому идём:**
1. **Один канонический ключ режима на источник** — `live | shadow | off`. Все прочие места
   его ЧИТАЮТ, ни одно не решает само.
2. **В коде не должно быть условий, которые де-факто выключают источник** (`tf == "4h"`,
   жёсткие стороны, вселенные). Такое условие либо приходит из конфига, либо источник обязан
   ГРОМКО писать отказ с причиной.
3. **Порог, способный обнулить поток, — тоже разрешение.** `min_sl_dist`, `min_rr`, TTL заявки
   должны либо иметь персональное значение источника, либо логировать отказы со счётчиком.
4. **Селф-тест при старте:** таблица «источник → режим по конфигу → достижим ли путь в коде →
   сделок за N суток → отказов по каждому гейту». Ноль сделок при режиме `live` = громкая тревога,
   а не тишина.

**🔴🔴 29.09: САМ КАНОНИЧЕСКИЙ КЛЮЧ НЕ РАБОТАЛ СУТКИ — три двери** (коммит `93daf45`):

1. **`mode: off` без кавычек = boolean False.** YAML 1.1 читает голое `off`/`on` как boolean.
   Резолвер делал `str(False or "")` → пустая строка → `declared=None`, и канон МОЛЧА терялся
   во **всех шести** выключенных источниках; разрешение держал только старый `exchange_enabled`.
   Контракт не действовал именно там, где выключает. Мина: `exchange_enabled: true` рядом
   с `mode: off` → источник торгует вопреки конфигу.
   🔑 Та же ловушка в `market_store.bot_htf` (голое `on` = True) — это КЛАСС, не случай.
   Лечение: кавычки в конфиге + `mode_of` принимает bool False как off с ГРОМКИМ предупреждением.
   `True` как live НЕ трактуется: непонятно, live или shadow, а это деньги.
2. **Источника нет в `source_policies` → считался `MODE_LIVE`.** Новый луп торговал бы реальными
   деньгами, не будучи ни строкой упомянут в конфиге. Теперь `off` + предупреждение. Безопасно:
   все 23 имени из `router.submit` описаны; отсутствующие 10 (`fvg_fill`, `wt_extreme`, `ote_zone`…)
   — имена сигналов, не источников роутера. Список торгующих до/после совпал.
3. **Конфиг недоступен → было «торгуем, раз не знаем».** Теперь `off`.

Проверка живёт в `tests/unit/test_source_mode_resolver.py` (13 тестов, два — против БОЕВОГО
config.yaml: ни одного boolean в `mode`; `mode` и `exchange_enabled` не расходятся). Прибор L12b
теперь сам называет источник с голым `off/on`.

**How to apply:** добавляя источник или гейт, спрашивать себя: «может ли это молча обнулить поток,
и увидит ли это конфиг?». Если решение принимается в коде — вынести в конфиг либо сделать отказ
видимым. **Любое YAML-значение, которое выглядит как слово-переключатель (`off`, `on`, `yes`, `no`),
писать В КАВЫЧКАХ** — иначе получишь boolean и молчаливую потерю смысла.

[[sources_audit_28sep_three_dead_gates]], [[feedback_selftest_every_strategy_loud]].

## 🔴 05.10: ПРОВЕРЯТЬ КОНФИГ ТОЛЬКО ЧЕРЕЗ `config_loader`, НЕ через `yaml.safe_load`

Я «нашёл баг»: `adaptive_weights` и `narrative` лежат в YAML под `sl_tp_engine` (отступ 2,
строки 1075/1080), а код читает их из `trading` → решил, что конфиг не управляет и нарратив
выключен. **Доложил Егору. Неверно.** Егор прислал скриншот живого TG-сигнала с блоком
«📖 Нарратив» — работает.

Причина ошибки: я читал **сырой** `yaml.safe_load(open('config.yaml'))`. А `config_loader.py:31`
делает `CONFIG-SLTP-BUG merge` (14.06.2026): все ключи `sl_tp_engine`, которых нет в `trading`,
копируются в `trading` через setdefault — чтобы ОБА пути работали. Проверка точных цепочек из
кода через loader: `trading.narrative.enabled = True`, `trading.adaptive_weights = {method: ema,
half_life: 50, …}`. Всё читается.

**Правило:** проверяя «видит ли код ключ», звать то же, что зовёт код:
```python
from core.infra.config_loader import config
config.get('trading.narrative.include_in_tg')     # точечный доступ
config.get('trading', {}).get('narrative', {})    # как в trading_intelligence.py
```
`yaml.safe_load` показывает ФАЙЛ, а не то, с чем работает бот. Это тот же класс, что
[[law_reproduce_live_config_first]]: сначала воспроизвести боевую конфигурацию, потом судить.
