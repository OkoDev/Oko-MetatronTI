# 🔴 НОВАЯ СЕКЦИЯ КОНФИГА АКТИВИРУЕТ СПЯЩИЕ КЛЮЧИ

**21.08.2026.** Создал `trading.sl_management`, потому что код её читал
(`trade_simulator.py:776-780`), а в конфиге её НЕ БЫЛО. Вписал туда
`max_rr: 3.0` и `max_rr_range: 2.5` с комментарием «прежний дефолт кода —
поведение не меняется».

**Поведение изменилось.** Раньше `.get(...)` не находил секцию и возвращал
запасные 3.0 для ЛЮБОГО режима. После моей правки для RANGE стало 2.5:

```
[DEV-64A] __SELFTEST__/USDT R:R cap → 2.5x (regime=RANGE)
CRITICAL SELFTEST FAIL [L12] Trade Lifecycle: OPEN-проверка: tp=112.5≠115
Бот не может стартовать — критические тесты провалены!
```

Бот падал каждые ~35 секунд, pm2 поднимал заново (`bot_pm2.js:15` пробрасывает
exit-код) — **74 рестарта, ~25 минут без торговли**. Поймано не мной, а вопросом
Егора «постоянно перезапускаются PM2 процессы или мне кажется?».

## 🔑 ПРАВИЛО
Ключ, которого нет в конфиге, — это НЕ «ключ со значением дефолта».
Это **другая ветка кода**: `if "max_rr_range" in cfg` может вообще не
существовать, и запасное значение одно на все случаи.

**Перед созданием секции:** прочитать, как код её берёт, и выписать, что вернётся
БЕЗ секции для каждого режима/ветки. Совпало — вписывать. Не совпало — не вписывать
вовсе, оставить только новый ключ, ради которого секция создавалась.

Итог: в секции остался ТОЛЬКО `rr_cap_exempt`, в файле стоит предупреждение
не добавлять туда `max_rr*`.

## 🔑 ВТОРОЕ: самотест поймал, а я — нет
Самотест L12 отработал ровно как задумано: не пустил сломанного бота в бой.
Дефект был не в нём. Дефект в том, что **я не запустил бота после правки конфига**
и ушёл дальше. Правка конфига = обязательный рестарт + проверка `SelfTest N/N`.
