**Что построено (Егор 30.09: «хаб строить»):** `scripts/cube_hub.py` (pm2 `cube-hub`, 127.0.0.1:8020, база
`oko_feed/cube.db`, токен `oko_feed/cube_hub.token` в .gitignore) + зеркало бота `core/context/cube_mirror.py`
(флаг `config.cube_hub.enabled: true`). Класс события — `bus_catalog.EVENT_CLASS` (state / fact / internal).
API: `GET /state[/sym]`, `/facts?since=&types=`, `/ws?types=`, `/stats`; `POST /publish` с токеном, Origin → 403.

**Ключевые решения:**
- синхронная шина остаётся в боте (бот = Sub-куб), хаб — реплика и ничего не считает;
- состояние = ВСЕ поля PairState: `get_full_state` — выборка без фандинга/OI/волн (класс «API-дырка»);
- круговой досыл 20 пар/тик: часть кода пишет поля пары напрямую мимо publish/update;
- EventBus наружу НЕ выставлять — это очередь повторного анализа (разбор ARCH-101).

**Замер шага 1 (30.09, все критерии ADR выполнены):** 12 777 стабильных полей на 300 парах — 0 расхождений;
задержка p95 состояние ~0.1 с, факт ~0.09 с; разрывов seq 0, выброшено 0; скан после включения медиана 226 с
(6 циклов) против 257 с до (66 циклов). `pm2 save` сделан.

читать по паре подряд бот→хаб→бот, поле считать только если у бота стабильно во всех чтениях.
