# 📋 БЭКЛОГ: алерты на сервер (решено 16.08.2026 — пока делаем клиентские)

**Сейчас (v1, клиентская):** разметка (уровни/трендовые/прямоугольники/фибо) хранится в
localStorage браузера (`oko_draw`), алерты проверяются в открытой вкладке монитора на тике цены
(раз в 3с) и дают звук + подсветку окна + ленту событий. Работает, пока вкладка открыта.

**Чего не хватает (v2, серверная):**
1. Таблица `drawings` в `subscriptions.db` (symbol, kind, price/точки, created_at, note) + CRUD
   в `web/structure_terminal.py`; клиент переезжает с localStorage на неё (миграция: при первом
   заходе залить существующий `oko_draw`).
2. Фоновый воркер (pm2, рядом с `structure-term`): bulk-тикер BingX отдаёт **все 550 монет одним
   запросом** (кэш 3с уже есть) → проверка касаний уровней стоит копейки, API не грузится.
3. Доставка в Telegram через готовый `oko_feed/alerts.py::send_tg(channel=...)`.
4. Дедуп + кулдаун на (символ, уровень, тип) — иначе на 550 монетах это спам за час
   (паттерн `signal_quality.dedup_minutes` в config).
5. **Shadow-журнал обязателен**: писать КАЖДОЕ срабатывание и что было через N баров, чтобы через
   неделю выкинуть типы алертов, которые ничего не предсказывают. Иначе получим лампочки
   [[feedback_verdict_protocol_egor]].

**Почему не сразу v2:** ценность алерта проверяется на своих же уровнях за пару дней; если типы
окажутся бесполезными, серверная инфраструктура будет выброшена вместе с ними.
