# 🔴 VERDICT_GATE МЁРТВ 4 МЕСЯЦА: str(enum) вместо enum.value (12.08.2026)

## Как нашли
Цепочка от починки прибора самодиагностики ([[cube_selftest_stub_lied_38_missing]]):
прибор врал про сферы 3/4 «не обучены» → оказалось обучены → вопрос «а влияют ли они
на решения?» → `trading.verdict_gate.enabled = true` → проверка, срабатывал ли гейт.

## 🔑 КОРЕНЬ (подтверждён живым логом)
`core/trading_intelligence.py`: в агрегатор передаётся
`direction=str(getattr(recommendation, "direction", "") or "")`.
`recommendation.direction` — это **enum** `SignalDirection`, и `str(enum)` даёт
`'SignalDirection.LONG'`, а не `'LONG'`.
`core/intelligence/verdict_aggregator.py` сравнивает строго `direction == "LONG"` / `"SHORT"`.
Совпадение невозможно → `is_counter=False`, `is_aligned=False`, все SMC-ветки мимо.

Живой лог после добавления диагностики GATE_EVAL:
```
GATE_EVAL exha_dir=BULLISH dir=SignalDirection.LONG block=False would=False reason=no_signal
```
Проверка: `str(SD.LONG)` = `'SignalDirection.LONG'`, `SD.LONG.value` = `'LONG'`.
**В ТОМ ЖЕ файле** (строка ~1970) используется правильный приём
`getattr(recommendation.direction, "value", str(recommendation.direction))` — в гейте забыли.

## Доказательства, что гейт не работал (три независимых)
1. **Логи**: за окно 08.07–12.08 (1.6 ГБ) — `DEV-146` встречается **0 раз**
   при 22 684 записях `wt_verdict=EXHAUSTION conf=0.80` (порог 0.65).
2. **БД**: на свежем окне 26.06–11.08 из 576 EXHAUSTION-сигналов **80 (13.9%)**
   подпадали под условие блокировки, но лежат ЗАРЕГИСТРИРОВАННЫМИ.
   (Первый замер дал 25% — но `LIMIT` без `ORDER BY` взял старые сделки; окно исправлено.)
3. **Прямой прогон** `aggregate_verdicts` с реальными значениями: при `EXHAUSTION conf=0.80`
   и `exha_dir=NEUTRAL` блокирует; при живом `dir='SignalDirection.LONG'` — нет.

`verdict_gate.enabled: true` стоит в конфиге минимум с 06.04.2026.

## SMC-плечо мертво ВТОРИЧНО — порогом
Даже после починки enum SMC блокировать не сможет:
`smc_block_confidence = 0.65`, а `confidence` = `p_win` модели.
Замер на **7719** исторических снимках (обучение из той же БД, AUC 0.181):
```
min=0.218  p50=0.398  p95=0.512  p99=0.525  max=0.552   →  conf>=0.65: 0 (0.00%)
метки: STRONG_BEAR_ZONE 2494 | WEAK_ZONE 3806 | NEUTRAL 1419
```
Метка STRONG_* выдаётся часто (32%), но порог по confidence недостижим НИКОГДА.
Модель с win_rate 37% физически не выдаёт вероятностей выше ~0.55.
Независимое подтверждение из живой шины (250 пар): `smc_confidence` ≡ 0.500.

## ЗАКОН
**Enum, попадающий в сравнение со строкой, — молчаливый мёртвый путь.**
`str(enum)` не равно значению. Ловится не код-ревью, а логированием ИСХОДА
решения, а не только факта срабатывания: гейт логировал только BLOCK, поэтому
«ни одного BLOCK» и «гейт сломан» были неразличимы 4 месяца.
Родственно [[bug_rr_gate_killed_tp1r_edge]] (луп ОБЯЗАН логировать отказ с причиной).

то есть «режет худшее из плохого».
