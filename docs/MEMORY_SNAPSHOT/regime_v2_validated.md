**ВЕРДИКТ: v2 информативнее v1 — активировать (`use_v2=true`) через A/B на гейтах.**

**Разброс avgR между режимами (больше = лучше разделяет edge):** v1=**0.552** vs v2=**0.798**.

| | RANGE | TREND_UP | TREND_DOWN | HIGH_VOL |
|---|---|---|---|---|

**Ключевое:**
1. **v1 валит 47% в RANGE** (мислейбл, [[arch124_regime_audit]] подтверждён). v2 распределяет (RANGE 22%, видит тренды).
2. **v1 не различает RANGE(0.971)≈TREND_UP(0.983)** — метка бесполезна. v2 чётко: TREND_UP лучший, HIGH_VOL худший.
3. **Расхождение v1↔v2 = 67%** (на тех же сделках!).
4. ⚠️ Честность: высокий avgR (0.7-0.97) был от ВЫБОРКИ (недавние сделки лучше), НЕ от режима — v1 на той же выборке тоже высок. Преимущество v2 = РАЗДЕЛЕНИЕ, не абсолют.

**🔑 ДАВНИЙ ВОПРОС РАЗРЕШЁН:** RANGE-сделки ПРИБЫЛЬНЫ (v1 avgR 0.971!) → гейты, блокировавшие RANGE, **резали прибыль**. Проблема не «RANGE плохой», а v1 туда сваливал всё, и гейт на метке отсекал хорошее. v2 + прямые htf_dir фильтры (вместо regime-гейта) — путь.

## HIGH_VOL — разбор (вопрос юзера 11.06)
- **Определение:** `_ATR_HIGH_VOL_MULT=1.8` — ATR > 1.8×median_ATR (или range-spike >3×). **По ВОЛАТИЛЬНОСТИ диапазона, НЕ по объёму!**
- **Влияет — ГЕЙТ (блок входов):** `scan_loop:235` WL-breach пропуск; `monitoring:72` hidden-div отклонение («тренды рвутся»); SHORT в HIGH_VOL avgR −0.77. v2 HIGH_VOL avgR 0.176 (худший) → гейт оправдан.
- **🎯 НЕИСПОЛЬЗОВАННЫЙ РЫЧАГ:** объём ПИШЕМ (`features["volume_24h"]`, `pivot_volume_z`), но HIGH_VOL его НЕ юзает (чисто ATR). Ирония: crypto_**VOLUME**_bot, а «объёмный» режим = волатильность. Идея: объёмный режим (volume spike) отдельно ИЛИ HIGH_VOL = волатильность+объём (импульс vs шум-вынос).
