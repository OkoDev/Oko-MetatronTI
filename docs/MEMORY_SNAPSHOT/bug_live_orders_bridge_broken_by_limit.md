# 🔴 ЛИМИТНЫЙ ВХОД РВАЛ МОСТ live_orders → simulated_trades (22.08.2026)

Поймал Егор скриншотом дашборда: четыре открытые позиции в плюсе, у всех
`SIGNAL = unknown`, `TF = 15m`, а SL/TP — прочерки. В БД при этом всё правильно:
`signal_type='impulse_fib'`, статус OPEN, филл состоялся, `exchange_order_id` есть.

## Механизм
1. Запись в `live_orders` создаётся в момент ВЫСТАВЛЕНИЯ заявки.
2. `PositionManager.sync_with_exchange` сверяет OPEN-записи с позициями биржи и
   закрывает те, которых там нет: «позиция закрылась пока бот не работал».
3. Лимитка до фила позицией НЕ ЯВЛЯЕТСЯ → первый же sync помечал запись CLOSED.
4. Заявка исполнялась, позиция появлялась — но запись обратно не открывалась.
   **Мост рвался навсегда.**
5. `/api/live` матчит позицию с сделкой JOIN'ом через `live_orders` при
   `lo.status='OPEN'` → матча нет → `signal_type=None`, SL/TP пустые.
6. Фронт брал `tf: p.tsl_tf || "15m"`, а `tsl_tf` заполняется ТОЛЬКО при активном
   трейлинге — у impulse_fib он выключен по конструкции → печатался чужой ТФ.

🔑 Тот же класс, что [[phantom_trades_corrupt_forward]]: **статус по ТИПУ ОРДЕРА**.
Учёт был рассчитан на MARKET-вход, где ордер и позиция появляются одновременно.

## Что НЕ пострадало
Торговля. SL/TP ведёт `trade_simulator` по `simulated_trades`, лайфцикл заявок —
`radar_armed._check_pending`. От `live_orders` зависят только `order_reconciler`
(считает количество для лога) и дашборд. Ущерб чисто ПРИБОРНЫЙ — но по законам
проекта прибор, который врёт о том, какая стратегия в рынке, чинится немедленно.

## Фикс
- `sync_with_exchange`: запись НЕ закрывается, если её сделка в `PENDING_ENTRY`
  (позиции нет ПО КОНСТРУКЦИИ, а не потому что закрылась);
- `_reopen_filled`: мост возвращается, если позиция реально есть на бирже И
  `simulated_trades.status='OPEN'` — строгие условия, чтобы не воскресить закрытое;
- ТФ отдаётся из реестра `source_registry.tf_for(signal_type)`, фронт: `p.tf || p.tsl_tf`.

**Тест на синтетике 5/5**, включая негативные: реально закрытая → CLOSED,
сделка со статусом SL не воскресает, живая позиция не трогается.
**В бою:** `reopened=4, pending=1, closed=0`, SelfTest 12/12, API отдаёт
`signal='impulse_fib' tf='1h'` и настоящие SL/TP.

## Урок
Любой учёт, где «ордер» и «позиция» — одно и то же, ломается о лимитный вход.
При добавлении механики с LIMIT проверять ВСЕ места, где статус выводится из
наличия позиции на бирже.
