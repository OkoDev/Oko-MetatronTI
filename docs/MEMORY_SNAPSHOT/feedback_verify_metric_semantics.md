**Правило:** Прежде чем публиковать вывод вида «N% сделок плохие по метрике X» — проверить **семантику X** в коде:
1. Grep где записывается `field_name` — найти точку записи в features_json/БД
2. Прочитать что именно туда пишется (какой источник данных, в какой момент)
3. Сравнить с моей интерпретацией
4. Если не совпадает — переформулировать вывод

**Why:** За 27.04 поймал 6 случаев когда метрика измеряла одно, а я интерпретировал другое:
1. **H1 «poздние входы pivot_reversal»** — `distance_to_pivot_pct` это distance до удалённого pivot, не proximity-at-entry. Детектор использует ≤0.5% gate и работает корректно.
2. **B5 «wt1=−15 вместо <−60»** — wt1_value на 15m, а wt_b детектор работает на 1h. Сравнивал разные TF.
3. **B6 «distance_to_pivot 4.32%»** — это TP-distance, не entry-trigger pivot.
4. **TSL fate «70% активаций в SL»** — VST использует STOP_MARKET, биржа закрывает как `status='SL'`. 32% на самом деле скрытые TSL exits.
5. **R_multiple 65.6% аномалий** — мой audit-скрипт неправильно учитывал SHORT direction и tp1_fix константу из config.
6. **DUAL_TSL leak/Phase 1 cutoff** — использовал cutoff 12:00 UTC, реальный restart 17:30 UTC. Все «leaks» — артефакт окна между config edit и реальным restart.

В каждом случае создавал тревогу, рекомендовал фиксы — параллельный агент или сам пользователь находили мою ошибку. Это **подрывает доверие к моим выводам** и тратит время на разбор false positives.

**How to apply:** Для каждой новой метрики или гипотезы:
- НЕ публиковать «N% сделок имеют X» без grep `field_name` в коде
- НЕ предлагать фикс без понимания что метрика измеряет
- Если выборка post-restart — проверить ТОЧНОЕ время restart через grep лога, не догадываться
- Если формула проверки — должна совпадать байт-в-байт с формулой записи в коде
- Если уверенности нет — явно говорить «не проверил семантику, нужно проверить» вместо публикации вывода

**Триггер:** любое утверждение со словами «N% сделок», «метрика показывает», «доля», «pre vs post», «leak», «аномалия». Прежде чем — grep + read code, потом вывод.
