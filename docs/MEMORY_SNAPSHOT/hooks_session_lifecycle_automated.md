# 🪝 ХУКИ ЖИЗНЕННОГО ЦИКЛА — ручные правила стали автоматическими (12.08.2026)

Три правила из `.claude/CLAUDE.md` требовали дисциплины и потому **забывались**:
запись статуса до компакта, чеклист завершения сессии, прогон линтеров после правки
памяти/vault. Переведены в хуки — теперь срабатывают без меня.

## Что настроено (`.claude/settings.json` → `hooks`)

| событие | matcher | что делает | тайминг |
|---|---|---|---|
| SessionStart | `*` | `tools/context_brief.py` (было раньше) | — |
| Stop | `*` | `scripts/check_tasks.py` (было раньше) | — |
| **PreCompact** | `*` | вставляет маркер «⏸️ КОМПАКТ КОНТЕКСТА» в `memory/current_state.md` + `additionalContext` мне | мгновенно |
| **SessionEnd** | `*` | называет НЕ обновлённые current_state / whats-next / START (порог 6ч) | мгновенно |
| **PostToolUse** | `Write\|Edit` | по ПУТИ: `memory/` → `memory_lint.py` (444 мс), `obsidian/` → `validate_obsidian_vault.py` (4.6 с) | **`async: true`** |

Вся логика в одном файле `tools/session_hooks.py` (подкоманды `precompact|sessionend|postwrite`).

## 🔴 ГЛАВНАЯ ЛОВУШКА: `jq` на этой машине НЕ УСТАНОВЛЕН

Канонический паттерн хуков из документации —
`jq -r '.tool_input.file_path' | { read -r f; …; }` — **молча не сработал бы**:
команда упала бы с `jq: command not found`, а хук с `|| true` проглотил бы ошибку.
Хук, который ничего не делает, хуже отсутствующего — он создаёт ложную уверенность.

**Решение:** stdin-JSON парсится в самом Python (`_read_stdin()`), фильтрация пути
внутри `postwrite()`. Никаких shell-утилит в команде.

**ЗАКОН: пайп-тест обязателен ДО записи в settings.json.**
Синтезировать payload и прогнать команду руками:
```
echo '{"tool_name":"Write","tool_input":{"file_path":"<реальный файл>"}}' | <команда>
```
Именно пайп-тест поймал отсутствие jq. И он же поймал, что валидатор vault идёт
4.6 с — синхронный хук вешал бы каждую правку, отсюда `async: true`.

## 🔴 ЛОВУШКА ПАРАЛЛЕЛЬНОЙ РАБОТЫ: порядок в DISCUSSION.md ≠ время (13.08)

Stop-хук `scripts/check_tasks.py` считает «отвечено» по **ПОЗИЦИИ** в файле
(`меньший idx = новее`), а не по дате в заголовке. Конвенция «новые записи — сверху»
это обычно обеспечивает — но ломается, когда **два агента пишут параллельно**.

Случай: DS добавил запись 01:35 в самый верх, пока шёл мой ночной прогон. Я позже
вставил ответ 07:40 перед своей же записью 05:00 — то есть **ниже** записи DS.
Хук честно рапортовал «нет ответа», хотя ответ был написан и содержателен.
Два прогона хука подряд выдали одно и то же — это и выдало, что дело не в содержании.

**Диагностика:** не спорить с прибором, а распечатать, что он парсит:
```python
secs = re.split(r'(?=^### \[)', content, flags=re.M)   # как в хуке
# → [1] DS 01:35, [2] Даат 07:40  ← порядок нарушен
```
**Фикс:** переставить свою запись ВЫШЕ чужой (порядок = хронология), после чего хук
отдаёт `{"decision": "approve", "reason": "📋 DISCUSSION чист"}`.

**ПРАВИЛО: при работе параллельно с DS свою запись вставлять В САМЫЙ ВЕРХ файла,
а не «перед своей прошлой».** Иначе ответ существует, но не засчитывается.
