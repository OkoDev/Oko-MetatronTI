# 🜂 МЕТОД ЕГОРА — двухмасштабный цикл сделки (04.07.2026, разбор ZEC вживую на TW)

**Формула (полный жизненный цикл):**
```
1. СТОРОНА    = позиция в БОЛЬШОЙ структуре (пик→SHORT / дно→LONG) + позиционирование толпы
               (long/short ratio: толпа в шортах у пика = топливо сверху → сначала свип, потом слом)
2. ТРИГГЕР    = len5 CHoCH в сторону ожидания (внутренняя структура ломается ПЕРВОЙ)
3. ВХОД       = откат после len5-слома (ретест/OTE), тугой стоп за локальный экстремум (~3%)
4. len50 CHoCH = ПОДТВЕРЖДЕНИЕ по ходу (+6% форы к этому моменту):
               SL→БУ + ДОБОР на ретесте сломанного уровня (полный размер на оплаченном риске)
5. ЦЕЛИ       = OTE СЛОМАННОГО большого импульса: 0.5 → 0.62 → 0.705 (там часто имбаланс/FVG);
               частички по целям, остаток на трейле
```

**🔴 ГЛАВНОЕ (слова Егора): «стоп короткий, цель огромная, и на пути открываем на откатах
сделки в ОДНОМ направлении».** Не одна сделка — СЕРИЯ входов на каждом откате внутри
импульса, все в направлении импульса, каждый с тугим стопом (~3%), общая цель = OTE
большого. Асимметрия × серия = экономика метода. Бот обязан знать «в каком я импульсе» —
и пока структура импульса не сломана, каждый откат = вход по направлению (добор/новая),
а НЕ контр-сигнал.

**Ключевые принципы:**
- len50 и len5 ОБА валидны — это НЕ «слепой vs зрячий», а РАЗНЫЙ МАСШТАБ: len50 = значимые
  сломы (направление/подтверждение), len5 = внутренняя структура (точки входа). Работают ВМЕСТЕ.
- Ждать len50 для входа = заплатить ~6% движения за уверенность и покупать дороже. Вход по len5
  платит ~3% стопа за 6% форы (асимметрия). len50 — точка ДОБОРА, не входа.
- Фибо-сетка ЕДИНАЯ и непрерывная: … −2, −1.5, −1, −0.62, 0, 0.5, 0.62, 0.705, 1 … — НЕ
  «retracement+extension», а одна шкала одного импульса, продолженная в минус.
- Сетки ВЛОЖЕНЫ каскадом: −2/−1 одной ноги ложится на 0.5/0.618 другой = конфлюэнция; вход
  только в совпадении уровней РАЗНЫХ сеток (одиночный уровень не значит ничего).
- «Первая фибо после слома структуры — цель отката в OTE предыдущего импульса (−2), откуда
  разворот» (слова Егора). Симметрично в ОБЕ стороны.

подтвердил, плато 27/27). **НО ВСЁ ФАЛЬШИВО:** вход = w3 (BOS) на баре пробоя, а слом опирается на
свинги, которые `_swings_luxalgo` подтверждает лишь через `length` баров ПОСЛЕ экстремума → в
реальном времени на баре входа слом ЕЩЁ НЕ НАПЕЧАТАН. Тест `lookahead_true.py`: обрезал df до
entry_ts → **16/19 сетапов ИСЧЕЗАЮТ** point-in-time. ЧЕСТНЫЙ пересчёт `test_v2_mtf_honest.py`
(per-setup передетект, вход по цене момента подтверждения): 29–71% «сетапов» = фантомы; net
переключает ЗНАК по задержке входа lag (+0.62% при lag3 → −0.34% lag5 → −0.18% lag10), OOS 2/3

detect_structure_breaks недостаточен — нужен end-to-end point-in-time сетапа. Плато по ПАРАМЕТРАМ
детектора не ловит дыру во ВРЕМЕНИ входа. [[oko-suite-trend-wt-validated]] (класс 1 look-ahead —
слом по концу истории — тот же корень). [[principle-measure-pct-not-r-law]].

**Корень провала оцифровки:** машина ловит «свежий слом волна3 = вход» = момент, невидимый live.
Живой метод Егора входит на ОТКАТЕ (волна2) ПОСЛЕ уже подтверждённого слома — другой триггер.
Волна-2-вход машина не тянет как автоторговлю (−0.70% нож), это эдж ЧУТЬЯ (глаз). Значит корректный
путь = decision-support (бот подсвечивает «волна1 старшего готова, жди откат»), не автоматический
вход на BOS.

**🔑🔑 НАХОДКА 05.07 (Егор навёл: «_swings модифицировали чтобы не ждать length, детектили в чарт-
билдере и сверяли глазами»):** method_v2_mtf был ДВОЙНОЙ ошибкой — (1) ДУБЛЬ детектора на голом
`detect_structure_breaks` (ждёт `idx+length` активации свинга, smc_engine.py:124-127) вместо
переиспользования provisional-движка; (2) вход на BOS/волна3 вместо отката. Правильный движок УЖЕ
СУЩЕСТВУЕТ: **`append_provisional_leg`** (smc_engine.py:863) дорисовывает текущую формирующуюся ногу
как неподтверждённый pivot = «то что трейдер рисует глазом, не ждёт индикатора» (решает
zigzag_lag_live_critical, XLM 1h воспроизвёл ручную SHORT-OTE до 6 фибо). **`ote_retest_setups(
provisional=True)`** (smc_engine.py:897) = ГОТОВЫЙ метод: слом CHoCH → OTE → **РЕТЕСТ (первый бар
отката в OTE) = ВХОД** → стоп за 1.0 импульса. [[principle-reuse-not-duplication]] — method_v2
надо ВЫБРОСИТЬ, мерить этот движок.

**⚠️ provisional активен ТОЛЬКО на КРАЕ df** (на полном историч-df последняя нога подтверждена,
дорисовывать нечего → provisional=off≡on). Значит честный бэктест = **point-in-time скользящим
окном** (`scripts/test_ote_retest_honest.py`): каждый срез df[:T] = живой край, provisional дорисует
текущую ногу, вход при свежем ретесте по цене момента. **BASELINE БЕЗ СТОРОНЫ (12 симв вкл. альты
LUNA/PEPE/DOGE, 544 сд, R-цели 2/4/6R): ALL −0.76% WR34%, WF OOS −1.88%, деградация 2024→26.**
Голый вход-на-откате = устойчивый минус на масштабе → подтверждает: без СТОРОНЫ = шум («бот не
знает где он»). Егор (05.07) выбрал направление **A: добавить СТОРОНУ** — HTF-gate 4h
`structure_trend`==направление входа (флаг `--side 1`, предпосчёт 4h по барам). A/B изолирует
вклад стороны (те же R-цели). Недостаёт ещё: толпа/funding/OI — их в OHLCV-историчке НЕТ (только
live-радар) → полный метод историч-бэктестом невоспроизводим by design, часть эджа на живом крае
(SHADOW/forward).
