# 🔴 ONCHAIN: В ШИНУ НЕ ИДЁТ — НЕТ НИ СИГНАЛА, НИ КАЧЕСТВА (02.09.2026, ARCH-129.3)

Последний хвост ARCH-129. Сначала инвентаризация и оценка полезности, потом инфраструктура —
после двух отрицательных подряд строить вслепую нельзя.

## Что в `onchain_events` (21 274 строки, 2026-07-03 → сегодня, живое)

| тип | источник | строк | что это |
|---|---|---|---|
| `btc_outflow` / `btc_inflow` | mempool.space | 20 151 | движение BTC на/с горячего кошелька Binance |
| `oi_spike` | binance_oi | 1 123 | всплески OI |

## Сигнала нет

Нетто-флоу дня (отток − приток, после дедупликации по txid) → доходность BTC
следующего дня. **51 день пересечения** (цены в кэше до 2026-08-23), n=50 пар:

| срез | n | ср. доходность след. дня |
|---|---|---|
| отток > медианы (накопление, «бычье») | 25 | **+0.458%** |
| отток < медианы (приток, «медвежье») | 25 | **+0.452%** |
| **разница** | | **+0.006 п.п.** |

Корреляция r = **−0.261** — слабая, и ЗНАК ПРОТИВ канона (больше оттока → хуже).
Крайние квинтили тоже наоборот: сильный приток +0.804%, сильный отток +0.181%.
При n=50 такая r не значима.

## 🔴 Три дефекта данных (чинить до любого использования)

1. **48.5% ДУБЛЕЙ**: 20 151 событие против 10 379 уникальных txid. Одна транзакция
   пишется несколько раз с разным `ts`, а PK = (ts, kind, symbol, amount_usd) дубль
   пропускает.
2. **`amount_usd` содержит БИТКОЙНЫ, а не доллары**: значения 5.00…7653 при цене BTC
   ~78 800. Третья за сессию ловушка единиц после фандинга и OI.
3. **`symbol` у `oi_spike` сломан**: вместо тикера записана строка
   `'LINK -0.59%/10m'`, `'SOL +0.80%/10m'` — отсюда «691 символ» вместо ~30.
   Поле `raw` при этом пустое.

Плюс: BTC-флоу **не per-pair** — это один глобальный ряд, место ему в `MarketState`,
а не в `PairState`. А `oi_spike` дублирует то, что уже есть в `radar_state`
(`oi_d5/d15`) и уже доведено до шины.

## Вердикт

**В шину не тащим.** Порядок обратный: сначала починить сборщик (дедуп по txid,
переименовать поле в `amount_btc`, чинить `symbol`), накопить окно длиннее 51 дня,
измерить снова. Публиковать в Куб данные с половиной дублей и неверными единицами —
значит переносить дефект вглубь системы.

## НЕ проверено

Внутридневной горизонт (мерил день→день) · крупные транзакции отдельно от мелких ·
связь флоу с альтами, а не с BTC · окно длиннее 51 дня (его физически нет).
