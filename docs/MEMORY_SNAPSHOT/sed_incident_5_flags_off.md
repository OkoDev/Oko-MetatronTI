# 🔴🔴 SED-ИНЦИДЕНТ 16.07: пять флагов выключены одной правкой

## Что произошло
Коммит `4bbac5b` «feat(net): прокси = ручной вкл/выкл флаг» правил `proxy_pool.enabled`
через `sed` по шаблону `enabled:` — и задел **пять** посторонних блоков `true → false`.
В теле коммита признано частично: *«(sed задел sideways_mode.enabled — восстановлен;
**аудит всех enabled-флагов зелёный**.)»* — аудит пропустил три из пяти.

| `market_ws` | ❌ выключен, но **де-факто безвреден**: `performance.ws_enabled` уже был `false` до sed (DEV-230, REST-only курс) — случайное выключение совпало с намеренным решением |

## Ответ на вопрос из handoff
«`event_bus.enabled=false` — проверить, осознанно ли» → **НЕ осознанно.**
Событийная шина работала в production с 27.04 (`docs/SIGNAL_BUS_CUBE_MAP.md:496`:
«`shadow: false` ✅ production с 27.04»), выключена случайно 16.07.
Цена: 2 из 21 рёбер Куба (`E_EB_FIRE`, `E_DET_EB`) и весь реактивный Full CALL —
внеочередной `analyze_symbol()` по событию (аномалия объёма, экстремум фондирования,
WT-конфлюэнция, смены тренда 15m/1h/4h/1d) вместо ожидания планового скана.
Все `publish()` из `scan_loop` эти 27 дней создавали таск, который сразу выходил
по `if not self.enabled: return`.

## 🔑 ЗАКОН
**Массовая правка конфига по шаблону (`sed`) требует ДИФФА ПО ЗНАЧЕНИЯМ, а не
самоотчёта «аудит зелёный».** Проверка: распарсить YAML до и после, сравнить все
пути `*.enabled` — 10 строк кода, ловит весь класс:
```python
before=flags(load('<ref~1>')); after=flags(load('<ref>'))
[k for k,v in before.items() if v is True and after.get(k) is False]
```
Родственно [[bug_source_policies_deadpath_router_off]] («config ≠ поведение») и
[[verdict_gate_dead_enum_str]] («логировать ИСХОД, а не срабатывание»): все три —
один класс «переключатель есть, поведения нет», и все три жили месяцами.

## 🛠️ ИНСТРУМЕНТ: `tools/config_audit.py` (и урок на нём же)
Ищет два перекоса: **СИРОТА** (ключ в config.yaml, никто не читает) и
**ПРИЗРАК** (код читает, в config.yaml нет → молча берётся дефолт).

⚠️ Первая версия судила ПО ТЕКСТУ и дала 13 сирот + 51 призрак — **почти все ложные**:
`ConfigProxy` маппит поддеревья на pydantic-модель, поэтому `sl_tp_engine.*` читается
как `trading.*`. Добавлена проверка РАНТАЙМОМ → сироты **13 → 0**, призраки **51 → 24**.
Причём фильтр сперва не сработал: скрипт в `tools/` не видел `core/`, а `except: _live=None`
проглатывал это МОЛЧА. Инструмент против молчаливых сбоев содержал молчаливый сбой —
пятая итерация того же класса за сессию. Теперь путь чинится, а отказ печатается громко.

**ЗАКОН (повтор третий раз за сессию): судить по РАНТАЙМУ, а не по тексту.**

## Что нашёл аудит (после починки)
- 🟡 **`trading.min_rr_ratio` в config.yaml НЕТ** — RR-гейт (`core/trading/gates/rr_filter.py:41`)
  работает на **зашитом 2.0**. Комментарий в `ote_signal_generator.py:108` уверяет
  «ДОЛЖНО совпадать с config.yaml → trading.min_rr_ratio (2.0)» — ключа там нет.
  Живые источники спасает `min_rr_per_strategy` (ote_nested 0.9 · oko_ote 0.1 · radar 0.5 ·
  rangefade/rangefade4h/bigflush15 0.95). **Риск: любой НОВЫЙ источник получит 2.0 молча** —
  ровно сценарий [[bug_rr_gate_killed_tp1r_edge]], который уже стоил суток без сделок.
- 🟡 **Меню риска показывает выдуманные числа**: `bot/menus/risk.py` читает
  `trading.risk_per_trade_pct` / `sl_pct` / `tp_pct` — **ни одного нет в config.yaml**,
  печатаются дефолты 1.0% / 2.0% / 4.0%. Реальный риск живёт в `trading.risk_pct`
  и в per-strategy `risk_pct: 0.5`. UI врёт так же, как врал дашборд с фантомами.
- 🟡 `sl_tp_engine.min_sl_dist_pct = 0.5` — **дубль-сирота**: работает `trading.min_sl_dist_pct = 0.25`.
  Правка «0.5» не изменит ничего.
