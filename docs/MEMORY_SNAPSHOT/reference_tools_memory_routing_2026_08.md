# 🔧 ВНЕШНИЕ ИНСТРУМЕНТЫ: оценка под наш проект (12.08.2026)

Егор прислал 4 ссылки в контексте «улучшить память агента». Прочитаны, оценены
под конкретную боль проекта. **Ничего не установлено** — решение за Егором.

| инструмент | вердикт | почему |
|---|---|---|
| **OmniRoute** | 🟢 попробовать | чинит РЕАЛЬНУЮ боль роя |
| **claude-mem** | 🟡 осторожно | дополняет, но риск дублирования и heuristic recall |
| **claude-code-setup** | 🟡 безопасно глянуть | read-only, может найти пробел в хуках |
| **headroom-desktop** | 🔴 не подходит | macOS 14 + Apple Silicon, у нас Windows 11 |

## OmniRoute (`diegosouzapw/OmniRoute`)
AI-gateway: 338+ провайдеров через один OpenAI-совместимый `/v1` на `localhost:20128`,
**auto-fallback** при отказе, 19 стратегий роутинга, 90+ бесплатных провайдеров,
~1.5 млрд бесплатных токенов/мес. `npm i -g omniroute`.

**Наша боль, которую он чинит:** рой стабильно даёт 5 из 7 — `github_models` 410
(retirement brownout), `sambanova` timeout, `openrouter` 404 на reasoning-модель,
DeepSeek иногда пустой ответ. `tools/llm_ask.py` имеет самописный fallback, но
провайдеры всё равно сыпятся → рой теряет независимые мнения.
**⚠️ Компрессию токенов (15-95%) ОТКЛЮЧАТЬ**: наши брифы — таблицы чисел, искажение
данных = ложный вердикт. Проверяемо за один прогон роя (7/7 против 5/7).

## ✅ OmniRoute ВНЕДРЁН (12.08, решение Егора) — работает
```
npm i -g omniroute                          → omniroute@3.8.49
node <npm-prefix>/node_modules/omniroute/bin/omniroute.mjs serve   → :20128, HTTP 200
```
На Windows команда `omniroute` не попадает в PATH bash — звать через `node <path>/bin/omniroute.mjs`.
Подхватывает `.env` проекта (видит наши ключи) + свои бесплатные провайдеры.

**Правки в коде:**
- `tools/llm_ask.py`: провайдер `omniroute` (`auto/best-chat`, reasoning → `auto/best-reasoning`),
  base_url `http://127.0.0.1:20128/v1`, множество `KEYLESS` (ключ не нужен),
  `has_key()` возвращает True для KEYLESS, в запрос добавлен **`stream=False`**
  (по умолчанию шлюз отдаёт SSE, и OpenAI-SDK на нём падает).
- `tools/team_ask.py`: `omniroute` добавлен в `ALL_PROVIDERS`.

**Результат прогона роя: 6/8 против прежних 5/7.** Ответ omniroute на тесте с таблицей
чисел — ТОЧНЫЙ: медиана +3.74% ✓, отношение WR дал дробью 30/13 ≈ 2.31 (единственный,
кто не округлил) ✓, 2 перелома ✓, плюс сам отметил неоднозначность вопроса.
**Компрессия числа НЕ исказила** (`compression status` = strategy standard, settings {};
`compression configure` требует авторизации — 401, но дефолт безопасен).

**Остаточная проблема:** `github_models` отдаёт 410 `github_models_retirement_brownout`
(провайдер закрывается — это не временный сбой), `sambanova` 429 при нагрузке.
Кандидат на чистку: убрать `github_models` из `ALL_PROVIDERS`.

### 🔴 ПРОВЕРКА 13.08 (вопрос Егора «рой корректно работает через OmniRoute?»)

**Рой НЕ ходит ЧЕРЕЗ OmniRoute** — и это верно по конструкции. `ALL_PROVIDERS`
(`team_ask.py:59`) = 9 имён, `omniroute` — ОДНО из них; остальные 8 идут напрямую
к своим API по своим ключам. Шлюз = один дополнительный участник, не маршрутизатор роя.

**Что проверено запуском:**
- ✅ **Компрессия ВЫКЛЮЧЕНА** — заголовок `x-omniroute-compression: off; source=off`.
  Числа в брифах не искажаются (это была главная опасность).
- 🔴 **`auto/*` — ЛОТЕРЕЯ, а не модель.** 6 одинаковых запросов дали ТРИ разные модели:
  `big-pickle` (provider=oc) → `felo-chat` ×5 → `hy3-free`. Голос НЕвоспроизводим.
- 🔴 **`auto/best-reasoning` = `auto/best-chat`** — оба резолвятся в `felo-chat`.
  Настройка reasoning для omniroute в `llm_ask.py` **фиктивна**.
- ⚠️ На прямой вопрос модель ответила «I am Claude, an AI model from Anthropic».
  Самоидентификация ненадёжна, но если правда — голос **дублирует меня**, а не добавляет
  независимости. Ценность роя именно в разнообразии источников.
- **Из 115 моделей шлюза отвечают ЧЕТЫРЕ**: `oc/nemotron-3-ultra-free`, `oc/hy3-free`,
  `felo/felo-chat`, `felo/felo-search`. Остальные: все 26 `tllm/*` → **403 blocked by Vercel**,
  28 `aug/*` → 502, `pepper` → 502, `ddgw` → 418, `oc/north-mini-code-free` → 401,
  `mcode/mimo-auto` → 400, три `oc/*` → 429.

**Починено:** `llm_ask.py` после ответа печатает `[llm_ask] omniroute: auto/best-chat →
РЕАЛЬНО <модель>` в stderr — иначе в протоколе роя не видно, кто голосовал.
Проверено боевым вызовом.

**Точность на числовом тесте** (WR 60→26, медианы −5.95/+2.25, 2 перелома):
omniroute дал `34 / 2.64 / 2` — п.1 и п.3 верно, п.2 инвертировал отношение
(2.64 вместо 0.38; cerebras/groq/openrouter дали 0.38). **Mistral был хуже** — `32`
вместо 34, прямая арифметическая ошибка.

**Прогон 13.08: 5/8** (не 6/8) — добавился отказ `gemini` 429 RESOURCE_EXHAUSTED (квота).

### 🟢 РОЙ 5/8 → 7/7 (13.08): запасной вход + защита от пустого голоса

Егор: «подключай все LLM по максимуму, одна модель вместо роя не устроит».
Найдено и починено ДВА дефекта состава:

1. **Рой терял голоса при 429.** `call_with_fallback` в `llm_ask.py` существует, но рой его
   НЕ звал — только `call_provider` напрямую (`team_ask.py:265,307,472`). gemini (429 квота)
   и sambanova (429 high demand) просто выпадали. Добавлен `OMNIROUTE_SPARE`: при 429/503
   голос берётся через локальный шлюз **с ФИКСИРОВАННОЙ моделью** (не `auto/*` — та
   подставляет случайную). В отчёте видно замену: `gemini-3.5-flash → oc/nemotron-3-ultra-free`.
2. **🔴 ПУСТОЙ ГОЛОС СЧИТАЛСЯ КАК ✅.** `oc/hy3-free` и `felo/*` на коротком тесте («60−26»)
   отвечают верно, а на боевом промпте роя возвращают **«....» / 3 символа при HTTP 200**.
   Такой голос ХУЖЕ отказа: он врёт статистикой состава и льёт пустоту в синтез.
   Добавлен порог `SPARE_MIN_CHARS = 200` — короче считается провалом.
   **Урок того же класса, что «прибор врёт»: HTTP 200 ≠ ответ.**

**Результат:** 7/7, минимальный голос 1381 симв. (был 3). `github_models` убран из
`ALL_PROVIDERS` — 410 retirement, гарантированный ❌ в каждом прогоне.

### 🟢🟢 РОЙ 5→8 ПОЛЕЗНЫХ ГОЛОСОВ БЕЗ ЕДИНОГО НОВОГО КЛЮЧА (13.08)

Задача Егора: «нам нужны все самые сильные и **без подписок** для сохранения бюджета».
Решение нашлось не в шлюзе, а в **уже имеющемся ключе OpenRouter**: там 16 моделей `:free`.

**Что сделано:**

2. **+3 НОВЫХ СЕМЕЙСТВА** псевдо-провайдерами через тот же ключ (разные компании — рою нужны

Первую версию порога я поставил только на запасные вызовы — прямой `omniroute` пролез
с 5 символами. Проверять надо ВСЕ пути, а не тот, что чинишь.

**Итог прогонов:** было 5/8 (из них 2 пустых → фактически 5 полезных) → стало **8/9
содержательных**, суммарно 21160 символов, минимальный голос 1371. Состав: 10 в списке,

### 🔴 ИНЦИДЕНТ 13.08: ШЛЮЗ ЛЁГ → РОЙ УПАЛ 10 → 6 (единая точка отказа)

Боевой прогон дал **6/11**: `ag_gemini_pro`, `ag_opus` и ОБА запасных входа отвалились
с `Connection error`. Причина не токен (он живёт 1 ч и **обновляется сам**), а то, что
**процесс OmniRoute был остановлен**: `curl` → HTTP 000, порт 20128 свободен.

**Урок: шлюз держал ТРИ голоса из одиннадцати** (два antigravity + запасной канал),
и его падение уронило рой почти вдвое. Голоса через один процесс = коррелированный отказ,

**Фикс:** шлюз поставлен под **pm2** (`pm2 start …/omniroute.mjs --name omniroute -- serve`,
id 34) + `pm2 save`. Теперь автоперезапуск, как у остального. Порт держали ДВА node-воркера —
убивать надо по `CommandLine like '*omniroute*'` через CIM, обычный `Stop-Process` по порту
поднимает следующий воркер.

**После фикса: 9/11** (упали `openrouter` и `or_gemma` — 429 у апстрима).
⚠️ Замечено: `openrouter` + `or_cohere` + `or_poolside` + `or_gemma` идут через ОДИН ключ →
4 параллельных запроса ловят общий rate limit. Цена расширения одним ключом.

### 🔄 РЕВИЗИЯ СОСТАВА 18.08: бесплатные тиры ГОРЯТ, состав надо перемерять

Через 5 дней после сборки роя **три голоса из одиннадцати сгорели молча** — код не менялся,
изменились чужие тарифы. Пинг всех провайдеров живьём: было **7 из 12**.

| выбыл | причина | это не наш баг |
|---|---|---|
| `cerebras` | **402 Payment required на ВЕСЬ каталог** — free-tier аккаунта закрыт. Модель `zai-glm-4.7` вдобавок архивирована → 404 | биллинг Cerebras |

незаметно строится на меньшинстве.

≥200 симв. + доля кириллицы ≥25% + ≥3 цифры в ответе. Из 19 кандидатов прошли 7.

| слот | было | стало | почему |
|---|---|---|---|

### 🟢🟢 ШЛЮЗ СНЯТ С pm2 → ПО ТРЕБОВАНИЮ (18.08, Егор: «бот обрастает процессами»)

**🔴 pm2 ВРАЛ О ПАМЯТИ ВТРОЕ.** В `pm2 list` omniroute висел как **46.5 MB** и выглядел
седьмым по весу. На деле launcher **форкает воркер** (`node --max-old-space-size=4096`),
которого pm2 НЕ мониторит: **303.8 MB**. Итого **350 MB** — самый тяжёлый компонент из
шестнадцати online, при заявленных 1207 MB на всех.

**🔑 УРОК КЛАССА «ПРИБОР ВРЁТ»:** `pm2 list` показывает только процесс, который запустил САМ.
Всё, что тот форкает, в мониторинге не видно. Мерить надо через
`Get-CimInstance Win32_Process | ? CommandLine -like '*имя*'`, а не по таблице pm2.
Два PID на один сервис — это launcher+воркер, НЕ дубль (13.08 я чуть не убил «лишний»).

**Почему держать 24/7 было незачем:** шлюз нужен ТОЛЬКО на прогон роя — голоса `ag_*` и
запасные входы при 429. Проверено grep'ом: ни один фоновый процесс от него не зависит
(`news_sphere` ходит к API напрямую своими ключами).

**Сделано:**
- `llm_ask.py`: `gateway_alive()` (socket, без HTTP) · `ensure_gateway()` — поднимает, только
  если порт молчит, ждёт готовности до 45с · `stop_gateway()` — **`taskkill /T /F`, убийство
  ДЕРЕВА**: одиночный kill оставил бы воркер на порту.
- `team_ask.py` и CLI `llm_ask` (`--provider ag_*`/`omniroute`): поднимают сами, гасят через
  **`atexit`** — срабатывает и при исключении, и при `sys.exit`, без переиндентации `main()`.
- Гасим ТОЛЬКО свой процесс: `ensure_gateway` возвращает `None`, если шлюз уже был жив →
  чужой (pm2/ручной) не трогаем.
- `pm2 delete omniroute` + `pm2 save`. Вернуть при нужде:
  `pm2 start C:\Users\yogoru\AppData\Roaming\npm\node_modules\omniroute\bin\omniroute.mjs --name omniroute -- serve`

**Проверено боевым прогоном при выключенном pm2:** шлюз поднялся за 5.5с → `2/2` голосов
(`ag_gemini_pro` + groq) → погашен, порт свободен, процессов omniroute ноль.
Через CLI `llm_ask --provider ag_gemini_pro` — тот же цикл за 0.5с.
**node-процессов 11 → 9, память node 766 → 418 MB.**

**Цена:** +0.5–6с на прогон роя (холодный старт шлюза). Рой запускается эпизодически —
против 350 MB круглосуточно размен очевидный.

**🔴 ПОБОЧКА ПЕРЕХОДА НА ON-DEMAND (Егор поймал сразу): `omniroute serve` ПО УМОЛЧАНИЮ
ОТКРЫВАЕТ БРАУЗЕР** на `localhost:20128/home`. Под pm2 это случалось раз в сутки и было
незаметно — при подъёме на каждый прогон вкладка лезла на КАЖДЫЙ запрос к рою.
Лечится флагами: `serve --no-open --no-tray` (есть в `serve --help`).
🔑 Урок: меняя частоту запуска процесса с «раз в сутки» на «каждый вызов», перечитывай его
дефолты — безобидное стартовое поведение становится назойливым ровно во столько раз,
во сколько выросла частота.

**Побочная находка:** `scripts/news_sphere.py` (фоновый COMPASS-SWARM, pm2 online 63ч)
