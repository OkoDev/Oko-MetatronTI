04.10.2026, Егор: «собственные ошибки до вердикта нужно научиться ловить и перепроверять сразу,
а не ловить после! какие изменения нужно внести в скиллы чтобы самопроверка работала лучше?»

**Разбор моих ошибок 30.09–04.10 — ни одна не была статистической:**

| ошибка | как возникла | что бы поймало |
|---|---|---|
| метка «разворот/по импульсу» ИНВЕРТИРОВАНА — все выводы зеркальны | угадал смысл `side` по имени поля | golden-case на 1 строке |
| «стоп 0.315 импульса» вместо 0.129 | взял `stop_loss` из БД, его перезаписывает TSL | паспорт поля (кто пишет, перезаписывается ли) |
| «кост съедает 72% риска» | взял `abs(slip)`, а знак означал «ЛУЧШЕ сигнала» | запрет `abs()` на знаковом + баланс знаков |
| «два минуса в коридоре» | коридор измерен на LONG, в выборке были SHORT | ассерт «срез по стороне применён» |
| тест ждал 0.129 вместо 0.121 | спутал медиану отношений с отношением медиан | расчёт вручную до кода |

**Why:** протокол вердикта ловил ошибки ВЫВОДА (срезы, артефакты, контроли), но не ошибки
ЧТЕНИЯ ДАННЫХ. А именно они и давали зеркальные результаты. «Смотреть внимательнее» уже
не сработало — значит проверка должна быть МАШИННОЙ и стоять в скрипте.

**Что внесено (`.claude/skills/research-verdict/`):**
1. **§0A КОНТРАКТ ДАННЫХ** — гейт до инвентаризации: паспорт поля (кто пишет / перезаписывается
   ли / смысл знака) · golden-case на каждую метку и знак · инварианты (len после merge, сумма
   групп, срез по стороне, запрет `abs()`) · **калибровка** (воспроизвести прошлый замер ДО
   нового) · печать сырых строк, клетки n<10 — поштучно.
2. **§4.5 ОСТАНОВКА НА ПРОТИВОРЕЧИИ** — порядок подозреваемых: (1) моя метка/знак, (2) мой срез,
   (3) мой источник, (4) только потом рынок. Сенсацию объяснять рынком — последнее, что делать.
3. **`references/selfcheck.py`** — готовые ассерты в одну строку: `golden`, `signed`,
   `no_merge_loss`, `single_side`, `parts_sum`, `raw`, `calibration`. Проверено: ловит все
   четыре ошибки выше, плюс предупреждает «нулей больше половины — проверь, не значит ли 0
   НЕ ИЗМЕРЕНО» (ровно случай `live_orders.slip_pct`).
4. Чек-лист §7 пополнен шестью пунктами контракта данных.

**How to apply:** в каждом новом замере — импорт `selfcheck` и 4-6 ассертов ДО основного
прогона. Нет golden-case на метку → вердикт по ней запрещён. Расхождение с прошлым замером —
первый подозреваемый свой код, а не находка.
