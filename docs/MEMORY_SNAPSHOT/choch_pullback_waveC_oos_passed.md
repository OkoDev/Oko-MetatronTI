# 🟢🟢🟢 CHoCH → КОРРЕКЦИЯ → ВОЛНА C: OOS ПРОЙДЕН (17.08.2026)

Первая за всё время механика, которая устояла под строгой OOS-проверкой.
Скрипты: `choch_pullback_real_leg.py` (находка) · `choch_oos_validation.py` (валидация).

## Механика

```
swing-CHoCH (len50, из st.events OKO-SM)
  → нога СТРУКТУРНАЯ: origin/extreme из run_structure(record_legs=True).leg_history[i]
  → откат 0.236 от ноги → ЛИМИТНЫЙ вход (налог на исполнение не платится)
  → стоп за origin (инвалидация ноги) → цель волна C ×1.0 от |A|
  → 1h, держим до 96 баров (~4 суток), косты 0.35%
```

## 🔑 Ключ к находке — ЗАМЕЧАНИЕ ЕГОРА ПРО НОГУ

Егор 15.08: «расчёт ноги тут имеет место?! это напрямую влияет на зону OTE».
Он был прав — грубая нога (`L[i-20:i+1].min()` … `C[i]`) расходилась со структурной:

| | грубая vs структурная |
|---|---|
| направление совпало | **44.4%** (при смешанных масштабах) → **100%** (при согласованных) |
| длина структурной / грубой | медиана **4.06×** → 1.74× |
| смещение ЗОНЫ ВХОДА | медиана **2.74%** цены → 0.96% |

совпадать: swing-слом → swing-нога. После согласования — PF 1.15.

## 🛠️ РЕАЛИЗОВАНО В БОТЕ (19.08.2026) — и что вскрыл перемер

### 🔴 БАГ, КОТОРЫЙ ПОЙМАЛА РЕГРЕССИЯ (иначе ушёл бы в бой)
Резолвер лупа искал исполнение лимита **по всей истории**, а замер — только в окне
`range(i+1, i+1+wait)` (12 баров) и держал позицию 96 баров ОТ ФИЛА. Расхождение
на **1086 из 1807** сетапов: бот заходил бы на протухших сетапах, которых в бэктесте
не было. Тот же класс, что [[universe_mismatch_backtest_vs_live]] и
[[live_entry_differs_from_backtest_wt_rising]].
🔑 УРОК: сверять реализацию с замером не «глазами по коду», а **прогоном на одних
данных с независимо написанным эталоном**. Проверка «многошаговый резолв (как в бою,
каждые 15 мин на растущем df) == одношаговый» — обязательна, именно она и покраснела.

### ✅ ЧТО ПРОВЕРЕНО ЗАПУСКОМ
- резолвер == эталон замера: 0 расхождений (1807 сетапов);
- многошаговый == одношаговый: 0 расхождений;
- **источник данных чист**: нативный 1h (что берёт бот) против ресемпла 15m→1h
  (на чём мерился эдж) — **1468 сломов у обоих, 0.0% расхождения**, PF 1.04 у обоих.
  Подозрение на дефект реализации снято;
- фильтр синтетики на живой вселенной: 848 пар → **532 крипто**, 316 отсеяно.
  Ложное срабатывание найдено и убрано: `SPX` на BingX = SPX6900 ($0.32), а не индекс.

### ⚖️ ПЕРЕМЕР НА ШИРОКОЙ БАЗЕ: PF 1.07, НЕ 1.17
198 монет, 4885 сделок, окно **2022-2026** (шире, чем окно находки), косты 0.35%:
база **PF 1.07, WR 50.2%, медиана +0.055%, безтоп10% −6193**.
Закон [[law_recorded_pf_needs_remeasure]] сработал в пятый раз — записанное число
оказалось верхней оценкой. Причина видна в разрезе по годам:

| год | PF базы | PF в коридоре стопа 8-15% |
|---|---|---|
| 2022 | 1.48 | **1.80** (безтоп10% **+227** — единственный положительный) |
| 2023 | **0.65** | 0.79 |
| 2024 | 1.08 | 1.17 |
| 2025 | 1.38 | 1.48 |
| 2026 | 0.92 | 1.03 |

**2023 (бычий) валит SHORT-механику** — тавтология режима, а не дефект. Окно находки
его почти не содержало.

### 🔑 КОРИДОР СТОПА 8-15% — сильнейший фильтр, и он НЕ подгонка
PF 1.07 → **1.21**, медиана +0.055% → **+0.881%**, хрупкость −6193 → −1738, охват
**63% монет** (124 из 198), 10.5 сделок на монету. Поднимает PF **в каждом из пяти
лет** — подгонка так себя не ведёт. Вне коридора: <8% PF 1.01 (косты съедают цель),
>15% PF 0.88. Совпадает с [[bigflush_edge_size_not_timeframe]] — законом размера,
подтверждённым теперь на четвёртой независимой механике.
Ядро + час≤7 UTC: **PF 1.38, WR 54.9%, n=718, безтоп10% −233** (почти нехрупко).

Ликвидность: Q3 лучший (1.22), Q4 ликвид худший (0.99) — направление «крупные хуже»
из [[choch_boosters_exits_oos]] подтвердилось, но пик не на Q1 (1.00), а на Q3.
