# Ретро-бэктест инсайта «сторона зависит от фазы рынка» (22.07)

Вместо 3-нед форварда — восстановил структурный тренд BTC 4h на входе КАЖДОЙ из 46k
закрытых сделок (`scripts/phase_backtest.py`, look-ahead-safe окно 200, net%=profit−costs).

## Результат — инсайт НЕ подтверждён в лоб
| | ПО фазе | ПРОТИВ | Δ |
|---|---|---|---|
| **VST** (правда) | −0.219% n=8895 | −0.222% n=6985 | **+0.003% — НЕ разделяет** |
| SIM | −0.562% | −0.728% | +0.166% (обе глубоко в минусе) |

**На VST макро-veto по тренду BTC не отделяет прибыль от убытка.** Обе стороны льют ~−0.22%.
Интуиция «шорт против роста льёт» на уровне ПОРТФЕЛЯ не работает — всё льёт после costs.

## Но фаза работает ПО КЛАССАМ (ключ к живому противоречию pump-SHORT vs TREND_UP)
- `arch104` (continuation): ПО −0.09% vs ПРОТИВ −0.42% → фаза **помогает**
- `radar_build_flip` (бывшая течь): ПРОТИВ **−1.48%** → льёт сильнее против тренда
- `radar_pump` (единственный доказанный): ПРОТИВ **+1.74%** vs ПО −0.54% (n=10/11) → **живёт ПРОТИВ фазы** (mean-reversion: шорт всплеска)

**Вывод:** слепой veto «не шортить в TREND_UP» убил бы pump. `phase_fit` УЖЕ режет только
continuation, reversal пропускает — дизайн верен. НО [[phase_sphere_decision_core]] снапшот
(`trade_phase_snapshot`) для не-мажоров без пер-пара данных судит по голому макро-veto →
метит pump-SHORT `fit=False`. **БАГ для reversal-класса — фит должен учитывать strategy_class.**

**Why:** экономит 3 недели ожидания + опровергает наивный гейт до его активации.
**How to apply:** (1) фаза-veto применять только к continuation-классу сигналов, не глобально;
(2) фазу мерить не глобально а per-source (arch104 да, pump нет); (3) фаза НЕ спасёт убыточную
систему — эдж не в плотной автоторговле ([[strategy_truth_state]], honest project assessment).
Связано: [[forward_machine_sphere11]] (pump SHORT единственный не-льющий), [[atr_s2_survived_honest]].
