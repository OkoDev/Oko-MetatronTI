# 🔴 ПРИБОР САМОДИАГНОСТИКИ КУБА ВРАЛ 38/38 MISSING (12.08.2026)

## Как нашли
Handoff `whats-next.md` предписывал первым действием новой сессии запустить
`python -c "from core.selftest_cube import run_cube_selftest"` с формулировкой
«Их **никто ни разу не запускал**». Запустил — и прибор оказался сломан в двух местах.

## Что было сломано
1. **Падал до единой строки вывода**: `UnicodeEncodeError` cp1251 на Windows-консоли.
2. **Под UTF-8 печатал 38/38 MISSING** — все 13 сфер, 21 ребро, 4 цикла красные.
   Причина: `if __name__ == "__main__"` подставлял `class _Stub: config = None`
   вместо бота. Каждая проверка не находила атрибут и рапортовала «ОТСУТСТВУЕТ».

Ровно на этот запуск вели **три** документа: `BOT_SIGNAL_MAP.md`,
`docs/TASKS_DETAILS.md`, `docs/SIGNAL_BUS_CUBE_MAP.md`.

## 🔑 Гипотеза о корне (НЕ доказана)
Отсюда, вероятно, и пошли пометки «❌ ОТСУТСТВУЕТ» в энциклопедии, которые держались
три месяца при живых сферах — см. [[ml_spheres_worse_than_coinflip]]. Прибор, написанный
ради ответа «какие сферы живы», сам же и породил ложный ответ. Доказательства связи нет,
только совпадение вывода прибора с текстом документа.

## Уточнение к handoff
«Никто ни разу не запускал» — **неточно**. L13-L15 выполняются при КАЖДОМ старте бота
(`bot/core/bot.py` → `core/selftest.py` → `run_cube_selftest`). Но `cube_text` уходил
**только в Telegram** — в лог писались лишь L1-L12. Результат нигде не оседал, поэтому
статусы сфер приходилось брать из документа. Отсюда и закон «статусы сфер — из КОДА».

## Что починено
- `GET /api/cube/selftest` (`web/dashboard_server.py`) — живой отчёт по работающему боту.
- `python core/selftest_cube.py` теперь ХОДИТ за живым отчётом; `--stub` оставлен, но
  печатает громкое предупреждение «MISSING здесь = нечего проверять, а НЕ сферы нет».
- `bot/core/bot.py` пишет `cube_text` в лог при старте — отчёт оседает в pm2-логе.
- Три документа исправлены + приписка в `docs/ENCYCLOPEDIA.md`.

## 🔴 5-й ДЕФЕКТ: прибор врал и В ДРУГУЮ СТОРОНУ (ACTIVE вместо SHADOW)
`_edge_wt_to_ti` рапортовал `ACTIVE — TI._wt_specialist.predict=ok`, проверяя
`hasattr(wt, "predict")` — **наличие метода, а не использование ребра**.
На деле `_wt_specialist.predict` не вызывается НИ В ОДНОМ модуле (grep 12.08):
DEV-161 заменил ML-предсказание на rule-based `derive_wt_verdict`
(«AUC=0.49 был < случайного»).

Следствие: `MTFWTSpecialist` **обучается на 7437 сделках при КАЖДОМ старте бота**
(~7 секунд RandomForest) и результат выбрасывается. SMC-модель для сравнения
используется по-настоящему (`_smc_specialist.predict` в `trading_intelligence.py:1117`).

Починено: S3 → SHADOW с пояснением «обучение впустую», `E_WT_TI` → SHADOW
«ребро разорвано». **Урок: проверка «атрибут существует» ≠ проверка «связь работает».
Диагностика должна мерить ИСПОЛЬЗОВАНИЕ, а не наличие.**
