Правило: время в логе и в БД — в РАЗНЫХ часовых поясах. `crypto_bot.log` — локальное МСК (UTC+3). `simulated_trades.created_at` — UTC (суффикс `+00:00`). Разница ровно 3 часа.

**Why:** 01.06.2026 при проверке магнитов после рестарта «14:58 локал» дважды получил «0 сделок после 14:58» — фильтровал `created_at >= '14:58'` (думая это UTC), но 14:58 было ЛОКАЛЬНОЕ время = 11:58 UTC. MAX created_at в БД был 13:48 UTC = 16:48 МСК (свежак), но мой фильтр «>=14:58 UTC» отсекал всё. Лог `[ExitManager P2]` в 16:48 МСК соответствовал записи БД 13:48 UTC — выглядело как «лог есть, а в БД нет», ложная паника. Потерял ~3 итерации на ложный баг.

**How to apply:**
1. Время рестарта/события взято из ЛОГА (МСК) → для SQL-фильтра по `created_at` вычесть 3ч (МСК−3 = UTC).
2. Надёжнее: фильтровать через `datetime(created_at) >= datetime('now','-N minutes')` — оба в UTC, рассинхрон не важен.
3. Для отображения сопоставления: `created_at[11:19]` это UTC; чтобы найти строку в логе — прибавить 3ч.
4. Признак промаха: «MAX(created_at) свежий, но since-фильтр даёт 0» = почти всегда timezone-рассинхрон, а не отсутствие данных.
5. Связка с [[feedback_metrics_hygiene]] — указывай зону времени в выводе, если показываешь и лог, и БД.
