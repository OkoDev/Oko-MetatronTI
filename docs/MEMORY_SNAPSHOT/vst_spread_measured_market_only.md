# 🟢🔴 НАЛОГ VST ИЗМЕРЕН: он реален, но платят его ТОЛЬКО рыночные входы (28.08.2026)

Вопрос Егора: «заперто до выяснения о несправедливом спрэде на VST?». Выяснение
сделано — это был пункт 3 из «НЕ проверено» в [[backlog_vst_spread_poisons_forward]],
лежавший с 14.08.

**Метод.** Эталон — реальная свеча 15m из `ohlcv_cache`. Если бы наш ордер исполнился
на настоящем рынке, эта сделка вошла бы в свечу и расширила её `high`/`low`. Цена
филла ВНЕ диапазона реального бара ⇒ сделки по этой цене на реальном рынке не было.
Выборка: **4326 сделок · 458 монет · июнь–август 2026**.

## Результат и три контроля

| контроль | что проверял | итог |
|---|---|---|
| **К1 базис↔спред** | кэш Binance, торгуем BingX — не межбиржевая ли премия? | LONG хуже 40.9%, SHORT хуже 36.1%; выше бара 22.2%, ниже 18.1% → **двусторонний СПРЕД**, не базис |
| **К2 тайминг** | не артефакт ли сопоставления баров? | ЗАЯВЛЕННАЯ цена: хуже/лучше = **0.3:1** · ФАКТИЧЕСКАЯ: **24.6:1** → разница на два порядка = налог |
| **К3 тип входа** | предсказание бэклога «LIMIT спред не платит» | **ЛИМИТНЫЕ 1.4% · РЫНОЧНЫЕ 43.6%** — подтверждено буквально |

Медиана выхода за диапазон **+0.178%**, 90-й перцентиль **+0.601%**, при медианной
свече 15m 0.640%. Хвост облагается сильнее топ-12 (+0.187% против +0.062%).

## 🔴 Налог объясняет НЕ ВЕСЬ разрыв

Для `ote_nested`: доля обложенных 42.5% × медиана 0.178% = **0.076%/сделку**.
А разрыв SIM↔биржа был **0.315 п.п.** ([[ote_nested_off_by_decision_confirmed]]).
Спред закрывает лишь **~24%**.

Тест консервативен по построению: он видит только выход ЗА границу бара. Филл
внутри бара, но в худшей его части — тоже налог, и он не посчитан. Значит
0.076% — **нижняя** граница, истина между 0.076% и 0.315%.

## 🔑 Поправка к «вход съедает 85% стопа»

Проскальзывание `actual` против `declared` = +0.538% медиана — это НЕ весь налог.
К2 показал: заявленная цена в **24.5%** случаев ЛУЧШЕ реального бара, то есть она
сама оптимистична/устарела. Часть «проскальзывания» — наша собственная задержка
между расчётом и отправкой, а не спред биржи. Разделять эти две вещи обязательно.

## Что из этого следует

1. **Ждать LIVE, чтобы «эдж проявился», НЕ надо.** Налог не универсален: он привязан
   к типу входа, а не к домену. Лимитный вход не платит его и на VST.
2. **Живые источники уже защищены**: радар · impulse_fib(_15m) · rangefade(4h) ·
   choch_wavec входят ЛИМИТКОЙ (1.4% обложенных). Пострадавшие — `ote_nested`,
   `wt_sideways`, `pivot_reversal`, `confluence` — все с рыночным входом и все выключены/мертвы.
3. **Починка исполнения для `ote_nested` = смена типа входа на лимитный**, а не
   ожидание боевого домена. Сходится с [[radar_limit_pullback_entry_candidate]] и
   законом impulse_fib «лимит бьёт рынок».
4. Прежние выводы «эдж не переживает косты» ([[live_root_cause_costs_eat_tight_stops]])
   для MARKET-путей завышали налог, для LIMIT-путей — корректны.

## НЕ проверено

- сравнение с LIVE-доменом напрямую (боевых сделок в окне нет — домены изолированы);
- выход (SL/TP по `MARK_PRICE`) — мерился только ВХОД;
- систематичность по времени суток;
- сколько именно из 0.315 п.п. даёт филл «внутри бара, но в худшей части».
