## Факт, который печатается при КАЖДОМ старте бота
```
MTFWTSpecialist:  обучено на 7434 сделках | win_rate 36.9% | CV AUC = 0.283
MTFSMCSpecialist: обучено на 7428 сделках | win_rate 37.0% | CV AUC = 0.180
```
`scoring="roc_auc"`, метка `y = 1 если win` (с учётом скрытых TSL-выходов, DEV-190).
**AUC 0.5 = монетка. 0.18 и 0.28 = систематически НАОБОРОТ.** Никто не смотрел в лог.

## Три версии
1. **ИНВЕРСИЯ ПО РЕЖИМУ (главная).** `cross_val_score(cv=5)` → `StratifiedKFold` без
   перемешивания = **непрерывные блоки времени**. Модель учится на одном режиме, проверяется
   на другом. Если связь «признак→исход» переворачивается с режимом — а это доказано 11.08
   ([[regime_switch_causal_survives]]: в быка лонг 1.46/шорт 0.33, в медведя наоборот) —
   AUC ОБЯЗАН упасть ниже 0.5.
   → **Эти сферы — независимое эмпирическое подтверждение зеркала режима.**
2. **Перепутанные метки.** AUC 0.18 при инверсии даёт 0.82 — подозрительно красиво.
3. **`TimeSeriesSplit` не используется вовсе** — методологическая ошибка сама по себе.

## Решающая проверка (дешёвая)
Обучить с меткой режима как ПРИЗНАКОМ либо обучать/проверять внутри одного режима.
AUC перешёл 0.5 → версия 1 верна, сферы оживают одной правкой. Не перешёл → искать метки.
Всё готово: 35 признаков у WT, 36 у SMC, причинная метка режима (`core/context/market_drift`).
