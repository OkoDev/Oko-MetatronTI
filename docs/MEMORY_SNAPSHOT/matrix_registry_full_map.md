## Два ограничения ИНСТРУМЕНТА, а не данных

1. `blind_select` проверяет ЛЮБОЙ признак как `f > 0` → для числовых это единственный
   порог «ноль». Все дистанции и z-оценки тестировались одной точкой.
2. Матрица целиком БУЛЕВА: `wt_os` = «wt < −60», порог зашит, отбор не мог искать свой.

✅ **Опровергнуто прогоном** (важно, чтобы не искали снова): гипотеза, что признаки
старших ТФ выпадают из отбора из-за `dtype == object` после `shift(1)`, НЕ подтвердилась —
все 435 доходят до `feature_cols()`.

## Метод: субагенты + обязательная верификация

Инвентаризацию делали два субагента параллельно (реестр `features_json` и локализация
модулей). 🔴 Перед записью в `docs/` отчёт сверен автоматически через **AST**, а не на
слово: **65 из 66 утверждений точны** (файл+имя+строка), одно расхождение по номеру
строки. Правило: отчёт субагента в документацию идёт ТОЛЬКО после машинной сверки —
документ становится контрактом для других агентов.
