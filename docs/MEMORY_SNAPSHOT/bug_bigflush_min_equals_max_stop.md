# 🔴🔴 BIGFLUSH15 ВЫКЛЮЧЕН ЛОГИЧЕСКИМ ПРОТИВОРЕЧИЕМ (найдено 01.09.2026, задача 136.E)

## Дефект

`bot/loops/rangefade_loop.py:254-260` — два гейта подряд, оба из одного конфига:

```python
if min_stop_pct and stop_pct < min_stop_pct:   # bigflush15 → 4.0
    continue
if MAX_STOP_PCT and stop_pct > MAX_STOP_PCT:   # общий для лупа → 4.0
    continue
```

`bigflush_min_stop_pct: 4.0` (config.yaml:224) и `max_stop_pct: 4.0` (config.yaml:266)
дают окно шириной НОЛЬ: пройдёт только `stop_pct` ровно 4.0.

**Источник не отключён и не «редко срабатывает» — он не может открыть ни одной сделки.**

## Почему это возникло

Правка 13.08 делалась ДЛЯ `rangefade4h` по замеру на **n=56 боевых сделках**
(«потолок ≤4% → PF 3.94»), а `MAX_STOP_PCT` читается ОДИН на весь луп и применяется
ко ВСЕМ его вариантам: `rangefade`, `rangefade4h`, `bigflush15`.

🔑 В самом конфиге (строка 265) записано: «Это ПОТОЛОК, а не минимум: у фейда эдж
в МАЛЫХ стопах, обратно radar_pump (>6% → PF 3.01)». То есть про разную сторону
у разных источников знали — и всё равно применили общий потолок.
У `bigflush15` эдж по построению в КРУПНОМ стопе (его смысл: «косты 3% цели вместо 30%»).

## Цена: отрезана рабочая зона

Перемер на ядре 97 монет, 6164 сигнала, с 2023 (`scripts/bos_gate_core.py`),
внутри боевого BOS-гейта len5:

| стоп | n | WR | PF | безтоп10% | монет+ |
|---|---|---|---|---|---|
| 4-6% | 1 288 | 46.7% | 1.08 | −542 | 45/95 |
| **6-10%** | 1 014 | 65.6% | **3.28** | **+952** | **88/95** |
| **10-20%** | 355 | 71.5% | **4.16** | **+479** | 64/87 |
| 20-100% | 68 | 64.7% | 2.87 | +122 | 26/38 |

Потолок 4% оставляет источнику ровно ту зону, где его нет, и режет 6-20%,
где PF 3.28-4.16 при 88 монетах из 95 в плюсе.

🔴 Прежнее объяснение «bigflush15 не торгует из-за схлопывания частоты стопкой гейтов»
([[bigflush_frequency_collapse_stacked_gates]]) — НЕВЕРНО или неполно: дело не в
частоте, а в пустом пересечении двух порогов.
