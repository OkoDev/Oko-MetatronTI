# 🔴🔴 BINGX ТРОТТЛИТ IP ПО НАКОПЛЕННОЙ НАГРУЗКЕ (доказано 02.09.2026)

**Вопрос Егора:** «latency биржи от количества запросов может расти на наш IP?»
**Ответ: ДА.** Доказано на 89 замерах `health_loop` за 7 часов.

## Доказательство

Доля выбросов latency >8000 мс по ВОЗРАСТУ процесса (время с последнего рестарта):

| возраст | замеров | выбросов | доля |
|---|---|---|---|
| **≤10 мин** | 37 | **0** | **0%** |
| 10-30 мин | 22 | 6 | 27% |
| >30 мин | 15 | 6 | **40%** |

P(ноль выбросов из 37 при базовой доле 27%) = **8.8e-06**, то есть 1 шанс из 114 000.
Случайностью не объясняется.

Медиана latency: 0-10 мин — **2594 мс** · 30-60 мин — **8625 мс** (×3.3).
Максимумы доходят до **71 297 мс** (71 секунда на один запрос).
Наблюдается живьём: 03:48 → 35 218 мс, 04:10 → 21 110 мс, **рестарт** → 04:20 → 2594 мс.

🔑 Значения — реальные измерения (78 различных), не константы. Выбросы разбросаны
по всем 7 часам, не один эпизод биржи.

## Что это меняет

**Сокращение запросов даёт ДВОЙНОЙ, нелинейный выигрыш:** меньше запросов →
меньше накопление → ниже троттлинг → быстрее каждый оставшийся запрос.
Раньше считалось линейно ([[scan_cycle_formula_latency]]: цикл = REST × latency / параллелизм),
но latency сама зависит от REST.

| рычаг | почему теперь ценнее |
|---|---|
| **прокси** (3 IP в `.env`, флаг off) | ПРЯМОЕ лекарство: накопление делится на 3 IP |
| **WS на 3m/5m** | −63% запросов → и меньше троттлинга |
| рестарт | сбрасывает окно — отсюда ощущение «после рестарта летает». Лечение симптома, не причины |

## Ловушка для будущих замеров

🔴 **Любой замер производительности зависит от возраста процесса.** Проба WS 02.09
шла в окне 20-50 минут после рестарта — как раз там, где троттлинг нарастал, поэтому
эффект утонул. Сравнивать конфигурации можно только на ОДИНАКОВОМ возрасте процесса
либо усредняя по нескольким полным циклам.
