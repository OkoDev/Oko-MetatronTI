28.09 замер медианы WT (`scripts/wt_median_info.py`) показал EMA14 как лучшее из всего, что мерили по WT:
0.006–0.008 бит на 1h, точность выше порога костов. Подозрение вызвало расхождение с SMA той же длины (≈0).

Разбор: в таблице направлений ячейка «над медианой · медиана падает» имела форвард 0.000 / 0.000 / доля роста
0% во ВСЕ годы. На плоском ряду wt1 ≈ медиана, EMA-состояние из-за численного шума уходит в редкую ячейку
(~0.6% строк), где ответ всегда «не рост» (fwd = 0 → y = 0). 0.6% детерминированных строк ≈ 0.006 бит —
ровно «находка». У SMA плоские строки сливались с большой ячейкой → информации не было.

После исключения ничьих (`fwd == 0 → y = −1`) и плоских участков (диапазон 24 бар = 0): EMA14 → 0.0005 бит.

**Why:** контроли подсадкой и шумом этот артефакт НЕ ловят — он живёт в данных, а не в приборе. Контроль-сдвиг
тоже не ловит (монета мёртвая долго). Повтор урока 18.04 «артефакты данных живут дольше фиксов»
(docs/AUDIT_LESSONS_18APR.md).
**How to apply:** в любом замере знака форварда — ничьи исключать (сделано в `oi_info_ceiling.measure`, общий
прибор); подозревать находку, если две версии «одного и того же» признака расходятся на порядок; смотреть
таблицу направлений на ячейки с ровными 0.000. Перемер фандинга без ничьих вывод не изменил.
Связано: [[positioning_layer_info_ceiling]], [[wt_median_length_info_measured]].
