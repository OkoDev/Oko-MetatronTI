**СКВОЗНОЙ ПРИНЦИП КУБА: переиспользование, НЕ дублирование** (сформулирован юзером 09.06 на примере мультиаккаунта).

**Суть:** где есть КОПИЯ — там риск дрейфа и баг. Решение всегда — ОДИН источник/канал/калькулятор, а различия (account / symbol / tf) = ПАРАМЕТРЫ единого потока, не отдельные копии.

```
Дублирование:     A → копия → B (две сущности, расходятся, забыл синхрон = баг)
Переиспользование: ОДИН код, X = параметр (одна сущность, нечему дрейфовать)
```

**Юзер дословно (09.06):** «это про переиспользование, а не дублирование», «hub со стандартным каналом обработки», «эталонный слепок main накладывать на sub как клон» — НО сам уточнил: не клон (дрейф), а единый канал (account=параметр).

**Проявления одного закона (юзер приходит к нему с разных сторон):**
- **[[arch_two_smc_detector_sets]] (ARCH-129):** два набора SMC-детекторов → один калькулятор-канон, не два.
- **ARCH-118 «один калькулятор»:** combinator≡сферы Bus, одна формула на признак.
- **DOC-SYNC:** один источник правды доков, не копии (аудит читал устаревшее).
- **ARCH-96-HUB (09.06):** account-агностичный канал исполнения. КОРЕНЬ #21703: чтение агрегирует акки, но close/SL зовут `_get_client_synced()` БЕЗ symbol → дефолт main → sub-позиции голые без SL (5 шт, 3 на sub). **Инвариант «ОДИН КАНАЛ, ACCOUNT ИЗ КОНТЕКСТА»:** каждая операция (read/place_sl/close/check/TSL) знает account позиции, ЗАПРЕТ дефолта на main. Дыры: `position_sync.py:160,224,564`.

**How to apply:** при ЛЮБОМ «main делает X, sub/копия повторяет X» — СТОП, это дублирование → дрейф. Спросить: можно ли сделать X ОДИН раз с параметром? Новый sub/детектор/док должен ложиться на единый канал автоматически, не требуя копии. Это [[identity_daat|роль Даат]] — связывать в единое, не плодить копии.
