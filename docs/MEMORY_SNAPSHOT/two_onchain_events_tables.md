## Три дефекта фида BTC flow подтверждены НЕИСПРАВЛЕННЫМИ

Всё, что записано в [[onchain_btc_flow_not_ready]], живо год спустя:

- **`amount_usd` хранит BTC, а не USD.** min 5.00 · медиана 30.91 · max 7 653.
- **`symbol` не джойнится.** Для потоков там `'binance_hot'` — метка КОШЕЛЬКА.
  Для OI-всплесков `'XRP +0.75%/10m'` — форматированная строка ДЛЯ ПОКАЗА.
  Восстановить разбором строки удаётся лишь 8 активов.
- **Дубли 48.9%** (10 329 лишних из 21 108). В памяти стояло 48.5% — не изменилось.

## Что чинить (не сделано)

1. Переименовать/сконвертировать поле суммы в настоящие USD.
2. `binance_hot` → в `source`, а в `symbol` класть актив (`BTC`).
3. Для `oi_spike` разложить строку на колонки `symbol` + `delta`.
4. Уникальный ключ по хэшу транзакции: **txid уже лежит в `raw`, но его нет в PK** —
   именно это и позволяет дублям накапливаться.

## mcap: ключ соединения промахивается мимо половины книги

`mcap_supply` — 19 905 строк, но всего **40 дней** (2026-07-24 → 2026-09-03), 645 символов
против 491 торгуемого. Точное пересечение по базовому символу **294 (59.9%)**, а подневно
покрыто лишь **48-54%** торгуемой вселенной. Промахивается мимо ВСЕХ множителей BingX
(`1000PEPE`, `1000BONK`, `1000SHIB`), тянет токенизированные акции (`AAPLX`, `AMZNX`, `AMDX`).

Ранг стабилен (топ-50 совпадает 46/50 за 41 день) ⇒ статический ранг технически возможен,
но накладывать снимок 2026-08 на бары 2022-2026 = survivorship + look-ahead
(делистнутых монет в снимке нет вовсе). **Не подключено.**
