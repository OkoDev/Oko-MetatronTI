**Новый рабочий формат после подключения TW-MCP (Егор 01.07.2026). Ground-truth валидация детекторов.**

## Идея
Раньше детекторы (ote_signal_generator, oko_ote, smc_engine) валидировались СЛЕПЫМ бэктестом,
который врал look-ahead'ом ([[bug_select_significant_impulse_full_dataset_lookahead]],
[[wave_phase_filter_lookahead_survivors]]). Теперь **живая OKO-SM разметка Егора = эталон (ground
truth)**, детектор учится СОВПАДАТЬ с ней. TW-MCP даёт доступ к его графику: [[tradingview_mcp_setup]].

## Что даёт TW-MCP для этого
- `data_get_pine_labels/boxes/lines` (study_filter="OKO") → его разметка ЧИСЛАМИ: CHoCH/BOS/EQH/EQL,
  FVG-зоны (боксы), пивоты (3 набора+D/W/M), фибо-OTE уровни.
- `data_get_ohlcv` → те же бары → прогнать детектор бота → сравнить FIRE vs разметка.
- `capture_screenshot` → визуальное подтверждение вместе.
- `replay_*` → историческая перемотка, проверка сетапов в прошлом пошагово.
- `chart_set_symbol/timeframe`, `quote_get`, `data_get_study_values` → любая пара/ТФ/индикаторы.

## Цикл «визуал → код»
1. Егор описывает паттерн/сетап (словами или на графике).
2. Я: читаю его OKO-SM разметку + прогоняю детектор бота на тех же OHLCV (MCP).
3. ВМЕСТЕ сверяем: сетап есть/нет? бот согласен или врёт? (скриншот + числа).
4. Расхождение = точка обучения → правлю детектор в коде.
5. Снова сверяю на графике → перенос в прод. Мерить эффект в % net на VST ([[principle_measure_pct_not_r_LAW]]).

## Первое применение (01.07)
ICNT LONG: подтвердил 2 недостающих гейта входа визуально ([[ote_entry_two_missing_gates]]) — FVG-под-SL
магнит + нет LTF-CHoCH. Детектор входит по «цена в зоне», игнорируя оба → входы-ножи.

**Why:** бэктест-валидация провалилась (look-ahead), нужен человеческий эталон разметки. **How to
apply:** на любой сверке — читать OKO-SM разметку + детектор на тех же барах, расхождение править в код.
⚠️ Запуск TW-MCP: [[tradingview_mcp_setup]] (Invoke-CommandInDesktopPackage + полный путь exe).
