# 🔴🔴 ЧЕТЫРЕ ПРАВКИ МЕТОДА — ПЕРЕПРОВЕРИТЬ ВСЁ (Егор, 27.08.2026)

Егор: «я чувствую, что уже несколько дней мы гоняем неполноценные тесты на обрезанном
понимании данных». Справедливо — все четыре пункта ниже это подтверждают.

## 1. 🔴 СОБЫТИЕ КРОССА ДЕЙСТВУЕТ ДО ОБРАТНОГО КРОССА

Дословно: «событие кросса действительно ДО обратного события кросса».

Я мерил `bars_since(последний кросс вверх)` — и эта метрика СМЕШИВАЕТ: если после
кросса вверх был кросс вниз, состояние уже медвежье, но `bars_since` продолжает
показывать давность бычьего кросса. Признак загрязнён.

**Как надо:** мерить ТЕКУЩЕЕ СОСТОЯНИЕ (`wt1 > wt2` бычье / `wt1 < wt2` медвежье)
и ДЛИТЕЛЬНОСТЬ этого состояния — сколько баров оно держится непрерывно.
В матрице проекта состояние уже есть: `wt_state_up_*` / `wt_state_down_*`
(combinator_core.py:518). Длительности — нет, добавить.

## 2. 🔴 wt2 НЕ МЕРИЛСЯ ВООБЩЕ

Дословно: «ты не ответил про wt2? ты смотришь обе скользящие или только wt1?».

Мерил только wt1: его зону, наклон, отношение к медиане. wt2 использовал ИСКЛЮЧИТЕЛЬНО
как вторую линию для кросса. Не мерилось:
- зона самого wt2 (OB/OS по wt2);
- наклон wt2;
- положение wt2 относительно медианы;
- спред `wt1 − wt2` как величина (не только знак) — в матрице есть `mtf_wt_spread_*`,
  но на 15m-механике не проверялся;
- расхождение наклонов wt1 и wt2.

## 3. 🔴🔴 ИСКАТЬ КОНФЛЮЭНЦИЮ, А НЕ МОМЕНТ

Дословно: «похоже ты всё время ищешь момент для входа, а не конфлюэнцию событий
как набор для возможности».

Что я делал: мерил признаки ПО ОДНОМУ (реже парами), искал «какой признак включить
как гейт». Это поиск момента.

**Как надо:** считать СКОР КОНФЛЮЭНЦИИ — сколько условий из набора выполнено
одновременно на баре сигнала, и мерить результат по числу совпавших условий
(0 / 1 / 2 / 3+). Гипотеза, которую это проверяет: сила не в отдельном признаке,
а в НАБОРЕ. Отдельно взятый признак может быть слабым, а три вместе — рабочими.

🔑 Это объясняет, почему слепой отбор по одиночным признакам дал 0 из 446 для обеих
сторон на 15m: протокол судил их поодиночке. Конфлюэнция как счётчик — ДРУГАЯ гипотеза,
и она НЕ проверена.

Родственное в проекте: [[mtf_confluence_matrix_vision]] (скелет есть, жёсткий гейт
не работает), [[zone_confluence_and_gaps]] (U-образная кривая конфлюэнции в зоне входа).

## 4. 🔴🔴 И ВСЁ ЭТО СВЯЗАНО ЧЕРЕЗ MTF

Дословно: «+ все это MTF связанно».

Конфлюэнция считается НЕ на одном ТФ. Набор условий должен собираться по вложенности:
15m + 1h + 4h одновременно. Состояние WT на 15m, состояние WT на 1h, состояние на 4h —
это три разных условия одного набора, а не три отдельных замера.

То же для всего остального: кросс на младшем при согласии старшего, дивергенция на 15m
внутри бычьего состояния 4h, FVG старшего ТФ как контекст для входа на младшем.

**Что это меняет в замерах:** харнесс УЖЕ подтягивает признаки старших ТФ
(`__from_1h`, `__from_4h` — 290 из 446 признаков, с shift(1) для причинности).
Но я мерил их ПООДИНОЧКЕ наравне с младшими — то есть снова моментами, а не набором.

**Как надо:** скор конфлюэнции считать ПО ЭТАЖАМ:
  · согласие 15m (состояние WT, зона, спред)
  · согласие 1h (то же со старшего, с закрытого бара)
  · согласие 4h
и мерить результат по числу согласных этажей (0/1/2/3). Это и есть Куб в действии —
вложенность как основа, а не сумма независимых признаков.

Родственное: [[mtf_nested_zigzag_principle]], [[mtf_weight_hierarchy_universal]],
[[impulse_mtf_4h_and_nesting]], [[mtf_confluence_matrix_vision]].
