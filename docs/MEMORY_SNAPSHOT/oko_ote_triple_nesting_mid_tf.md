`core/smc/oko_ote.py::detect_oko_ote` (24.06, по запросу Егора «играть с наборами 4h-1h-15m/4h-1h-5m») — добавлены опциональные параметры в КОНЕЦ сигнатуры: `mid_tf=None, df_mid=None, entry_fib=ENTRY_FIB`. Все с default → живой вызов (`bot/loops/oko_ote_observer_loop.py:109`, 9 позиционных аргументов) НЕ меняется ни байтом. Верифицировано: прогон 4h→5m/100 пар до и после рефакторинга дал **побайтово идентичную** $-таблицу и reach-rate.

**Механика тройной вложенности:** `find_setups_zz` и `select_significant_impulse` возвращают ОДИНАКОВЫЙ shape-dict (`levels/ote/direction/from/to/choch_ts`) на ЛЮБОМ ТФ — рекурсивно. Тройная вложенность = ТОТ ЖЕ containment-фильтр (`htf_ote_lo <= entry <= htf_ote_hi`), что уже был для zone⊃break, применённый ОДИН РАЗ ДОПОЛНИТЕЛЬНО: `mid_setups = find_setups_zz(zigzag_atr(df_mid), df_mid)` (ВСЕ сломы mid_tf, не один значимый — чтобы поймать МНОГО под-импульсов) → отфильтрованы containment-чеком относительно htf-зоны → каждый прошедший mid-сетап становится своим `container=(lo,hi)` для финального break_tf слома. 0 новых формул, чистая композиция. Дедуп по `s["choch_ts"]` против double-counting одного и того же break_tf-слома, если он попадает в зону НЕСКОЛЬКИХ mid-контейнеров одновременно.

`scripts/oko_ote_runner_test.py` — флаги `--mid-tf`/`--entry-fib`, плюс multiprocessing (`--workers`, см. [[perf_multiprocessing_not_gpu]]) и reach-rate доп. фибо-уровней.

**Результат (100 пар, confs≥3, $5 риск):** тройная вложенность даёт БОЛЬШЕ сделок, не меньше — 4h→1h→15m: 54 vs 47 у простого 4h→15m (+15%); 4h→1h→5m: 52 vs 45 у простого 4h→5m (+16%), при сравнимом $/трейд на `target_-1.618`.

🔴 **ПОПРАВКА после overlap-анализа (24.06, та же сессия) — «больше сделок» ≠ «много новых вложенных импульсов»:** сравнил CSV-дампы (sym+dir+entry_ts) 4h→5m (45 сделок) vs 4h→1h→5m (52 сделки). **83% сделок тройной вложенности (43 из 52) — БУКВАЛЬНО ТЕ ЖЕ сделки** (тот же symbol+direction+entry_ts побайтово), что уже находит простой 4h→5m. Только **9 сделок (17%) генуинно новые** (6 — символ/направление, которых вообще нет в простом наборе; 3 — тот же символ+направление, но ближайшая «похожая» сделка в простом наборе отстоит на 50+ дней = не связана). **0 (НОЛЬ) случаев «той же сделки, но смещённой на несколько часов»** — найден точный 0/1 паттерн (либо идентично, либо полностью не связано), НЕ плавная лестница вложенных входов внутри одного движения, как предполагалось. Тройная вложенность ТАКЖЕ потеряла 2 сделки, которые находил простой 4h→5m (ATH/USDT long 05.01, AVNT/USDT long 06.03) — не строгое надмножество.
**Практический вывод:** запускать 4h→5m И 4h→1h→5m ОДНОВРЕМЕННО как «две независимые стратегии» = 83% дублирующих сигналов → 2x размер позиции на ОДНОЙ И ТОЙ ЖЕ сделке, не диверсификация. Если нужен только ОДИН выбор — 4h→1h→5m чуть полнее (52 vs 45, почти то же $), но НЕ радикально лучше; гипотеза «много вложенных импульсов внутри тренда» для ЭТОЙ конкретной пары zone=4h/mid=1h/break=5m подтвердилась слабо (+9 сделок, не лавина). Возможно на ДРУГИХ mid_tf-парах (напр. mid=15m между zone=1d и break=1h) эффект будет другим — не проверено.

**Why:** Егор хотел охват максимума данных + готовность забирать много вложенных импульсов внутри одного устойчивого тренда (не 3-5 сделок на весь тренд, а в разы больше), вместо упования на единственный крупный свинг.

**How to apply:** для ЛЮБОГО будущего расширения вложенности (4+ уровней, если понадобится) — тот же паттерн: "containers"-список + плоский `[(container, item) for container in X for item in Y]` вместо вложенных for (избегает переиндентации существующего тела цикла, минимальный диф при правке live-кода).
