Порядок работы при изменениях кода (особенно в trading-логике):
1. **Обсуждение** — что планируется, почему, какие риски
2. **Тестирование/проверка данных** — подтверждение гипотезы цифрами
3. **Действие** — только после согласования

**Why:** Пользователь несколько раз убеждался что поспешные фиксы дают деградацию. ARCH-100
показал avgR=-0.437 после 10+ фиксов без проверки гипотез. Каждое изменение в trading-коде
влияет на реальные деньги — ошибка стоит депозита.

**How to apply:** Когда вижу проблему в коде или у меня есть гипотеза — сначала описать
наблюдение и предлагаемый фикс словами, дождаться согласия. Тестировать через SQL/data analysis.
Только после явного "делай" — править код. НЕ применять Edit без обсуждения, даже если фикс
выглядит очевидным.
