**АРХИТЕКТУРНЫЙ ВЕКТОР «Матрица OTE» (Егор 02.07.2026, визуал-сессия TW-MCP на XLM/GRT).**
Егор — трейдер/визионер (не кодер): даёт ВИДЕНИЕ как читать рынок, перевод в код = наша работа.

## Концепция
Система должна ВСЕГДА держать не одну зону, а МАТРИЦУ OTE — вложенный стек зон/уровней всех ТФ:
```
           значимая нога → OTE-зона → фибо-уровни (0.5/0.62/0.705/−0.27/−0.62/−1.0)
  4h  ═══  [нога] → [OTE] → [уровни]        ← контекст «ГДЕ мы»
  1h  ═══  [нога ВНУТРИ 4h-OTE] → [OTE] → [уровни]
  15m ═══  [нога ВНУТРИ 1h-OTE] → [OTE] → [уровни]
  5m  ═══  [нога ВНУТРИ 15m-OTE] → [OTE] → [уровни]   ← точка входа
```
- **Пересчёт постоянно** (каждый бар, все ТФ) — система «видит всю карту».
- **Локализация цены**: какие зоны/уровни разных ТФ сходятся у текущей цены.
- **Значимость = КОНФЛЮЭНЦИЯ** вложенных OTE (LTF-OTE ВНУТРИ HTF-OTE + совпадение уровней масштабов).
  Пример XLM: вход 0.19944 = 0.62 LTF-фибо И −0.27 HTF-зоны одновременно (см. [[mtf_nested_zigzag_principle]]).
- **Вход** = где вложенные зоны совпадают («нога вернулась в OTE старшего»).

## 🔑 УТОЧНЕНИЕ (Егор 02.07): старшая OTE = ЦЕЛЬ+НАПРАВЛЕНИЕ, младшие = входы ПО ПУТИ
Матрица — не просто вложенные зоны, а НАПРАВЛЕННОЕ движение к старшей цели:
```
СТАРШАЯ OTE (4h/1d) = ЦЕЛЬ (куда цена стремится) + НАПРАВЛЕНИЕ
   ↓ цена НЕ падает «одной палкой» — откатывает по пути (неизбежно)
по пути образуются НОВЫЕ младшие OTE (1h/15m/5m) — в них ТОЖЕ торгуем,
   но ТОЛЬКО в направлении старшей цели
пока цена НЕ дошла до старшей OTE → новые младшие входы В ТОМ ЖЕ направлении
```
**КОРЕНЬ слива:** младшая 15m-нога значима ТОЛЬКО в контексте старшего. Изолированно (без «большой
лотереи» 4h) значимость теряется → **торгуем ШУМ на 15m в зоне 4h** (детектор берёт мелкую ногу без
проверки, что она ПО ПУТИ к старшей цели). GRT падает → старшая OTE даёт огромный LONG-отскок; пока
сваливаемся — младшие ноги; вход = слом на младших В НАПРАВЛЕНИИ старшего отскока.

## Реализация (инженерный план — наша часть, Егор не кодер)
```
СЛОЙ1 КОНТЕКСТ (4h/1d): значимый импульс → OTE-зона + НАПРАВЛЕНИЕ + ЦЕЛЬ (fib −0.62 старшего)
СЛОЙ2 ВХОДЫ (1h/15m/5m): OTE-сетапы, но ФИЛЬТР — direction==старший И младший OTE «по пути»
                          (между ценой и старшей целью). Против старшего = ШУМ, отбросить.
СЛОЙ3 КАСКАД: пока цена не дошла до старшей OTE → новые младшие входы в том же направлении
```
В `ote_signal_generator` добавить HTF-контекст-слой (направление+цель старшего) как ФИЛЬТР LTF-входов.
Превращает «шум 15m» в «15m-входы по пути к 4h-цели». Шаг1 (выбор HTF-ноги «цена в зоне») уже в коде.

в точке разворота. XLM: progress=0 (каскад снизу не начат). МАТРИЦА ПОЛНАЯ: зоны+контекст+вложенность+переворот.

## ✅ ПРАВИЛО ЕГОРА реализовано (structure_trend, 02.07): LH давший LL = слом, без пилы
Чистая market structure: DOWN = последний ХАЙ, давший новый ЛОЙ (LH) = уровень слома; пробой ХАЯ
вверх = CHoCH. Обновляется ЛОЙ → обновляется ХАЙ (новая нога). Симметрично UP (HL давший HH).
Реализовано через zigzag typed точки: lows[-1]<lows[-2]→short (слом=highs[-1]); highs[-1]>highs[-2]→long.
trend_direction теперь обёртка над structure_trend (было: сырой CHoCH=пила). Живой тест GRT: 1h=SHORT
(слом 0.01797 НЕ пробит — совпало с глазом Егора, раньше пила давала ложный long), переворот только
5m/15m (мелкий отскок дна) прогресс 2/4. Слом-уровни на графике легли на структурные хаи Егора.
## Урок ГЛУБИНЫ (Егор 02.07): структурные точки зависят от ОКНА, но ЛОКАЛЬНЫЙ вывод стабилен
Дальше влево (больше limit баров) → swing-точки/ноги ДРУГИЕ (крупнее), НО локальная структура
(последние ноги, вывод) — ТА ЖЕ. Точки НЕ абсолютны. Матрица берёт ЛОКАЛЬНУЮ структуру для решения
(последние значимые точки = устойчиво); глубина/окно = крупный контекст (старший ТФ). Не бояться
«плавающих» точек — важен локальный последний слом. Разумное окно (limit ~300) даёт стабильный вывод.

## ✅ OTE-МАТРИЦА ОТ СТРУКТУРЫ (02.07): ote_matrix(dfs) — «OTE по матрице» (Егор)
Раз структура+сломы готовы → OTE строится ОТ неё (не старый изолированный ote_retest_setups).
`ote_matrix(dfs)`: для каждого ТФ берёт НОГУ из coherent_structure (extreme→break_level) →
build_ote(extreme, break) → зона отката 0.5-0.79, SL=слом (защищённый), цели=расширение −0.62/−1/−1.618.
Младшие НАСЛЕДУЮТ ногу старшего → OTE ВЛОЖЕНЫ (не изолированы = корень слива). structure_trend теперь
возвращает 'extreme' (LL для short/HH для long = 2й конец импульса). coherent_structure наследует
extreme вниз. Возвращает {tf: {direction, ote_lo/hi, entry, sl, target_062, targets, active(цена в
зоне), broken, from, to}}. Валидировано: GRT все SHORT OTE[0.01791-0.01838] SL0.01872 цель0.01608
(цена ниже→ждёт откат вверх продать); XLM 1d IN-ZONE long, 4h/младшие OTE[0.181-0.191] ждут откат.
Дальше: младший СВОЙ тонкий OTE (['own']) ВНУТРИ старшего = entry-timing СЛОЙ-2 (сейчас младший=копия старшего).

## Как строить (вектор, не сейчас — большая переделка ядра)
Матрица OTE = постоянный структурный контекст в **Shared Context Bus** (центр Куба): для каждого ТФ
значимые ноги (walk-forward-честный ZZ, не look-ahead) → OTE-зоны → уровни. Все стратегии читают «где мы»
из матрицы. Строить пошагово с ВИЗУАЛЬНОЙ валидацией на графике Егора ([[visual_validation_workflow]]):
шаг1 выбор HTF-ноги «где цена в зоне» → шаг2 вложенность LTF в HTF-OTE → шаг3 конфлюэнция уровней матрицы.
**Why:** детектор видит один срез (setups[-1]), Егор видит всю карту (матрицу) — отсюда разрыв.
**How to apply:** не setups[-1], а MTF-матрица зон/уровней + локализация цены + конфлюэнция.
Связь: [[mtf_nested_zigzag_principle]], [[project_confluence_principle]] (score=gravity/dist), Куб=Shared Context Bus.
