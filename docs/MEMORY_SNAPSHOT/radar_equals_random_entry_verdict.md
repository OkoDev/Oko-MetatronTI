Протокол `scripts/radar_verdict.py`, отчёт `obsidian/Research/2026-10-02-Radar-Full-Verdict.md`.
Повод: починка `vst_real_resolve` (30.09) перевернула радару знак → Егор «запускай» полный протокол.

**Главное:** радар (609 заявок 03.07–01.10, вся его жизнь) ср **−0.78%**/сделку. Контроль (случайный вход той же
геометрии, ×5): случайный момент −0.99% → Δ +0.21 (95% [−0.22; +0.66]); **с подбором по волатильности** −0.58% →
Δ **−0.20** (95% [−0.67; +0.24]). Оба интервала накрывают ноль, знак меняется от способа → **эджа нет**.
🔴🔑 ЛОВУШКА КОНТРОЛЯ (нашёл после вопроса Егора «про какую геометрию?»): сохранять геометрию в % НЕДОСТАТОЧНО —
радар входит после резкого движения (ATR% перед входом 0.76 против 0.17 у случайного момента, вчетверо).
Контроль обязан совпадать и по ВОЛАТИЛЬНОСТИ (±25%), иначе сравниваются разные рынки. Дополняет [[law_control_group_random_entry]].
Минус во всех разрезах: обе стороны · все 3 месяца · все 4 типа сетапа (pump −0.95 · build −0.70 ·
spring −0.48 · build_flip −0.30) · все грейды (A −0.82, B −1.05) · все корзины стопа · охват 33% монет.
Хрупкость: без верхних 10% сумма −1105 против −473 → **минус системный, не хвост**.

**Записанный плюс гейта wave_leg не подтвердился:** 26.09 (58 сделок, дефектный инструмент) leg≥3 = +2.20%;
теперь (236 сделок) leg≥3 = **−0.43%**, leg=1 = −1.99%. Гейт отсекает худшее, но лучшая корзина тоже минус.
🔴 `wave_leg` пишется ТОЛЬКО для типа `pump`; в `radar_orders` монета БЕЗ суффикса ('SUPER'), ключ связи — (base, radar_ts).

**Факт журнала бота (не только реплей):** VST 547 сделок, ср −0.25%, медиана −1.17%, сумма **−139.2%**,
без верхних 10% −933.8%. По 530 общим сделкам управление (TSL/мульти-TP/пивот-трейл) даёт **+0.47 п.п.**
(по месяцам −0.04 → +0.96 → +2.01), но знак не переворачивает. Сентябрь по факту +54.7%, однако медиана
там −0.57%, а без верхних 10% −59.2% — весь плюс делают 6 сделок.

**НЕ проверено:** второй режим рынка (радар жил только во флэте BTC + дрейфе альтов), суррогат, ликвидность
(оборот в сигнале был 0 до 29.09).
**Гипотезы:** (1) тугой стоп <1.5% даёт −0.19 против −2.15 при ≥5%, монотонно — минус приходит из ШИРОКИХ
стопов, против [[stop_zone_survived_blind_test]]; (2) ценность в слое выхода, не входа ([[exit_is_fine_entry_gives_no_move]]);
(3) `radar_build_flip` наименее убыточен — смотреть при накоплении.

**🔴🔴 ГЛАВНАЯ ПОПРАВКА (02.10, возражение Егора «радар ведь использует ДИНАМИЧЕСКИЕ данные, а не строгую геометрию»):**
возражение верное — тот протокол судил ГЕОМЕТРИЮ СДЕЛКИ. Отдельный замер информативности САМОГО сигнала
(`scripts/radar_signal_info.py`, ВСЕ 45 894 сигнала журнала `radar_orders` — сделками стали лишь 670;
форвард цены в сторону сигнала, контроль = та же монета/сторона/волатильность; метрики МЕДИАНА и доля>0,
потому что средние забиты хвостами мемкоинов):
- 🟢 **`pump` ЖИВОЙ:** SHORT (n=2271) 24ч медиана **+1.50 п.п.** [+0.76; +2.20], доля>0 +4.8%; LONG (n=866)
  +0.77 [+0.08; +1.50]. **3 из 3 месяцев в плюсе**, у SHORT интервал не накрывает ноль ни в одном месяце.
- 🔴 **`build LONG` (n=19741) значимо ПРОТИВ:** 24ч медиана −1.24 [−1.73; −0.68], доля>0 −7.5%.
  То же у `spring LONG` (−1.01, доля>0 −9.5%). Их надо выключить или перевернуть сторону.
- ⚪ `build SHORT`, `build_flip` (обе стороны) — ноль. `grade C/B` и `wave_leg` значимы, но это ПОДМНОЖЕСТВА pump
  (и grade, и wave_leg пишутся только для него) — не независимые находки.
**Почему живой сигнал терял деньги:** медиана форварда +1.5% за 24 ч, а геометрия просила кратно больше
(цели по магнитам/пивотам, корзина стопов ≥5% дала −2.15%/сделку) — ход не доходит до цели, стоп выбивается шумом.
Плюс 94% потока — build/build_flip (пусто или против), pump — лишь 7%.
**Итог:** оживить РЕАЛЬНО, но только `pump` и с геометрией под замеренный форвард (цель ~1.5–2%, стоп
сопоставимый, горизонт ~сутки). Какая именно геометрия извлекает форвард — НЕ замерено, нужен отдельный прогон.
🔑 Урок метода: «механика убыточна» ≠ «сигнал пустой». Сначала мерить информативность сигнала (форвард против
контроля), и только потом судить геометрию. Связано: [[resurrect_dead_strategies_by_stop_size]].

**How to apply:** не опирать решения на прежние «плюсы» радара (оба артефакт инструмента); радар торгует на бирже —
решение о выключении за Егором. Связано: [[radar_wave_gate_was_dead_column_not_selected]], [[limit_fill_live_matches_market]].
