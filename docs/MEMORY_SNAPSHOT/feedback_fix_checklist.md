## Принцип: эффект бабочки

Каждое решение — не изолированное действие. Любое изменение тянет цепочку:
код → поведение → данные → торговля → деньги.

**Перед реализацией спросить:**
- Что изменится в поведении системы после этого?
- Кто ещё использует этот код / данные / конфиг?
- Какой негативный сценарий я не вижу сейчас?

**После реализации спросить:**
- Работает ли это?
- Что ещё это ломает? (симметричный случай, смежные модули, edge cases)
- Что нужно чтобы это не сломалось снова? (тест на точный сценарий — падает ДО, проходит ПОСЛЕ)

**Why:** REAL #7264 → исправили min→max, не подумали о SHORT в профите → DEV-191. DEV-191 → исправили floor, написали 42 теста, не проверили покрытие реального сценария → пользователь указал сам. Паттерн: задача выполнена, последствия не просчитаны.

**How to apply:** На любой задаче — фикс, новая фича, изменение конфига, рефакторинг. Прогнозировать вслух до того как пользователь спросит. Молчать о пробелах нельзя.
