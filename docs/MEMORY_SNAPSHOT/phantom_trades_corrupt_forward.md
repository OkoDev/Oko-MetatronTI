# 👻 ФАНТОМЫ ЛОМАЮТ ИЗМЕРИТЕЛЬНЫЙ ПРИБОР (07.08.2026)

Егор увидел на дашборде сделки возрастом 6-8 дней при `vst_time_exit.default_ttl_days: 5.0`.
Копнул — оказалось ДВА независимых дефекта, и второй важнее.

## Дефект 1: тайм-выход не мог закрыть — нет `position_id`
`_vst_time_exit_check` (core/exchange/position_sync.py) требует `bot._exec_sphere` И `position_id`.
**7 из 17 живых VST-сделок были БЕЗ pid** (WS-фил не проставил) → 3400 записей в логе
«enabled, но нет sphere/pid — пропуск». ASTER и APEX висели 6-7 дней, будучи РЕАЛЬНЫМИ позициями.
**Фикс:** восстановление pid с биржи по (symbol, side) через `router._clients` перед отказом.

## Дефект 2 (главный): ФАНТОМЫ — БД врёт про открытые позиции
**17 записей OPEN в БД против 9 реальных позиций на бирже.** 8 фантомов: позиция закрылась,
БД не обновилась. `sphere.close()` честно отвечал «position not found in store» (6691 раз).
→ Дашборд показывал 17 сделок / WR 59% / +6.4R, где почти половина записей ФИКТИВНА.
**Это бьёт по прибору, а не по кошельку:** форвард-статистика, по которой мы решаем «дошёл ли
эдж до гейта», была загрязнена.

## Вариант А (выбор Егора): восстановить фактические выходы
`scripts/reconcile_phantoms.py` — dry-run по умолчанию, запись по `--apply`:
1. `get_filled_orders(symbol)` → первый ЗАКРЫВАЮЩИЙ филл (противоположная сторона) после входа
2. `get_income(REALIZED_PNL)` → денежная сверка
3. статус — из ТИПА ордера (TAKE_PROFIT→TP, STOP→SL/TSL по знаку P&L)
Результат: **6 из 8 восстановлено**, 2 (SOON, 1000000BOB) без найденного филла — НЕ тронуты
(выдумывать цену выхода нельзя). Осталось 11 OPEN против 9 на бирже.

## 🔴 ДВА БАГА В МОЁМ ЖЕ СКРИПТЕ (dry-run спас)
1. **Формат символов**: биржа даёт `APEX-USDT`, БД — `APEX/USDT:USDT`. Сравнение не совпало →
   ВСЕ 17 попали в «фантомы». Не испортил данные только потому, что у реально открытых нет
   закрывающего филла и сработала защита «выход не найден → не трогаю». Фикс: `_norm()` до тикера.
2. **Статус по арифметике врал**: AEONBSC вышел через TAKE_PROFIT (+3.12%), а метился SL —
   потому что TSL подтянул стоп ВЫШЕ входа и проверка «цена ≤ стопа» срабатывала всегда.
   Фикс: статус из ТИПА ордера, не из сравнения цен.
**Урок: любой скрипт, переписывающий историю сделок, — только через dry-run с построчным выводом.**
