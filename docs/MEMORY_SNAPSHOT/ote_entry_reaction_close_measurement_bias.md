# Раскопка входа ote_nested (шаг 3, 22.07): A/B — измерением, не спором

## Что нашли в коде
- `ote_signal_generator._check_shot` → `entry = float(c[k])` = **ЗАКРЫТИЕ реакционной 15m-свечи**
  (коснулась OTE-зоны + бычья/медвежья реакция >0.55 тела). НЕ отдыхающий fib-уровень глубже.
- ARMED-watcher (`ote_observer_loop`) стреляет когда `zlo≤px≤zhi`, регистрирует entry=reaction-close.
- VST: LIMIT на этой цене (trade_router→bingx `&price=entry`). Для LONG реакция бычья → цена
  после неё идёт вверх → лимит-buy на reaction-close НИЖЕ рынка → favorable-фил ЛИБО пропуск.

## Почему «+0.81% adverse» ВРАЛА (смещение выборки)
Баг шага 1: LIMIT-фил → actual_entry=NULL (WS ловил только MARKET, exec_ws:250) → **невидим**.
MARKET-фил / market-fallback (лимит не зафилился) → actual_entry записан → ЭТО и есть 1703
«adverse». **Выборка смещена на market-исполненные.** Реальный вопрос — не adverse-цена, а
**FILL-RATE**: чистый лимит фила хорошо но пропускает (цена ушла после реакции); market-догон adverse.

## A/B решается ФОРВАРДОМ (шаг 1 разблокировал — actual_entry теперь пишется и для лимитов)
Безопасно, без изменения живой торговли, 1-2 недели:
1. fill-rate лимитов (зафилилось vs пропущено), 2. качество чистого лимит-филла (actual vs entry),
3. net% лимит-филлов vs market-догон.
→ A (эдж восстановим): чистые лимиты в плюсе + приемлемый fill-rate → убрать market-fallback.
→ B (недостижим): лимиты фила только на пробое против / мизерный fill-rate → decision-support.

## ✅ ВЕРДИКТ A/B (scripts/ote_limit_fill_backtest.py, n=4167 ote SIM июнь-июль)
Лимит на reaction-close по пост-входовым min/max: фила ⟺ цена вернулась к входу.
- 🔴 ФИЛЫ n=2325 WR42 net **−0.531%** · 🟢 ПРОПУСКИ n=1842 **WR100** net **+1.437%** · Δ=−1.97%.
- Идентично LONG/SHORT. **B — ADVERSE SELECTION разгромно**: лимит фила ТОЛЬКО лосей (вернулась
  к входу=разворот к SL), пропускает ВСЕХ винеров (ушла и не вернулась=выиграла, WR пропусков 100%).
- **config ote=LIMIT обречён ПО ДИЗАЙНУ** (живьё −1.34% = это). SIM +0.34% для лимита ИЛЛЮЗОРЕН
  (отдыхающий лимит физически не ловит раннер). Эдж достижим ТОЛЬКО MARKET на ЛИКВИДЕ (глаз/
  decision-support), не автомат-лимит по 500 тонким символам (хвост=микрокапы, слиппедж съедает).
- ForwARD был бы ПУСТ (ote VST 0 с 16.07) — решено на истории SIM без живой торговли.

**Why:** порядок Егора (сначала починить actual_entry) оказался точным — разблокировал измерение
A/B (хотя вердикт пришёл с min/max, без докачки). **How to apply:** ote-лимит НЕ чинить наращиванием —
он структурно фила лосей; либо MARKET+liquidity-фильтр, либо decision-support (алерт Егору, вход глазом
на ликвиде). Связано:
[[ote_sim_edge_illusory_entry_slip]], [[cutover_blocker_ws_closefill]] (не трогаем WS-пол),
[[method_egor_two_scale_entry]] (живой вход=волна2/откат — чутьё Егора vs автомат-реакция).
