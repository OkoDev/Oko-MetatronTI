# Мультиканальный оркестратор + анализатор (продукт, backlog)

Егор 22.07: осознал, что мультиканальная стратегия ([[insta-niche-algo-2026]]: IG в РФ-трейдинге отражает славу, не растит → развернуть на YouTube Shorts/Дзен, IG=витрина) требует **отдельного продукта** — автопостер + анализатор. Не часть [[insta-content-factory-46k]], самостоятельный проект.

## Реальность API (карта возможного — определяет scope)
| Канал | Автопостинг | Аналитика | Вердикт |
|---|---|---|---|
| YouTube Shorts | Data API v3 (офиц., легально) | Analytics API полный | ✅ чисто |
| Telegram | Bot API (тривиально) | ограниченно | ✅ чисто |
| Instagram | Graph API только Business/FB-Page, Reels огранич., свежий акк рискован; instagrapi=риск бана | Insights Business | ⚠️ хрупко |
| Яндекс Дзен | публичного API постинга НЕТ (только RSS-импорт) | студия, API закрыт | ❌ руками |

**Вывод:** полного «автопостера во всё» легально нет (Дзен закрыт, IG=бан-риск). Чистое MVP-ядро = **YouTube + Telegram** (офиц. API).

## Ценность = АНАЛИЗАТОР, не автопостинг
Главное не экономия кликов (мала), а **единая таблица метрик по каналам**: один ролик → Shorts+TG → собрать досмотр/пересылки/охват в одну БД → «какой формат/хук работает где» → **feedback loop в фабрику** (результат правит сценарии). Ровно Куб-мышление (сфера учится от сферы).

## MVP-контур (когда строить — ПОСЛЕ первых постов)
- `channels/youtube.py` (Data API v3 upload + Analytics pull), `channels/telegram.py` (Bot API post + stats)
- `orchestrator.py`: один mp4/карусель → веер по каналам, лог публикаций
- `analytics.py`: тянет метрики → единая БД → сводка «формат×канал×хук → досмотр/пересылки»
- Переиспользовать бренд/контент из E:/PROJECTS/content_factory
