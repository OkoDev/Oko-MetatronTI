**Сессия 27-29.06.2026 — почему ote_nested лил в бою (−74R/2дня, WR 16%) ВОПРЕКИ OOS (WR 68%).**

## 🔴 Корень №1 — PRODUCTION DRIFT (прод ≠ validated)
**DS валидировал ОДНУ стратегию, в бой пустили ДРУГУЮ:**
- **Research** (`scripts/ote_nested_honest_test.py`, WR 68% +0.317R): SL = **LTF-импульс-1.0 (структурный, широкий)** + вход по **LTF-слому**.
- **Прод** (`core/smc/ote_signal_generator.py`): SL = **за СВЕЧУ реакции (тугой)** + курок = **касание+1 свеча-реакция** (`_check_shot:207/210` — просто бычья/медвежья свеча с закрытием в 55% бара, НЕ слом структуры).

→ Это РАЗНЫЕ стратегии. Бой ≠ OOS не только из-за слиппеджа, а потому что **SL-механика и курок в проде искажены**. Урок: ВСЕГДА сверять что валидировал backtest ↔ что в проде (spec parity).

## 🔴 Корень №2 — edge мерить в % после costs, НЕ в R
R обманул: 1R красиво =1.0, но в % ничтожен.
- **1R (SL) = 0.94% движения** (среднее 285 сделок). TP1-реально 0.76%. **Слиппедж входа 0.66% ≈ весь 1R.** Fee 0.10%.
- Реальный R:R = 0.76/0.94 = **0.81** (риск>профит). E = 0.157×0.76 − 0.843×0.94 − 0.10 = **−0.77%/сделку** = структурный минус.
- Тугой SL давал красивый R в бэктесте (маленький знаменатель), но 1R меньше шума исполнения.

## 🔴 Корень №3 — тугой SL выбивается проколом
- **MAE (ход против перед разворотом) = median 1.93%**, а тугой SL = 0.94%. **84% сделок (256/306) прокалывают глубже тугого SL** → выбивает ДО движения, потом цена идёт куда надо (TNSR/SOL/GWEI: дёрнулись против→SL→развернулись).
- Backtest (реалистичный, fee+funding+лимит48ч): тугой SL WR 23% −19% / широкий SL (за край зоны) WR 97% +740%. Широкий ≫ тугой (направление надёжно; +740% завышено — профиль «копейки перед катком», нужен длинный тест).

## 🔴 Корень №4 — БД R/$ ВРЁТ (income = истина)
GWEI #38061: БД **+2.404R / +$7.32** (unrealized), income-ledger реально **+$0.02** (realized +$0.09 − fee $0.069). Симулятор пишет exit по проливу (R-инфляция); «+$7.32» бумажный. + 14% позиций без биржевого SL/TP-id (async fetch не успел при быстром закрытии). См. [[income_ledger_db_overstates_realized]].

## ✅ МОДЕЛЬ ЛЕЧЕНИЯ (Егор, к реализации/тестам)
1. **Широкий SL для раннего входа** = за начало импульса / fib 1.0 / край зоны (= research-SL импульс-1.0). Переживает прокол.
2. **Ранний вход — оставить** по стеку подтверждений (div/fvg/sc/ob/wt/atr + касание). CHoCH = **поздний** вход → НЕ курок, а взвешенное финальное подтверждение (бонус conf/sizing).
3. **После LTF-слома (CHoCH) — перенос SL за LTF-структуру** (tighten, сокращение риска когда разворот подтверждён). Вариант к тестам.
4. Слой зоны (HTF-OTE) валиден — не трогать. Связь: [[ote_is_meanreversion_not_continuation]], [[strategy_truth_state]], [[ote_tight_sl_validated]] (тот «оптимум» был на R без costs — пересмотреть).

## 🏁 ВЫХОД РЕШЁН (29.06, backtest 38473 сделки 4 года, 14 политик)
**Чемпион = `struct_choch_tp1` (+0.315R WR67%, OOS +0.223R, WF 13/15):**
широкий SL → ОДИН перенос за LTF-структуру после ПЕРВОГО CHoCH (разворот, урезает убытки <−1R) → цель **tp1 (1R)**.
- tp1 голый +0.296 · struct_choch_tp1 **+0.315** (CHoCH-перенос урезает проигрыши)
- struct_choch держать (без tp1) +0.102 — ПЛОХО (откат съедает). Перенос+ЦЕЛЬ tp1 — ключ.
- choch_fib1.618/2/2.618/3.618 = +0.12 (защита подняла vs голый fib +0.10, НО ≪ tp1). Дальние цели = шум даже с защитой → mean-reversion подтверждён 3-й раз.
- runner +0.10 · hybrid +0.234 · trailing(struct_trail) +0.206 — все < tp1.
**Закон выхода:** бери 1R, защити стоп структурой после CHoCH, НЕ тянись за расширениями. Прод сейчас = широкий SL + tp1 (+0.296); CHoCH-перенос (+0.315) = след. слой ведения (exit-слой, детект LTF-CHoCH после входа).

**Why:** 1.5 мес исследований мерили edge в R на идеальном входе; реальность — costs+слиппедж+тугой SL съели edge. Сигнал валиден, исполнение сломано. Чинить слой исполнения (SL/вход/выход), не сигнал.
