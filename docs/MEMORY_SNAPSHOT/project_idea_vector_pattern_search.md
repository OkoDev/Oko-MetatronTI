Идея: использовать HNSW-индексированный векторный поиск для "мягкого" сопоставления паттернов вместо жёстких булевых условий.

**Как работает:** каждый момент времени → вектор из `features_json` → HNSW находит N ближайших исторических аналогов → оцениваем ожидаемый R и вероятность.

**Что даёт:**
- Soft-matching: паттерн "почти" сработал (wt=-45 вместо -53) — не пропускаем
- Риск-скоринг входа: "похоже на 8/10 прибыльных моментов"
- Объяснение сигнала через конкретные исторические аналоги
- Поиск новых паттернов кластеризацией без ручного перебора

**Почему отложено (26.05.2026):**
- n=29 для golden pattern — HNSW бессмысленно, нужно 1000+
- 15 production patterns с жёсткими правилами уже работают (WR=100%)
- Нужно дождаться накопления данных VST-observer

**Когда вернуться:** VST-observer накопит 500+ сделок по каждому паттерну → строить soft-matching и риск-скоринг.

**Why:** [[ARCH-104-Pattern-Mining-RiskIntel]]
**How to apply:** Поднять тему когда будет достаточно данных из VST-observer. Python-библиотека `hnswlib` — без Node.js/TypeScript зависимостей.
