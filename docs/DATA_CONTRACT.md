# 📜 ПАСПОРТ ДАННЫХ — требования на входе

> Принят 13.10.2026 (Егор: «стандартизация данных должна быть на первых местах, а не в процессе работы с данными»).
> Правила действуют **на границе**, где данные входят в систему. Внутри модули их не перепроверяют и не переделывают.
> Эпик — `TASKS.md` → ARCH-147. Откуда взялись правила — раздел «Почему» в конце.

## Как читать

У каждого правила три строки: **правило**, **ворота** (единственное место в коде, которое за него отвечает) и
**режим**. Режимов два: «считаю» — нарушение пишется в лог и в счётчик, работа продолжается; «отказываю» —
нарушение не проходит. Новое правило сначала неделю живёт в режиме «считаю».

## Правила

### 1. Свеча
- **Правило.** Таблица свечей бота: строки по возрастанию времени, колонки `time, open, high, low, close, volume`.
  `time` — время ОТКРЫТИЯ свечи, UTC, целое число миллисекунд. Последняя строка может быть незакрытой свечой.
  Номер строки временем не является.
- **Ворота.** `core/infra/candles.py`: `last_bar_time()` — единственный способ узнать время последней свечи;
  `violations()` — проверка формата. Поставщик — `DataCollector.get_ohlcv`.
- **Режим.** «Считаю» с 13.10.2026: отчёт `[DATA-CONTRACT]` в логе бота раз за круг скана.

### 2. Время
- **Правило.** Везде UTC. В базу — строкой ISO с зоной (`core/infra/time_utils.utc_iso()`), в расчётах — `datetime`
  с зоной или миллисекунды. Московское время — только при показе человеку. Время как текст не сравнивают: в SQL
  только через `datetime(поле)`.
- **Ворота.** `core/infra/time_utils.py`.
- **Режим.** Запись — «отказываю» для нового кода (ревью). Старые строки базы приводятся отдельной задачей.

### 3. Символ пары
- **Правило.** Одна форма на проект: `BASE/USDT:USDT`. Приведение — один раз, на входе.
- **Ворота.** `PairContextBus.canon()` для шины. Для базы и остальных входов — задача ARCH-147.7.
- **Режим.** Шина приводит сама и предупреждает один раз на символ.

### 4. Снимок в шине
- **Правило.** Снимок (`wt_snap`, `smc_snap`, `pivot_snap`, ноги волн) сопровождается паспортом: когда посчитан,
  по какой последней свече, кем, версия формы. Читатель обязан проверить возраст, прежде чем показывать или торговать.
  Внутрь самого снимка служебные ключи не кладём: читатели перебирают его содержимое.
- **Ворота.** `PairContextBus` (поле паспортов снимков) — задача ARCH-147.6.
- **Режим.** Ещё не введено.

### 5. Запись в шину
- **Правило.** Писать в состояние пары можно только методами шины. Неизвестное поле или неизвестный тип события —
  ошибка производителя, о ней сообщается громко. У каждого поля один владелец — он записан в `docs/BUS_CATALOG.md`.
- **Ворота.** `PairContextBus.update()` и `publish()`.
- **Режим.** «Считаю» с 13.10.2026: предупреждение в лог, один раз на поле или событие.

### 6. Единицы
- **Правило.** Единица — в имени поля и одна на проект: `_pct` — проценты (0.3 значит 0,3%), `_ms`, `_sec`, `_usd`,
  `_bars`. Доля от единицы суффикса `_pct` не носит. У знакового поля в описании сказано, что означает плюс.
- **Ворота.** Ревью и каталог полей. Ревизия существующих — задача ARCH-147.8.
- **Режим.** Для нового кода.

### 7. Признаки сделки
- **Правило.** Ключи `features_json` — по списку с версией. После вставки сделки ключ дописывается одним SQL-выражением
  (`json_set`), а не «прочитал весь словарь — записал весь словарь».
- **Ворота.** `TradeSimulator` (единственная вставка сделки) — задача ARCH-147.9.
- **Режим.** Ещё не введено.

### 8. Тесты
- **Правило.** Тест на всё, что касается свечей, времени или кэша, берёт данные из общей заготовки в формате бота
  (`tests/factories.py`), а не строит удобную таблицу сам. Тест кэша обязан проверять окно постоянной длины.
- **Ворота.** `tests/factories.py`.
- **Режим.** Для новых тестов с 13.10.2026.

## Как добавить новое

- **Новый источник свечей** — отдаёт таблицу через `candles` и проходит `violations()` без замечаний.
- **Новое поле шины** — поле в `PairState`, запись в `bus_catalog._PAIR_META` (владелец, описание), строка в
  `get_full_state`, пересборка `docs/BUS_CATALOG.md`.
- **Новый ключ признаков сделки** — в список ключей с версией.

## Почему

Каждое правило закрывает ошибку, которая уже случилась:

| Правило | Что случилось |
|---|---|
| 1 | Кэш структуры брал номер строки вместо времени свечи и неделю отдавал старый снимок; проверка свежести по той же причине пропускала свечу месячной давности (13.10.2026, находки F01 и F02 внешнего аудита). В коде пять самодельных приведений формата с разной таймзоной |
| 2 | Время закрытия сделки писалось двумя видами строк, и их сравнивали как текст; функция `utc_iso()` существовала, но ею не пользовались |
| 3 | Преобразователей символа больше десяти; захардкоженная форма символа давала пустую выборку вместо ошибки |
| 4 | Ни один снимок не знал, по какой свече посчитан; у двух не было и времени расчёта |
| 5 | Неизвестное поле терялось молча; 25 записей шли мимо методов шины и не доходили до зеркала вовремя |
| 6 | Поле с суффиксом «процент» хранило долю (0.003 при комментарии «0.3%») |
| 7 | Признаки сделки целиком переписывали шесть мест без блокировки |
| 8 | Тест кэша был на таблице с временем в индексе и с растущим окном — в бою окно постоянной длины и время в колонке |
