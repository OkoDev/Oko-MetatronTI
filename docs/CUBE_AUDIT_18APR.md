## 1. Философия Куба — почему это важно

Куб Метатрона — не просто «много компонентов связаны». Три уровня метафоры:

1. **Полносвязность** — нет привилегированных путей. Любой узел влияет на любой другой, включая обратно по потоку.
2. **Отсутствие слепых зон** — каждый узел знает о состоянии остальных через Shared Context Bus.
3. **Симметрия без иерархии** — ML, SMC, детекторы — равноправные голоса, агрегируемые через adaptive_weighted_strength.

### Эмерджентность

Эмерджентность — система демонстрирует поведение, которого нет ни в одном компоненте по отдельности. В stateless-пайплайне её почти нет. В полносвязном кубе появляются вещи, которые никто не считал явно:

- **Пара стала рискованной:** 2 SL подряд + BTC HIGH_VOL + коррелированная пара TSL в обратную → состояние риска из композиции фактов
- **Re-entry после TSL:** WT cross интерпретируется не как новый сигнал, а как продолжение сделки (TriggerBus + PostTradeAnalyser + OTE queue)
- **Адаптация весов:** через 500 сделок веса уже не те, что заложил разработчик — система «узнала» что работает

### Ключевой парадокс

> **Полносвязная система с непроверенными узлами = leverage на ошибки.**

Если один узел систематически врёт — в линейной системе он испортит один шаг. В полносвязной — его ошибка просочится во все остальные через обратные связи. Система будет **уверенно ошибаться согласованно**.

**Пример:** если MarketRegime неправильно детектирует HIGH_VOL как RANGE:
1. Regime Strategy переключается в DUAL_TP вместо сжатия позиции ×0.5
2. min_strength понижает планку
3. Quality Gates пропускают сделку
4. Симулятор регистрирует → SL → ML учится на «RANGE + паттерн = плохо»
5. Веса в aggregator сдвигаются в неправильную сторону

### Критерий запуска Куба (три условия одновременно)

1. Любой узел читает состояние любого другого без race condition (PairContextBus)
2. Обратные связи замкнуты и стабильны
3. Каждый узел валидирован в shadow до подключения к графу

## 6. SQL-срез: три проблемы, а не одна

### Проблема 1: micro-SL эпидемия (архитектурная, не стратегическая)

180/511 сделок MultiSignal имели SL < 0.2%. До DEV-157 (`min_sl_dist_pct=0.1%`, 15.04) это было системным: SL ставился в 0.1% от entry → 16% pump = +112R. Три ARIA 14.03 = один pump event, посчитанный трижды.

**Без micro-SL:** MultiSignal avgR = **-0.348**, Sharpe = **-0.255**. Стратегия никогда не была прибыльной.

### Проблема 2: wt_entry — edge исчерпан

```
15-31.03:  n=1289  WR=20.0%  avgR=-0.110
01-14.04:  n= 834  WR=19.3%  avgR=-0.376
15.04+:    n=  64  WR= 4.7%  avgR=-0.937
```

Каждый период — после важных фиксов. Стратегия не реагирует на улучшения. MTF gate = продление агонии. Нужно: убрать из active_strategies.

### Проблема 3: pivot_reversal — единственный edge, но данные противоречивы

- 01-14.04: WR=56.2%, avgR=+1.057 (n=64)
- All time (TR-001): WR=34%, avgR=-1.192 (n=581)

Без DEV-178 (split по data eras) невозможно определить, что правда.

### R-распределение multi_signal (гистограмма)

```
     <-1.5:  n=  0
  -1.5..-0.5: n=265  ████████████████████████████████████████
    -0.5..0:  n=  0
      0..+1:  n=  1  █
     +1..+3:  n=174  ██████████████████████████
    +3..+10:  n= 28  ████
   +10..+50:  n= 36  █████
       +50+:  n=  7  █   ← три ARIA + BANANAS31 + RIVER + A2Z + ZEN
```

Бимодальное: либо -1R (SL), либо хвост. Ничего посередине. Sharpe обречён.

### Методологические уроки

1. **avgR без распределения = ложь.** Всегда: median + Sharpe + гистограмма.
2. **Мёртвая стратегия с красивыми метриками опаснее живой плохой** — молча искажает решения.
3. **Артефакты данных живут дольше фиксов** — DEV-157 починил micro-SL, но метрики заражены.

## 7. Главный вывод

> Куб Метатрона с точки зрения **инфраструктуры = 9/10**. С точки зрения **использования собранного контекста в реальных решениях = 4/10**.

Проблема не в архитектуре — это выбор в конфигурации, сделанный из разумного опасения «не пропустить разворот от R5». Данные говорят, что эта цена слишком высока: 82% SHORT при WR 33.5% = система систематически теряет деньги на направлении.

Полносвязная система с плохими входами не станет лучше от больших связей — она станет увереннее в своих ошибках. **Фундамент — сначала.**
