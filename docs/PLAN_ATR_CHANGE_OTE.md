# 📋 PLAN — atr_change × OTE интеграция (REGIME-V2 шаг 3)

> **Статус:** дизайн 11.06.2026 · **Тип:** улучшение входа atr_change через OTE-фильтр
> **Данные:** `data/research/2026-06-11--atr-change-ote/` · **Память:** [[ote_nested_mtf_strategy]], [[arch124_regime_audit]]

## 🎯 Суть (что нашли)
`atr_change SHORT = ATRTrend −1` (направление верное), но **слеп к структуре** — входит на
ATR-всплеске, садясь **НИЖЕ OTE-зоны** (поздно, на импульсе). Старый regime-гейт лечил не ту ось
(силу ADX), течь −178R. **Снят 11.06** (config `allow_short_regimes` убран, `long_strength_penalty=0`).

## 📊 Данные (MTF backtest, 183 сделки, `atr_change_ote_test.py`)
| Позиция входа vs OTE | Результат (агрегат по ТФ) |
|---|---|
| **В 5m-OTE-зоне** | **WR 89%, avgR +0.741** 🟢 (n=9, оптимум) |
| ВЫШЕ OTE (рано) | убыток везде (−0.55/−1.0/−0.8) |
| НИЖЕ OTE (поздно) | слабо/смешанно; 4h медиана **19% ниже** |
| нет структурной ноги | убыток везде (−0.13…−0.40) |

**Вывод:** оптимум = вход в **5m-OTE** (ote_nested LTF). atr_change туда сам не целится →
нужно превратить его в **триггер**, а вход дисциплинировать OTE-зоной.

## 🏗️ Дизайн интеграции
```
atr_change детектит ATRTrend ±1 + ATR-всплеск   →  ТРИГГЕР (не вход!)
   ├─ ФИЛЬТР 1: есть структурная нога направления (ZigZag 11/3 последняя нога
   │            совпадает с td). Нет ноги → DROP (данные: −0.13…−0.40).
   ├─ ФИЛЬТР 2: цена ещё НЕ ушла глубоко ниже OTE (не поздно). Если уже >X% ниже
   │            OTE-low → DROP (проскочили откат).
   └─ ВХОД: ждать ретест 5m-OTE-зоны (0.5–0.79 от ноги) → войти в зоне,
            SL за 1.0 (начало импульса), как ote_retest_setups.
```

### Где в коде
- **Триггер:** `scan_loop` atr_change handler (`:849+`) — оставить детекцию ATRTrend±1+всплеск.
- **OTE-зона:** переиспользовать эталон `ote_retest_setups` / `zigzag_atr` (`smc_engine`, D-01 канон) —
  НЕ плодить расчёт ([[principle_reuse_not_duplication]]). Брать 5m-OTE (ote_nested).
- **Связь:** `core/smc/ote_signal_generator.py` уже строит OTE-сетапы — atr_change может стать
  доп. триггером ВНУТРИ OTE-окна, а не самостоятельным выстрелом.
- **Гейт-учёт:** DROP-причины (`no_structural_leg`, `below_ote_late`) через `record_drop`
  (прозрачность, [[gate_sphere_concept]]).

## Этапы
- [ ] **Э0 Baseline** — текущий atr_change perf зафиксирован (avgR+0.072 v1-данные, шум от слепоты).
- [ ] **Э1 Фильтр ноги** — atr_change DROP если нет ZigZag-ноги направления. Замер: убирает ли −0.13 хвост.
- [ ] **Э2 OTE-окно** — atr_change валиден только пока цена в/над 5m-OTE (не глубоко ниже). Триггер «ждёт» откат.
- [ ] **Э3 Вход в OTE** — сместить entry с импульса на 5m-OTE-ретест (entry=mid OTE, SL за 1.0).
- [ ] **Э4 A/B** — сравнить старый atr_change (импульс-вход) vs новый (OTE-вход) по avgR/раннеры.

## ⚠️ Риски / открытое
- n=9 для «5m-в-OTE» мал — **добрать историей** (сейчас 46 пар из 273; докачать → n≥30).
- Смещение входа на ретест = **меньше сделок** (часть откатов не случится) — проверить fill-rate.
- 4h-OTE далеко (19% выше входа) — для 5m-входа брать **5m/15m**-OTE, не 4h (HTF-OTE как контекст-фильтр, не точка входа).
- Раннеры: OTE-вход с SL за 1.0 даёт лучший R-старт → раннерам не мешает ([[milestone_clamp50_runners_proven]]).
